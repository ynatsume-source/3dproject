## v2 の変更（Codex レビュー 10/25 を反映。§2 以降の v1 の記述より優先する）

1. **保存先は台帳**：正本は版付きの `ledger.hearths[equipmentId]`。`village` には焚き火の会の回数だけを残し、火の状態は
   二重に持たない。火の状態を `equipment.params` に入れない（既存工程の設備指紋が変わるため）。計算は `src/world/` に
   分ける。v1 の hearth は「火がつくか」だけを扱い、燃料・熱はいままでどおり各工程で数える。
2. **出来事の処理**：`lastProcessedWorldMs` と進行中の試行1件を持ち、前回から今回までに越えた出来事を時刻順に1度だけ
   処理する。抽選の鍵は `世界 seed・炉 ID・世界時計の JST 日付・用途（eve / noon）・試行番号・仕様版`（島の時計は
   約 13 倍速なので使わない。焚き火の時刻もいまの `localHour(clockMs)` どおり世界時計の JST）。
3. **定刻は作業を始める機会**：成功の判定は、本体が「その住民がいた・3 分働いた・中断されなかった」を確定してから行う。
4. **昼におこした火は 13:30 に埋める**（`dieAt = 13:30 + 12 時間`）。
5. **操作の優先順**：科学工程が火を使っている間は、21:06 に埋めず、朝の埋め直しもしない。工程が火を返した時刻に埋める
   （`dieAt = 返した時刻 + 12 時間`）。19:24 にすでに工程の火が燃えていれば、そのまま焚き火の会に使う。
6. **欠測**：熾のあいだの雨は `rainMeasured` を使い、欠けた時間があれば熾は「使えるか不明」＝消えている扱い
   （`gap` を残す）。試みる時刻の気温・湿度が欠けているか、`woodEmc()` の範囲外なら試みない。
7. **旧保存**：移行した時刻 `migratedAtWorldMs` と処理済みの時刻を持つ。移行で「熾（12 時間）」から始め、移行時刻より前の
   出来事（追いつき計算で過去に戻る分）は新しい hearth に適用しない。移行結果は保存する。欠落と破損を区別するため、
   小さな `schema`・`policy` 版を持つ。
8. **保存量**：現在の状態・処理位置・試行1件・累計だけで、炉ごとに数百バイト。
9. **確かめ方**：「オフライン 3 日で一致」は純粋関数の検査にし、本体の追いつき（いま最大 12 時間）の検査とは分ける。
10. **PR**：2 本（①火の状態・保存・出来事の処理、②本体の作業・工程・集まりへの接続）。炎の表示は別 PR。

## 2. 決めること（世界の事実）

焚き火台の火に状態を1つ持たせる。保存先は `village.hearth`（`seaglass.*` の既存の保存の中、新しいキーは作らない）。

| 状態 | 意味 | 見た目（別 PR） |
|---|---|---|
| `burning` | 燃えている | 今の炎 |
| `embers` | 灰に埋めた熾。`dieAt` まで生きている | 炎なし（のちに細い煙を足してもよい） |
| `out` | 消えている | 炎なし |

```ts
village.hearth = { st: 'burning' | 'embers' | 'out', dieAt: number /* 世界の ms */, rainMm: number /* 埋めてからの雨 */,
                   lastLitAt: number, lit: number /* おこした回数 */, tries: number /* 試みた回数 */ }
```

すべて世界の時間（ADR 0001）。時刻パネルの早回し・プリセット・季節切り替えでは変わらない。

### 1日の流れ（決まった世界の時刻に起きる。チャンク・追いつき計算で結果が変わらないように）

| 時刻（島の時刻） | すること |
|---|---|
| 19:24（`fireHours` の始め） | 熾が生きていれば「かき起こす」→ `burning`（必ず成功）。消えていれば火溝で試みる（下の §3） |
| 21:06（`fireHours` の終わり） | `burning` なら灰に埋める → `embers`、`dieAt = 今 + 12 時間`、`rainMm = 0` |
| 8:51（朝の集まりの始め、嵐の日はない） | 熾が生きていれば薪を足して埋め直す → `dieAt = 9:30 + 12 時間`、`rainMm = 0`（炎は出さない） |
| 13:00 | 消えていれば、日中にもう一度試みる（湿度が下がる時間） |
| いつでも | `embers` のあいだに降った雨を `rainMm` に足す。`rainMm ≥ 8 mm` か `今 ≥ dieAt` で `out` |

- 朝に埋め直すので、晴れていれば熾は1日中つながる。夜の 21:06 から朝の 8:51 は 11.75 時間なので、
  熾の寿命は 12 時間より短くできない（10 時間にすると毎晩消える。§5 の試算）。
- 嵐で朝の集まりがない日は埋め直しがなく、熾は 9:06 ごろ消える → その日の昼か夕にもう一度おこす。
- 火を使う科学の工程を始めるとき：熾が生きていればかき起こして使い、終わったら埋め直す（`dieAt` を更新）。
  消えていれば工程を始める前に火溝で試みる。成功しなければ工程は始まらない（`no_fire`、あとで試み直す）。

## 3. 火溝で火をおこす

- 道具 `fire_plough_kit`（台木・こすり棒・火口）。小屋の中に置いてあり、雨には濡れない。
  台木は柔らかい乾いた木（太平洋の島ではオオハマボウ類が使われた。宮古・石垣ではユウナとして身近）。
- 1回の試み＝3分。夕方は 19:24 から3分おきに最大6回（〜19:42）、昼は 13:00 から同じく最大6回。
- 成功の確率（1回ごと）：

  ```
  p = P0 × f_wood × f_wet
  P0     = 0.5                      慣れた者が乾いた道具でやったとき（仮定）
  w      = woodEmc(気温, 湿度)       道具の木の平衡含水率（firewood.ts の Hailwood–Horrobin 式をそのまま使う）
  f_wood = clamp((0.22 − w) / (0.22 − 0.12), 0, 1)   12 % 以下で1、22 % 以上で0（仮定）
  f_wet  = 1                        小屋の軒下でおこすので、雨そのものは効かない（湿度を通して効く）
  ```

  28 °C で湿度 75 % なら w ≈ 14 %（f_wood 0.8）、90 % なら 20 %（0.2）、95 % なら 23.5 %（0）。
  小さい道具の木は数時間で空気の湿り気に追いつくので、その時刻の湿度で決める（近似）。
- 抽選：`hash(世界の seed, 'hearth', 島の日付, 'eve' | 'noon', 試みの番号)`。同じ世界なら何度読み直しても同じ結果。
- 気温か湿度がわからない時刻（記録の欠け・サーバー停止）は試みない（`tries` も増やさない）。
  熾に降る雨がわからない区間は 0 mm として数え、履歴が不完全なことを `hearth.gap = true` で残す。
- 誰がやるか：夕方は最初に座った者、昼は手の空いている者（見た目と台詞の都合で、本体が決めてよい）。
  台詞は用意したもの（LLM は使わない）：「火溝で火をおこした（3回目）」「今夜は湿っていて火がつかない」など。
- 材料：v1 では lot を消費しない（道具に火口が含まれる扱い）。v2 で乾かした `coir_pith`（ヤシ殻のくず、いま
  副産物として溜まっていくもの）を火口として 1 回 2 g 使う（溜まりすぎの解消にもなる）。

- 火がつかなかった夜も、住民は集まって座る（関係・会話はそのまま。暮らしを退屈にしないため）。
  ただし「焚き火の会」とは数えず、日記に「火のない集まり」と書く。`village.fires` は増えない。
  （`village.fires ≥ 2` で桟橋の相談が始まる。いまの世界はもう過ぎているので影響しない。新しい世界では少し遅れうる）
- 朝の集まりは今までどおり（火は出さない）。
- 炎の見た目は `fireHours` ではなく `burning`（＋工程の火）に従うよう変える。これは見た目の変更なので別 PR

## 5. 試算（石垣の3年分の毎時の記録 2022〜2024、`firesim.mts`）

1089 日。夜の消灯は「熾の寿命切れ」か「雨 8 mm」。抽選は固定 seed。

| 設定 | 夕方に熾が消えていた | そのうちおこせなかった（火のない夜） | 連続で火のない夜（最大） |
|---|---|---|---|
| 寿命 12 h、雨 8 mm、昼の試みなし、雨の日は ×0.2 | 月 6.4 回 | 月 2.8 回 | 6 晩 |
| 同じ＋昼にも試みる | 月 3.4 回 | 月 2.1 回 | 5 晩 |
| 昼にも試みる＋軒下でおこす（v1 の試算） | 月 3.2 回 | 月 1.8 回 | 3 晩 |
| **v2 の規則どおり（`firesim2.mts`、ハッシュ抽選、欠測の扱い込み、seed 3通り）** | **月 3.1〜3.4 回** | **月 1.9〜2.0 回** | **5 晩** |
| 同じで 22 % → 25 % まで成功しうる | 月 3.1 回 | 月 1.2 回 | 5 晩 |
| 寿命 10 h | 毎晩 | 月 6.6 回 | 8 晩 |

- v1 の試算（`firesim.mts`）は連続乱数・欠測の代用値を使っていて本文と違った（Codex 指摘）。v2 の規則で再計算すると、
  夕方の約 93 % が焚き火の会、最長 5 晩続けて火のない夜がある。月に3回ほど「熾が消えていておこし直す」場面があり、
  月に2回弱、湿った夜に火がつかない。梅雨・台風のころに偏る（季節らしさとして良いと考えている）。
- 熾の寿命 12 時間は、灰で覆った熾が「数時間〜一晩」もつという実用の記述と、朝の埋め直しの間隔から決めた。
  雨 8 mm も仮定。どちらも params に `assumed` として置き、観察で直す。

## 6. 旧データの読み方

- `village.hearth` がない保存（今のすべての保存）は、読み込んだ時刻に `embers`、`dieAt = 読み込み時刻 + 12 時間`
  として始める（初めて開いた夜に火がつかない、ということが起きないように）。`??=` で足すだけで形式の番号は変えない。
- 保存の増え方は数十バイトで一定（日ごとの記録は持たない。回数だけ）。

## 7. 実装されたら科学班が確かめること

1. 同じ seed・同じ天気なら、1分刻み／1時間刻み／まとめて追いつき（オフライン 3 日）で `hearth` が同じになる。
2. 時刻パネルの早回し・プリセットで `hearth` も焚き火の会の数も変わらない（ADR 0001）。
3. 湿度 95 % では1回も成功しない／60 % ではほぼ1回目か2回目で成功する。
4. 雨 8 mm で熾が消える、朝の埋め直しで寿命が延びる、嵐の日は延びない。
5. 旧セーブ（rehearsal-1 の old-saves）を読んで、最初の夜に火がつく。保存の大きさがほぼ変わらない。
6. 島の早回し（`npm run sim`、soak-island 1 週間）で、火のない夜が月 1〜3 回の範囲に入る。

## 8. この仕様でしないこと（v2 以降）

- 焚き火で薪が減ること（夕方 1.7 時間で数 kg。薪の取り合いになるので、C0 で炉の式と一緒に決める）。
- 火口に `coir_pith` を使うこと、火種をヤシの殻で運ぶこと（ほかの場所・島へ）。
- 風で火の粉が飛ぶ・燃え広がる、けが。
