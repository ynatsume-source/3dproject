# 科学側のレビューの進め方

2026-10-04 / **オーナーが合意した方針**（科学側 Claude の提案に、オーナーが同日に賛成した）

科学側（Claude）・Codex・本体側（main 担当）の三者が従う。変えるときはオーナーの合意を取り、この文書を更新する。

## 1. レビューの重さを、変更の重さに合わせる

| 変更の種類 | レビューの仕方 | 統合を止めるか |
|---|---|---|
| 新しい工程・接続仕様の変更・状態の形の変更 | **全面レビュー**：収支・区切り・停止・拒否・来歴・資料・本物らしさ | 重い指摘（下の「影響」A・B）は止める |
| 指摘への修正 | **軽い確認**：指摘が直ったか、直し方が新しい穴を作っていないか、だけ | 直っていなければ止める |
| 端のケース（影響 C） | 次の全面レビューへまとめて回す | 止めない |

- 軽い確認では、科学側は Codex の診断スクリプトの入力を回帰検査（`scripts/science-review-regressions.ts`）に取り込んでおく。Codex はそれを再実行し、差分を読む。
- 全面レビューの依頼書は、これまでどおり `CODEX_REVIEW_REQUEST_<commit>.md` に置く。

## 2. 指摘は影響の大きさで並べる

Codex は指摘ごとに、次のどれに当たるかを書く。

| 影響 | 意味 | 例 |
|---|---|---|
| **A 世界が嘘になる** | 物や熱が増える・消える、同じ入力で結果が変わる、住民が知り得ないことを知る | 熱を前半に使い切れる（F1）、熱のただ取り（W3） |
| **B 本体を壊す・止める** | 例外、保存状態の誤読、検査器を通らない正常な答え | 最初の要求で例外（W1）、0.2.x の拒否の形（W2） |
| **C 理屈の上の端** | 通常の操作では起きにくい入力。直す価値はあるが急がない | 1 ms で止める、継承プロパティの名前 |

## 3. Codex に厚めに見てほしい観点

科学側の数式の検査では確かめにくいもの。

1. **本物らしさ**：陶芸・窯・薪をやる人が見て、結果が現実の感覚と合うか（乾く日数、割れ方、薪の量、焼き上がりの時間、火の色）。合わないときは、どの数値・どの仮定が原因かの見立てを添える。
2. **自分の検査の思い込み**：科学側の検査が、本当に確かめるべき形になっているか（例：返却ロットをつながずに繰り返していた W3 の検査）。
3. **資料**：取得できた一次資料だけを `sources.json` へ。取得できなかったものは探索記録として残し、係数の根拠にしない。科学側も別の経路（公開リポジトリ経由など）を試す。

## 4. 変わらないこと

- Codex は lab（`codex/civilization-lab`）だけを変更する。科学側のブランチと main は変更しない。
- 修正は科学側が行う。main に取り込み済みのファイルを直したら、科学側が本体側へ取り込み直しを依頼する。
- 本体への統合は、Codex の確認と本体側の最終レビューの後に、小さな単位で行う。
