# ADR 0002｜ひとつの共有世界と、科学コアとの境界

状態：採択（2026-10-02）
置き換えるもの：ADR 0001 の 4（ブラウザでの最大12時間の追いつきを正式仕様とする）、7（保存はブラウザの localStorage）、「後回しにすること」のうち共有世界とサーバー常時実行。
出典：オーナーの決定（2026-10-02）、`docs/proposals/ai-world-server/`、Codex 設計案 `codex/creative-world-design`（c510246、未採択の提案）のうち下記に挙げた判断。

## 背景

住民の暮らしを「誰もが同じ島・同じ住民・同じ歴史を眺める」共有世界にすることをオーナーが決めた。
住民の創作（材料→施工→利用→改修→伝承）と、原料から照明まで作る長期の科学・文明を育てる。
科学・文明の重いシミュレーションは別の Claude プロジェクトが別ブランチで並行開発する。同じリポジトリで二重実装や二重計上を起こさない境界が要る。

## 決めたこと

1. **世界はひとつ、正本はサーバー**：国内 VPS 上の単一 writer（Node）と SQLite が世界の正本。閲覧者の数は世界の速さ・材料・AI 呼出に影響しない。閲覧者 0 人でも進む。
2. **ブラウザは閲覧者**：確定した状態と順序つき差分を受け取って描く。切断中は最後に確定した状態を示し、端末で新しい採集・施工・会話を進めない。既存のブラウザ内の島は、共有世界と混ぜない別のモード（オフライン・個人）として残す。旧保存を共有世界へ自動で取り込まない。
3. **世界時計**：住民・材料・工事・劣化・科学工程は世界の UTC 時刻で進む。日付の境界（生活・予算）は Asia/Tokyo。観賞用の時刻・季節・天気の指定（共有 URL を含む）は見た目だけで、正本を進めも戻しもしない（ADR 0001 の 3 を継続）。
4. **事実と見た目の分離（継続・具体化）**：作品は部品・接続・働き・作者・来歴として保存し、メッシュは導出する。画質で材料や働きは変わらない。
5. **AI は提案、世界が確定**：AI の出力は候補の選択・計画・言葉に限る。材料・場所・支え・衝突・到達・時間を世界が検査し、`commandId` で重複を排し、一つの transaction で確定する。AI に座標・数量・完了・時刻・コードを書かせない。AI は目的・計画・行き詰まり・改修・会話・振り返りの節目でだけ呼ぶ。
6. **AI 予算は全用途で一つ**：判断・会話・内省・創作・科学（研究の言語化を含む）を合わせて月 15,000 円。運用上限はそれより低く置く。会話や内省は場面単位で予約し、予約内で自然に終える。送達不明の課金は戻さない。バックアップから世界を戻しても予算台帳は戻さない。
7. **科学コアは純粋な計算部品**：材料加工・化学変化・熱・機械仕事・電気・研究の結果は、科学コアが「区間の状態変化案・消費/生成量・エネルギー収支・本人に見える観測・根拠」として返す。科学コアは時計・在庫・保存・課金・ネットワーク・乱数の外部源を持たない。在庫更新・保存・イベント確定は世界の正本が一度だけ行う。接続仕様は `docs/proposals/civilization/SCIENCE_HANDOFF.md` と `src/world/science-contract.ts`。
8. **分担**：科学コアは `codex/civilization-simulation`（別プロジェクト）で開発する。本体側は同じブランチを編集しない。共通インターフェース（`src/world/science-contract.ts`）の変更は main への PR として本体側がレビューし、最終採択と統合は本体側が行う。
9. **創作の設計案から採る判断**：`CONTRACTS.md` の用語（worldId / worldEpoch / worldVersion、MaterialLot、Project / BlueprintRevision / Work / PartInstance、Action と lease、UseSession、ProcessRun、EnergyLedger、確定イベント）を共通語彙にする。最初の創作は「ドットの小さな共同作業場：材料→施工→ランタンの実利用→フィードバック→改修」。

## まだ決めないこと（提案値のまま）

- 25cm グリッド、32 部品、長辺 6m・高さ 2m・1 層などの規模。G1 の試験世界で体格・動線・描画負荷を測ってから決める。
- 向かい風（事故）の頻度・損失上限・保護区分。試験世界で確かめ、限定的に導入する。住民の永久喪失は入れない。
- 科学工程カタログ（82 工程、概念案）の数量・熱・時間・性能。原典照合と校正の後、検証済みの工程だけを実行可能にする。
- 共有世界の出発点（新規に始めるか、選んだ一つの旧 snapshot を移すか）。切替時に決める。

## 結果

- サーバー側の作業（正本・時計・材料台帳・保存/復旧・配信・AI gateway と予算）は本体側が担う。科学側に、別の世界サーバー・永続在庫・世界時計・課金台帳を作らせない。
- `residents.ts` は描画・DOM・保存・乱数が同居しているため、時計・保存・地形の adapter を抜き出してから Node で動かす（設計案の G0）。
- 観賞時計と世界時計がずれる表示（例：観賞で夜にしても工事は進まない）を UI で分かるようにする。
