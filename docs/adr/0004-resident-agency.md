# ADR 0004｜住人の主体性と、思考の配分

状態：採択（2026-10-03）
関係：ADR 0002（AI は提案・世界が確定、AI 予算）、ADR 0003（提案：人間も Actor、共通の身体と行為、持ち物は資源 ID）。資源の ID 管理は ADR 0003 で扱い、この ADR は「誰が、何を根拠に、どう考えて動くか」を扱う。
出典：オーナーの構想（2026-10-03）、Codex との相談（同日）、香山レビュー `NAVIGATION_REVIEW.md`「AI がマイクラをプレイする」設計。

## 背景

オーナーの構想は、各キャラクターが自分の機能と性格を持つ AI として、視界・持ち物・知識をもとに世界を攻略していくこと。いまの4体はルールで行動を選び、AI は会話（任意のキー）と試験モードのランタンだけで使っている。

## 決めること（提案）

### 1. 4体全員が主体
4体とも、**観察 → 目的 → 計画 → 行動 → 結果 → 記憶** の循環を持つ。目的を決めるのは本人で、経験によって判断が変わる。自律性を決めるのは AI を呼ぶ回数ではなく、「誰が目的を決め、結果から何を学ぶか」。

ドット以外の3体も、次のことをする。
- 自分の関心から何かを始める。
- ドットや仲間に提案する。
- 頼まれても、別にしたいことがあれば断る。
- 失敗を覚えて、やり方を変える。
- 自分の専門で仲間に教える。ドットが仲間から教わる場面もある。

### 2. 各自の機能と専門（体と能力値の差として世界に表す）
| 住人 | 機能・専門 | 性格の軸 |
|---|---|---|
| ドット | 建てる・加工する・発明する。手が器用で、材料を多く運べる | 粘り強い、主人公、難しい問題に向かう |
| ランタン | 測る・地図を作る・夜と空を観察する。四本脚で足場を確かめる | 慎重、記録好き、夜型 |
| カメマル | 海の生き物と水の観察。泳ぐ、潜る、長く待てる | 博物学者、のんびり、細部にこだわる |
| ラッコ | 海底から拾う。石を道具に使う。少量を水中から運ぶ | 好奇心、遊び好き、見つけたものを見せたがる |

### 3. 考える仕組みは4層
| 層 | 誰が | いつ |
|---|---|---|
| 体と接触 | 世界（全員共通） | 毎更新。歩行・回避・運搬・届くか（`solids.ts`、水域区分） |
| 習慣と反応 | 各自のルール（性格つき） | 常時。API がなくても、予算が尽きても動く |
| 判断 | AI（軽量モデル） | 節目：目的の完了・失敗・行き詰まり・発見・頼まれごと・断るかどうか・1日の振り返り |
| 深い思考 | AI（上位モデル）。主にドットに厚く配分 | 難しい計画、未知の物の調査、失敗の原因分析、発明 |

AI の返答を待つ間も体は動き続ける（今の行動を続けるか、考える仕草をする）。

### 4. AI に渡すもの、返させるもの
- **渡すもの**：本人の視野・距離・遮蔽・明るさを通った観察（物体 ID・種類・距離・いつ見たか）、持ち物（資源 ID）、本人の知識と記憶、使える行為の一覧、直近の結果（`went` など）。画像は、形や見た目を詳しく調べる場面だけ。
- **返させるもの**：目的・計画・行為の要求・言葉。座標・数量・完了・時刻は書かせない。通れるか、届くか、材料があるか、終わったかは世界が判定する（ADR 0002 の 5）。

### 5. 知識は「仮説」と「確かめたこと」を分ける
LLM の事前知識は消せない。そこで「木から炭が作れそう」のような発想は**仮説**として扱う。材料を集め、工程を試し、世界（科学コア）の結果を確かめて初めて、本人の**実績と知識**になる。思いついただけでは成功にしない。

知識には、出所（見た／試した／聞いた／推測した）と根拠の出来事 ID を付ける。日記・会話・次の判断は、この区別を守る。

### 6. 仲間との関わりも世界の出来事
提案・頼みごと・断る・教える・渡すは、行為として世界に記録する。取り合い（仲間が先に拾った、同じ材料を同時に使おうとした）は世界が判定して、結果を本人に返す。

### 7. 運用の設定は、コードと設計から切り離す
モデル名・役割ごとのモデル・呼び出し頻度・1体ごとと全体の予算上限・予算切れ時の振る舞いは、変更できる**運用設定**にする。呼び出しごとに、住人・目的・入出力トークン・キャッシュ・遅延・費用・結果を記録し、実測で見直す。

## 費用の目安（確定予算ではない）

前提：1回の判断で入力約4,000トークン（毎回変わる部分）と固定部分約4,000トークン（キャッシュ）、出力約400トークン。1ドル150円、30日。
単価は公式料金ページの検索結果による（上位 $4/$20、軽量 $1/$5 /100万トークン）。採用時に料金ページとアカウントの実額で再確認する。
1回あたり：上位 約 $0.026（約3.8円）、軽量 約 $0.0064（約0.96円）。

| 構成（他3体は軽量で各100回／日） | 4体合計の月額 |
|---|---|
| ドット：上位 200回／日 | 約3.2万円 |
| ドット：上位 960回／日（16時間、平均1分に1回） | 約11.9万円 |
| ドット：軽量 200回＋上位 20回／日 | 約1.7万円 |
| ドット：軽量 960回＋上位 20回／日 | 約3.9万円 |

含まないもの：画像、キャッシュ作成、課金される思考トークン、再試行、会話、閲覧者との会話、サーバー・通信費。

共有世界では、住人が定期的に考える費用は閲覧者の数に比例しない。ただし閲覧者との会話や通信は別に増える。

ADR 0002 の月15,000円は、実測が出るまでそのまま置く。見直しはオーナーが実測値で判断する。

## 進め方と受け入れ条件

1. **ドットで一周**：雨の日にも使える作業場、のような目的を本人が決める。材料と手順を考え、体が運び、足りない・塞がれた・発見したらAIへ返り、計画を変えて記憶する。予算切れでもルールで動き続ける。
2. **もう1体を加える**：ラッコを想定（拾う専門、ドットへの提案と拒否がわかりやすい）。仲間が先に材料を拾った、頼みを断られた、教わってやり方を変えた、まで試す。
3. **4体へ広げる**：1体ごとの費用・遅延・行動の変化を記録し、運用設定を決める。

各段階の合格条件：
- 見ていない物を「見た」とせず、試していないことを「できた」としない。
- 失敗のあと、同じ失敗を同じやり方で繰り返さない。
- 仲間の拒否・取り合いが世界で判定され、本人の記憶と日記に正しく残る。
- AI の遅れ、予算切れ、キーなしでも、止まらず、壁を通らない。

## まだ決めないこと
- 上位と軽量のモデルの最終選定、呼び出し頻度、予算額（実測後）。
- 閲覧者（人間）と住人の会話の扱いと費用。
- 共有サーバー移行前の試験は、ブラウザの島（任意のキー）と、ヘッドレスのシミュレーションのどちらで行うか。私の案は、両方で同じ住人のコードを動かすこと。

## 追記（2026-10-04、採択）：発信の技能 — 島だより

オーナーの決定：住人の特殊技能として Web で発信する。公開先は `utsushiyo.earth/journal/`（島だより）。まずドットとラッコ。

- **撮影**：住人の行為に「写真を撮る」を加える。何を撮るかは本人が決める（自分の視野にあるものだけ、同じものは1日1回まで）。1日3枚まで、少なくとも1枚（15時を過ぎて0枚なら島がうながす）。写真はその瞬間の本人の目の位置・向き・時刻・ほかの住人の位置として記録し、実アプリで描き直す。
- **記事**：毎日1本ずつ。材料は本人のその日の記録・撮った写真・交わした言葉だけ。記事には自分のその日の写真を1〜3枚、必ず載せる。記録にない事実・数値・天気は書かない。URL・宛先・宣伝・政治・実在の人物は扱わない。検査に通らなければ1回だけ書き直し、だめなら出さない。
- **正式な島**：ブラウザごとの島ではなく、毎日1回 GitHub Actions で動かす島（状態は journal-data ブランチ）の二人が書く。共有世界（ADR 0002）への第一歩。
- **承認**：記事はプルリクエストで出し、運営者がマージしたものだけが公開される。すべてのページに「住人はAI」「自分の記録と写真だけから書く」「公開前に確認」と明記。
- **費用**：運用設定（scripts/journal-run.ts）。島の一日の思考はドット深い12・軽い30、ラッコ軽い20まで。記事は各3回まで。目安 1日 $0.5〜0.9。
- 詳細と設定手順：docs/JOURNAL.md。
