# ADR 0001｜小さな永続世界から育てる

状態：採択（2026-09-30）
出典：Codex 提案「Seaglass Architecture Kit v0.1」（`docs/proposals/`）を、現在のコードに合わせて修正したもの。

## 背景

実在の海を眺める観賞アプリに、島で暮らす住民4体（ドット・カメマル・ランタン・ラッコ）がすでにいる。
住民はブラウザ内に保存され、関係・日記・会話を積み重ね、閉じていた間の暮らしも追いつき計算される。
今後、住民の世界を作り込み、将来は陸・空・訪問者へ広げたい。開発は AI との対話で続けるので、会話が変わっても方針が失われない仕組みが要る。

## 決めたこと

1. **構成は継続**：TypeScript / Vite / Three.js（WebGL）の単一アプリ。エンジン移行・マイクロサービス化はしない。
2. **世界の事実と見た目を分ける**：住民の位置・状態・記憶・関係は世界側。モデル・画質・シェーダーを変えても同一性と記憶は変わらない。新しいコードでは「世界 → 見た目」の一方向を守る。既存コードは触るついでに少しずつ寄せる。
3. **住民は「世界の時間」＝現実の時刻で暮らす**：時刻パネルの早回し・季節・朝昼夕夜は観賞用（空・光・生態系の見た目）で、住民の日記・関係・予定の時刻を動かさない。
4. **見ていない間も暮らしは続く**：再び開いたとき、閉じていた時間を追いつき計算する（現行の方式を正式仕様とする。上限12時間）。*提案キットの「閉じている間は停止」は採用しない*。
5. **LLM は補助**：LLM がなくても用意された台詞とルールで暮らしが続く。返答は形式と内容を検査してから反映する。描画ループで待たない。
6. **API キー**：本人のキーを本人のブラウザに置く現在の方式は試作としてのみ可。訪問者が使う公開機能にする前に、キーを持つサーバーを挟む。
7. **保存**：当面はブラウザの localStorage。キーは `seaglass.*` を維持。形式を変えるときは版を上げ、旧形式を読んで移行する（黙って初期化しない）。
8. **文書は軽く**：`CLAUDE.md`（毎回の約束）、`docs/ARCHITECTURE.md`（現状の地図）、`docs/adr/`（判断）の3つ。ほかの文書は必要になったら作る。

## 後回しにすること

サーバーで常時動く世界、複数人で同じ住民を見る共有世界、IndexedDB への移行、地球規模の区画読み込み、課金・土地など。必要になった時点で ADR を書いて決める。

### 本番開始時に一緒に行うこと（本人の希望、2026-09-30）

独自ドメインで公開し、住民の暮らしを「1から」この世界で走らせて蓄積し始めるタイミングで、次をまとめて行う。

- **住民の考えと言葉を AI で生成する**：独り言・会話・焚き火の話を、用意した定型文ではなく、その子の個性・記憶・その日の出来事・見えているものから AI が毎回書く（今は同じ言い回しの繰り返しで「ボット」らしさが出ている）。
- そのための前提：API キーを持つサーバー（ブラウザに置かない）、呼び出し回数と費用の上限、失敗しても定型文とルールで暮らしが続くこと、記憶（日記・関係・出来事）を AI への入力に使う形の整理。
- 住民の時間を現実の時刻に固定する（決めたことの 3）も、このときまでに済ませる。

## 代償

- 旧い構造（大きな main.ts、入り組んだ依存）としばらく共存する。
- 住民の時間を観賞の時刻から切り離すと、早回しで「夜の住民」を見る遊びはそのままではできない（見たい場合は別の仕組みを考える）。
- 追いつき計算は開いたブラウザの中だけ。別の端末とは住民が共有されない。

## 見直す条件

- 複数の端末・複数の人で同じ住民を見たくなったとき（→ サーバーと共有世界）。
- 保存データが localStorage に収まらなくなったとき（→ IndexedDB）。
- 現在の描画方式が主な制約になったとき。
