# 構成図（現状）

2026-10-10 時点のコードに合わせた「いまこうなっている」の地図。理想形ではない。採択済みの方針と、まだ実装していないものは分けて記す。
境界を変えたらこの文書も直す。まだ決めていないことは「未決」と書く。

## 1. 全体の流れ

```
地球儀（globe.ts） ──地球の海を選ぶ──┐
もうひとつの星のカード / #planet ───┴─▶ buildOceanSteps(loc)（ocean/build.ts）
                                    ├─ 地形・サンゴ・洞窟・陸（ocean/*）
                                    ├─ 生態系 Ecosystem（eco/*）
                                    └─ 住民 Residents（robots/residents.ts、ドットたちの島のみ）
                                         └─ 工程表 / 実行役（world/process-*）→ 科学コア（science/*）
                                         │
main.ts のループ（毎フレーム）             ▼
  clock.advance → applySky → updateDrone（director で撮影先を決める）
  → cave / 露出 → residents.update → eco.step → HUD・音・描画（render/post.ts）
```

一度作った海は `oceans[worldKey(loc)]` に残り、戻ったときに作り直さない。`src/world/location-id.ts` の `worldKey` は地球を `earth:<id>`、ドットたちの星を `planet:<id>` とし、海・シェーダー準備済み・訪問済み・最終訪問・先行生成のキャッシュを世界ごとに分ける。地球の嘉弥真島とドットたちの島はどちらも地形の `loc.id = 'kayama'` を使うが、海の実体は `earth:kayama` と `planet:kayama` に分かれる。地形のデータと仕組みは共有し、嘉弥真島の値を `Object.create(kayama)` で継承する（ADR 0007）。

残す海は、今いる海と直前に訪れた2つ（`KEEP_SEAS`）と、住人のいる海だけ。それより古い海はシーンから外して形状・素材・テクスチャを解放する。陸のデータ（`lands`）は、同じ地形IDを使う別の海や生成中の仕事がなくなったときに忘れる。もう一度訪れたら作り直す。地球儀で先に作って訪れなかった海も同じように解放する。見ていない海の生態系は進まない。

入口の URL も `location-id.ts` の `seaHash`・`seaForHash` を使う。地球は従来の `#kayama` など、ドットたちの島は `#planet` で、入場後の URL・再読み込み・共有リンク・LAB の再現リンクも同じ世界を選ぶ。

## 3. 時間の種類

| 時間 | 実体 | 使う場所 |
|---|---|---|
| 観賞の時刻 | `clock.ms`（早回し ×1〜×360、季節で日付をずらす `offset`、朝昼夕夜プリセット） | 空・光・潮・天体、生態系の一日のリズム |
| フレーム時間 | ループの `dt`、`U.uTime` | 動き・アニメーション |
| 現実の時刻 | `Date.now()` | 住民の保存時刻、見ていない間の追いつき、天気の取得 |
| 住人の更新時刻（現実の実装） | 通常モードは `clock.ms`、`?lantern-study` は `Date.now()`（`main.ts` の `residents.update`） | 住人の暮らし・日記・関係、工程の入力となる `worldTime` |
| 島の暦・待つだけの時間 | `world/island-time.ts` の `ISLAND_RATE = 365 / 28`、`islandDate`・`islandWait`、工程の `toClock` | ドットたちの島の暦・天気、乾燥・焼成・栽培・回復・渡航。工程表の `clock: 'island'` は約13倍、`'world'` は住人の更新時刻 |

採択済みの方針：住人の生活・日記・関係は現実の時刻を使い、観賞の早回し・季節・プリセットで書き換えない（ADR 0001・0002）。島の暦と待つだけの変化は約13倍にする（ADR 0006・0007）。通常モードはまだ観賞の時刻を受け取っており、日記の日付・経過時間・科学工程の基準時刻も影響を受ける。時計を分離する作業は未完了。島の天気の取得は `Date.now()`、科学へ渡す天気は住人の更新時刻を `islandWeather` に渡すため、観賞の時刻を変えた場合の不一致も残る。

住人の保存には、上のほかに考える部分の状態と記憶、家・石垣・生き物の休み場・集落への移住、筏と渡航・島の地図、雨受け、台風への備え、材料ロット・設備・工程の `lab`、灯りの記録も含む。保存キーは引き続き `seaglass.residents.v1`。

世界を識別できない旧い観賞データ（`resume.sea` の素の地形ID、`opening` の素の地形ID）は復元に使わず、観賞位置と導入の印だけを作り直す。導入の印は次の保存で旧いIDの項目を外す。住人の保存データ・キーはこの観賞データの変更では書き換えない。

図鑑の旧形式は同じ `seaglass.seen` に `<海ID>:<生きものID>` の文字列配列を保存していた。読み込み時の `migrateSeen` は現在の世界付きキーを保持し、地球と判別できる嘉弥真島以外の旧キーを `earth:<海ID>:<生きものID>` に移す。旧 `kayama:<生きものID>` はどちらの世界で見たか判別できないため、読み込む観賞の記録から外す。次の発見時に移行後の配列を保存する。図鑑の表示と発見・種のキャッシュも世界ごとのキーを使う。

出来事ログの旧形式は `seaglass.log.<海ID>.<日付>`。新しい世界付きログがないとき、嘉弥真島以外の地球の海では旧ログを読み、次の保存で世界付きのキーへ書く。両世界が混ざりうる旧 `seaglass.log.kayama.<日付>` はどちらの表示にも読み込まないが、元の storage の項目は残す。これらは観賞の図鑑とログの移行で、住人の記憶・日記の保存には触れない。

住民の保存は20秒ごと。再び開いたとき、閉じていた時間（最大12時間）を20秒刻みで追いつき計算する。これは現在のブラウザ内の実装で、共有世界のサーバー正本を採択した ADR 0002 の実装はまだない。住人がいる海を開いたときにだけ動き、他の海や地球儀では住人を更新しない。追いつきのループは通常の `Residents.update` を通さず、そこで行う科学工程の定期更新も通らない。
魚など生態系の個体は保存しない。

## 6. 乱数と再現性

地形・配置は `core/math.ts` の `mulberry32` と `R()`（種つき）で決まる。動き・演出・住民の一部は `Math.random()` で、再現はしない。

## 8. 変更が集中する場所・気をつけること

- `main.ts` に多くが集まっている。分割は「その部分を触る作業のついでに1つずつ」。一括移動はしない。
- シェーダーは `render/common.ts` の `COMMON`（霧・光・洞窟の光）を全材質が共有する。ここを変えると全部に響く。Windows（ANGLE/D3D11）では、テクスチャを読むシェーダー内の早期 return で GPU が落ちた実績がある。
- 読み込み時に全シェーダーを準備する（`prepareShaders`）。並列コンパイル対応環境では12個ずつまとめて、非対応なら1つずつ。

## 9. ランタンの観察と制作（レビュー用試作）

`?lantern-study` を付けた嘉弥真島だけで有効。`robots/lantern-study.ts` が関心・問い・観察・作品・判断履歴を持ち、`residents.ts` が既存の移動/作業を実行した後に結果を確定する。`lantern-brain.ts` の任意のAI提案は許可済み行動候補からの選択に限り、実行中の仕事や世界の事実を書き換えない。遅延応答は次の判断時に再検証する。LLMの出力は制作物の文言にも利用できるが、観察値や星の座標には使わない。

試作では住民4体の時計を `Date.now()` に揃え、観賞用の `clock.ms` と分離。通常モードの既知の時計の問題はこの変更では直していない。試作は `seaglass.lantern-study.residents.v1` に島ごと保存し、初回のみ既存 `seaglass.residents.v1` を読み取りで引き継ぐ。通常の住民保存は上書きしない。画質等の設定・APIキー/使用回数・観賞ログは既存と共通。新しい `lanternStudy.version=1` は旧データの欠落・不正値を検査し、保留中の通信/途中の行動を復元せず、未完成の作品を残す。不在進行中は新たな星の観察とAPI判断を行わない。現行方式で最大12時間の暮らしを追いつかせる。

`robots/lantern-sky.ts` は既存 `public/stars.bin` の20恒星から観察時点の地平線上の計算位置を求め、記録済みの星だけをSVGへ出力。作品・記録には天候の入力元を残す。個別の雲の遮蔽や実測の視認ではない。`ui/lantern-study.ts` は状態を読む専用手帖で、作品出力とAI利用の切替を行う。ルール判断が初期値。履歴は作品6件・観察24件・記憶48件・判断32件以内に制限する。

`robots/mind.ts` の通信保護は通常の会話にも共通。既存キー/モデルと1通信ずつの枠を使い、この試作の判断は8秒で中止、会話と試作判断を合わせ1日120回まで（単一タブでの試作制限）。通常住人の `MINDS` による判断は別の用途別枠。試作の AI 判断は最短5分間隔。失敗時はルールを続け、保存不能でも `aiuse` のセッション内の回数を保持する。サーバーで強制する費用上限や複数端末で共有する世界は未実装。詳細と検証は `docs/proposals/lantern-autonomous-study/`。

## 共有世界と科学コアの境界（ADR 0002）

- `src/world/science-contract.ts`：科学・文明シミュレーション（別プロジェクト、`codex/civilization-simulation`）との接続の型と規則。`process-catalog.ts`・`process-runner.ts` と `robots/residents.ts` を通じて、島の実際の工程に使う。変更は main への PR で、本体側がレビューする。
- 分担と接続の詳しいメモ：`docs/proposals/civilization/SCIENCE_HANDOFF.md`。
- `src/science/`：科学コアから取り込んだ工程と結果の検査器。接続仕様は工程ごとに持ち、現在の島の工程は主に `0.2.1` と天気の `record` を使う。粘土の浸漬・練り、器の成形・乾燥・野焼き、薪の乾燥、ヤシのミルクと油、油の灯り、試験用の気圧計、乾留の炭・木タール・木酢液、壺のタール封止を住人の暮らしに接続済み。島で使えるかは工程表の `ready` と、その場の材料・自作設備・天気の記録で判定する。試験タイルの成形・乾燥、管を通した自作気圧計、漏れ試験は `ready: false`。科学側の持ち物で、本体側は計算を変更せずに取り込む。
