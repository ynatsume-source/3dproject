# 試し回し（2026-10-26〜。rehearsal-1 の代わり）

## 決まったこと（オーナー 10/26）
- 10/31 からの rehearsal-1（23f2c17 に固定して 24〜48 時間）は**延ばす**。
- 代わりに、10/26 の試運転のような短い試しを、**数日に 1 回、5〜6 回**回す。毎回その時点の main を使い、「見る → 見つけたことを直す → 次の回」を繰り返す。
- **目指すもの**：初めて開いた人が、最初の 60 秒で「**この世界の行く末を見届けたい**」と思うこと。ゲームの実況配信の代わりに見たい、BGM 代わりに流しておきたい、と選ばれること。

## そこから出てくる決まり（本体の読み。各班で詰める）
1. **行く末が見える**：世界がどこへ向かっているか（住人の大義・今の挑戦・道のり）が、いつも画面にある。その進みが、日ごとに見える。
2. **次が気になる**：いま何が懸かっているか、次に何が起きるか（今夜の焚き火の会、明日の渡航）が分かる。
3. **流しておける**：目を離していても、耳で世界が分かる（声・波・時刻に合わせた音楽）。見る価値のある瞬間は、音で呼ぶ。
4. **退屈な 1 分を作らない**：どの 60 秒を切り出しても、意味のあるもの（会話・決めた瞬間・進み・見せ場）が 1 つはある。
5. **島は続ける**：試しは毎回同じ島で行う（ブラウザの `rehearsal-trial`）。島の歴史が積み重なること自体が「行く末」になる。

## 費用（オーナー 10/26）
- 試し用のキーの workspace に、月の上限 300 ドルを付けてある（サーバー側で止まる）。
- いまは検証の速さを優先する。費用は目安（1 体 1 日 100〜200 円）を見ながら、多少は融通を利かせる。上限に近づいたら、本体がオーナーに知らせる。

## 1 回の回し方
1. 本体が、回す commit と、その回に見てほしい所を知らせる。
2. 家の PC で、アプリの黒い窓を閉じてから（Ctrl+C → Y）：
   ```
   cd $HOME\3dproject
   git fetch
   git checkout （本体が知らせる commit）
   npm.cmd ci
   npm.cmd run build
   npx.cmd vite preview --port 4173 --strictPort
   ```
3. ブラウザは `rehearsal-trial` のまま起こす（WINDOWS.md 手順 5。島とキーが残る）。アドレスは `http://localhost:4173/?live&rehearsal`。開いたら、まずコンソールで `seaglassRehearsal.saveOut()`（始めの保存 `save-…json`。同じ島なので、回ごとの保存の育ち方が分かる）。
4. 見る長さは自由（30 分〜数時間）。気づいたことは、右下の JST の時刻と一緒に、メモかスクリーンショットに残す。「離れたくなった」時刻も残す。
5. 終わり：F12 →「コンソール」で `seaglassRehearsal.download()` と `seaglassRehearsal.saveOut()`（終わりの保存）を打つ。Ctrl+J で `rehearsal-…ndjson` と `save-…json` が来たのを確かめたら、`seaglassRehearsal.clear()` を打つ。そのあとブラウザを閉じ、黒い窓で Ctrl+C → Y。
6. 記録（`rehearsal-…ndjson`）・始めと終わりの保存（`save-…json` 2 つ）・メモを本体に送る。保存は科学班にも渡す。所見は `findings/README.md` に足す。

## 長く回す確かめ（科学班の提案 10/26）
- **科学班が毎回**：その回の commit で、画面なしの soak（島の 1 週間）を回す。保存の大きさ・追いつき・エラーを見る（オーナーの PC は使わない）。
- **オーナーが毎回**：試しの始めと終わりに `seaglassRehearsal.saveOut()` を 1 回ずつ（上の 3 と 5）。
- **1 回だけ**：4 回目と 5 回目のあいだ（11/6〜8 ごろ）に、AI を入れたまま一晩〜丸 1 日回す。住人 1 体 1 日の費用（目安 150〜200 円）と、長時間の描画を測る。6 回目の判断の前に結果を出す。手順は RUNBOOK.md を使う。

## 毎回測ること（本体、`scripts/rehearsal-read.mjs`）
- **意味のある分の割合**：1 分ごとに、次のどれかがあったか。
  - 強：配信画面に出た字幕（sub）・節目の札（card）
  - 弱：状態の 1 行の変わり目（status）
  - 海の出来事の記録（event、shown）は別に数える。記録の決まりは通っているが、配信画面には出ないため。
  強だけの割合と、弱も含めた割合を出す。強のない分がいちばん長く続いた長さも出す。
- AI の呼び出し（数・失敗・トークン）。
- 遅いフレーム（slow）の数と内訳。
