# 住民が暮らし続ける世界サーバー（設計案）

2026-10 作成。オーナーの予算決定（AI 全体で月 1.5 万円まで、住民1体1日 150〜200 円まで許容）を受けた設計案です。合意後に実装します。

## なぜ必要か

今の住民は、閲覧者のブラウザの中だけで暮らしています。AI もそのブラウザから、閲覧者自身の API キーで呼んでいます。このままでは次の3つが解決しません。

1. **タブを閉じると考えない。** 戻ったときは最大12時間分を規則で早送りするだけで、留守中の思考も会話もありません。
2. **予算を確実に止められない。** 上限はブラウザごとの回数制限だけで、オーナーの費用として月額を守る仕組みがありません。
3. **一般公開できない。** オーナーのキーをブラウザに置けば漏れます。訪問者ごとのキーでは、普通の人は住民の AI を見られません。

## 提案：ひとつの島を、サーバーで24時間動かす

**全員が同じ4体を見る、ひとつの世界にします。** 住民の位置・行動・記憶・関係・作品はサーバーが正本として持ち、ブラウザは受け取って描くだけにします。うつしよの「現実を写した、もうひとつの地球」にも、予算が閲覧者の数に左右されない点でも、この形が合っています。

```
 ブラウザ（閲覧者）              世界サーバー（常時起動の Node）            Anthropic API
 ┌────────────────┐  状態を配信  ┌──────────────────────────────┐  呼び出し ┌──────────┐
 │ 3D の島・海を描く │◀────────────│ residents.ts をそのまま実行      │──────────▶│ Sonnet 5.5│
 │ 住民の体を動かす  │  (SSE/WS)   │ ・行動の決定・実行・記憶         │◀──────────│ Haiku 4.5 │
 │ 日記・手帖を読む  │────────────▶│ ・予算台帳（月額で必ず止まる）     │           └──────────┘
 └────────────────┘  閲覧のみ    │ ・保存（SQLite、日次バックアップ）  │
                                 └──────────────────────────────┘
```

### 既存コードを活かせる理由

- `src/robots/residents.ts` は描画と切り離されていて、Node で動きます。`scripts/lantern-residents-check.ts` などがすでにブラウザなしで実行しており、3時間分の暮らしを約2秒で計算できました。サーバーの負荷はごく小さいです。
- 必要な追加作業は2つです。
  - 嘉弥真島の地形グリッド（`public/land/`）を Node で読むローダー。今の `loadLand` はブラウザの fetch 前提です。
  - 保存先を localStorage からサーバーのストレージに替えること。
- 世界の事実はサーバーが確定し、LLM の返答は検査してから反映します。CLAUDE.md の原則とランタンの試作の設計はそのまま守れます。

### ブラウザ側

- 住民4体の「いま」（位置・向き・行動・手にしている物・作業の経過）を1秒に1回程度受け取り、間を補間して動かします。データは4体で数百バイトです。
- 日記・会話・手帖・作品は、開いたときにサーバーから読みます。
- 観賞用の時刻の早回しは今までどおり見た目だけで、住民には影響しません（ADR 0001）。
- サーバーにつながらないときは、今の手元シミュレーションで暮らしを描きます。古い保存はそのまま読めます。

## 決定事項（2026-10-02）

- 住民の島は独立したひとつの世界として、サーバーで24時間動かし続ける。
- 島全体と、まわりの海を360度、1〜2km先まで作る（下記「島と海の範囲」）。
- サーバーは推奨案（Fly.io などの常時起動 Node）。
- 会話や内省は、盛り上がっているところで途中で切らない。配分はテスト週にパターンを分けて検証する。

## 島と海の範囲

今の嘉弥真島は、島の中心から約 ±760m の地形（衛星画像と標高）を持っています。中心が島からずれているので、方向によっては海が数百mで終わります。これを、島の中心から半径2kmの円の内側すべてで地形と海が続くように広げます。

- 地形・水深：既存の手順で、島の中心から半径2km（4km四方）を作り直す。遠くほど粗い格子で持ち、容量を抑える。
- 海の生き物：今の「カメラの近くだけ生き物を置く」仕組み（半径約720m）を2kmまで広げる。生き物の密度は資料に基づき、根拠のない数を付けない。
- サーバーの住民が歩き回る範囲は島の中だけで、海の広さはサーバーの負荷に影響しない。

この作業は描画側だけで完結するので、サーバーの土台作りと並行して進められます。

## 会話と内省を途中で切らない

回数の上限を1回ずつ数えると、盛り上がった会話や深まった独り言が途中で切れます。そこで、予算を「1回」ではなく「ひとまとまり」に割り当てます。

- **会話は1つの場面として予約する。** 会話を始めるときに、その場面の上限（例：最大12往復、約30円）を予算から確保します。モデルには毎回「続けたいか・自然な終わりか」を返してもらい、話の切れ目で終えます。確保して使わなかった分は戻します。
- **内省も1つの流れとして扱う。** 独り言が前の考えを受けて深まっているあいだは、数回分を続けてよいことにします。同じ話題を言い換えて回っているだけなら、そこで閉じます。
- **一日の終わりで止めない。** 日をまたいでも、始まった場面は最後まで続けます。その分は翌日の配分から差し引きます。
- **止めてよいのは月の上限だけ。** 月額に近づいたら、新しい場面を始めないことで調整します。始まっている場面は自然な終わりまで続けます。

## テスト週のパターン分け

7日間を3つのパターンに分け、同じ指標で比べます。費用はどれも月1.5万円の範囲に収まるように組みます。

| パターン | 日数 | 判断 | 会話 | 内省・日記 | ねらい |
|---|---|---|---|---|---|
| A. こまめに考える | 2日 | 1体1日100回 | 1場面 最大8往復 | 短め | 細かい行動の変化が面白さになるか |
| B. 語り合う | 2日 | 50回 | 1場面 最大16往復、回数も多め | 普通 | 関係と会話が見返したくなるか |
| C. 深く考える | 2日 | 50回 | 普通 | 内省の流れを長く、夜にまとまった日記 | 作品・考えの積み重ねが育つか |
| 振り返り | 1日 | 結果を見て選んだ組み合わせ | | | 本番の配分を決める |

各パターンで記録すること：実費（1体ごと・合計）、会話の長さと自然な終わり方の割合、繰り返しの多さ、判断の理由に過去の出来事が出てくる割合、オーナーが「見返したい」と印を付けた出来事の数。

## AI の使い方と予算

### モデルの使い分け

| 用途 | モデル | 理由 |
|---|---|---|
| 次に何をするか（関心・記憶・途中の作品から） | Sonnet 5.5 | 面白さを決める部分。質を優先 |
| 住民どうしの会話 | Sonnet 5.5 | 関係の変化と記憶が要る |
| 1日の振り返り・日記・作品に添えることば | Sonnet 5.5 | 見返したくなるかを左右する |
| 短い独り言・相づち | Haiku 4.5 | 数が多く、軽い |

料金（2026-09 時点の Anthropic 公表値、1ドル150円で換算）：Sonnet 5.5 は入力 $2・出力 $10、Haiku 4.5 は入力 $1・出力 $5（いずれも100万トークンあたり）。

### 1体1日の配分（初期値）

| 内容 | 回数 | 1回の目安 | 円/日 |
|---|---|---|---|
| 行動の判断（Sonnet） | 80 | 入力2,000・出力300 → 約1.1円 | 約90 |
| 会話（Sonnet、相手と折半） | 10 | 入力3,000・出力500 → 約1.7円 | 約17 |
| 振り返り・日記（Sonnet） | 1〜2 | 入力4,000・出力800 → 約2.4円 | 約4 |
| 独り言（Haiku） | 30 | 約0.5円 | 約15 |
| **合計** | | | **約125円** |

4体 × 125円 × 30日 = 約1.5万円です。性格・世界の説明など毎回同じ部分はプロンプトキャッシュに載せます。載る長さに達すれば入力費が下がり、その分を判断の回数に回せます。テスト週の実測で配分を調整します。

**判断の頻度**：80回なら、起きている時間帯で10分に1回ほど自分で考えます。今のランタンの試作は最短5分間隔ですが、その間の細かな動作は規則で続けます。

### 予算を守る仕組み

- **台帳はサーバーに置きます。** API の返答に含まれる実際のトークン数に単価を掛けて、1回ごとに記録します。
- **月の上限 1.5 万円は絶対に越えません。** 呼ぶ前に、その回の最大費用を足しても上限内かを確かめます。上限に達したら、その月の残りは規則と用意した台詞だけで暮らします（止まるのは AI だけで、暮らしは止まりません）。
- **日の配分は、月の残額を残り日数で割って毎日決めます。** 1体の上限は1日200円です。静かな日に使わなかった分は、出来事の多い日に回せます。
- **閲覧者は AI を直接呼べません。** 訪問者の数が増えても費用は変わりません。
- API キーはサーバーの環境変数にだけ置き、リポジトリやブラウザには出しません。

## 置き場所

| 案 | 月額の目安 | 良い点 | 注意点 |
|---|---|---|---|
| **A. Fly.io などの小さな常時起動 Node（推奨・採用）** | 約 $5〜7 | residents.ts をほぼそのまま動かせる。SQLite で保存が簡単 | アカウントと支払い設定が必要 |
| B. Cloudflare Workers + Durable Objects | 約 $5〜 | 既存のドメイン管理と相性が良い | 実行時間の制約があり、シミュレーションの組み替えが大きい |
| C. 自宅や手持ちの PC | 0円 | すぐ試せる | 止まると世界も止まる。公開には不向き |
| D. エックスサーバー（契約中のレンタルサーバー） | 追加0円 | Node 自体は入れられる | 共用サーバーは長時間動き続けるプロセスを想定しておらず、24時間の世界の置き場には向かない。静的ファイルの配信や、保存データの予備の置き場には使える |

`api.utsushiyo.earth` のようなサブドメインで公開します。DNS の追加は前回と同じ画面で行えます。

## 進め方

1. **土台（2〜3日）**：サーバーで嘉弥真島の住民を動かし、保存と配信をします。ブラウザは配信された状態を描きます。AI はまだ使いません。
2. **AI と予算台帳（2〜3日）**：判断・会話・日記を Sonnet / Haiku に振り分け、台帳と上限を入れます。オーナー用の簡単な集計ページ（その日の費用、1体ごとの回数、最近の判断）も作ります。
3. **テスト週（7日）**：オーナーだけが見られる状態で、実際の API で動かします。毎日の確認項目は次のとおりです。
   - 1日の実費（1体ごと・合計）と月額の見通し
   - 行動の偏りや同じことの繰り返し
   - 記憶が次の行動に使われているか（判断の理由に過去の出来事が出てくる割合）
   - 見返したくなる出来事（会話・作品・日記）が1日にいくつ生まれたか
   - サーバーの停止・再開で記憶が欠けないか
4. **公開**：テスト週の結果で配分と頻度を直してから、一般の閲覧者に開きます。

Codex と分担する場合は、手順2の集計ページや、テスト週の記録を読みやすくする道具がまとまった試作に向いています。

## オーナーに決めてもらうこと

1. **ひとつの世界にしてよいか。** 全員が同じ4体を見ます。今の「ブラウザごとの島」は、サーバーにつながらないときの予備として残します。
2. **置き場所。** 推奨は A（Fly.io など）。アカウント作成と支払い設定はオーナーにお願いすることになります。
3. **API キー。** オーナーの Anthropic アカウントで、このサーバー専用のキーを発行してもらいます。Anthropic 側の利用上限も月 $100 前後に設定しておくと、二重の安全策になります。
