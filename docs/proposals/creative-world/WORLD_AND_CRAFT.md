# 世界に残る創造 — 材料、建築、使用、改修

設計提案。実装済みの機能ではない。基準コミットは `9b5a40f`。
全員が同じ島・同じ住民の歴史を眺める共有世界を対象とする。
識別子・遷移・書き込み権限は [CONTRACTS.md](CONTRACTS.md)、共有世界の実行と保存は [ARCHITECTURE.md](ARCHITECTURE.md) を正とする。

## 1. 目指す創造体験

住民の制作物は、形、用途、作られた経緯、使われ方を持つ。
誰かの困りごとから作られ、別の住民に使われ、作者の予想と違う結果が次の制作に返ってくる。
作業場が増えるだけでなく、「この机は雨に困ったランタンのためにドットが直した」と風景から読める世界を目指す。

制作の自由は、完成した家を一覧から選ぶことだけに限定しない。
材料の長さ、接続できる部品、支え方、利用位置を組み合わせ、同じ部品から違う形と使い方を作れるようにする。
一方、AI が名前を付けただけで新しい物理法則や機能が発生する仕組みにはしない。
形の新しさ、用途の有効性、本人や仲間が感じる魅力を、別々に育てる。

最初の一作は小さくても、場所の履歴は長く残す。
完成数や建築面積を増やすことを住民共通の目標にせず、見直す、修理する、今日は作らないという暮らしも成立させる。
興味の変化、共同制作、模倣と作者の記憶は [AGENCY_AND_CULTURE.md](AGENCY_AND_CULTURE.md) を参照。

## 2. 現状から引き継ぐもの

`src/robots/residents.ts` には、ドットが拾った木を運び、作業台で加工し、小屋へ順に取り付ける動作がある。
固定された部品群 `HUT` と進捗数で形を出し、石積み、桟橋、貝殻の収集も別々の状態で管理している。
採集・運搬・加工・取り付け・完成後に眺めるという、観賞上の手触りは活かす。
ただし、この構造をそのまま自由建築や共有在庫の正本にはしない。

`items.ts` は流木・貝殻・石を時間で補充し、保存から読む際に物の ID を採番し直す。
予約も保存されず、部材の加工後の形は主に作る対象で決まる。
新方式では物の所在、加工の入力と出力、取り付け済みの部品を永続的に追う必要がある。
既存の小屋や思い出を無断で解体・資材化せず、旧世界の移行方針は [CURRENT_STATE.md](CURRENT_STATE.md) と [ROADMAP.md](ROADMAP.md) に従う。

## 3. 材料・部品・設計図・作品を分ける

| 対象 | 持つ意味 | 例 |
|---|---|---|
| 材料ロット `MaterialLotId` | 出所、材種、数量、寸法、状態、所在、予約、加工履歴 | 浜で見つけた乾いた流木、回収した板、使い残した継手 |
| 部品 | 設計内の局所 ID、登録済み部品種、寸法、接続点、必要な材料 | 柱、梁、天板、屋根板、座板、接合部 |
| 設計版 `BlueprintRevisionId` | 部品と接続のグラフ、支持関係、配置、用途、検査条件 | 屋根付きの台と、屋根のない隣の観測場所 |
| 制作計画 `ProjectId` | 動機、作者、協力者、対象地、採用設計版、進行と中断理由 | 「雨の日も手帖を描ける場所を作りたい」 |
| 計画版 `ProjectRevision` | 対象作品、目的、評価条件、作業の依存関係 | 初回の建設計画、利用後に立てた改修計画 |
| 実物 `WorkId` | 実際に施工した部品、現在の機能、使用記録、修繕履歴 | 試用中の共同作業場 |

設計図と実物は一致しない期間を正常な状態として扱う。
まだ設置していない屋根が図面にあっても、雨は避けられない。
計画を中止しても、設置済みの柱や置いた資材は消えない。残置物の回収・保存・解体を次の行動として扱う。

すべての実物と計画は `WorldId` に属し、作者・実行者は `ResidentId`、場所は `SiteId` で参照する。
命令の再送は `commandId` で重複を防ぎ、実行を `ActionId`、確定した変化を `EventId` で追う。
部品内の局所 ID を、住民や実物の永続 ID の代用にしない。

## 4. 組み合わせから形を作る

初期の部品カタログは、脚・柱、梁、板、屋根用の重ね板、座板、登録済み接合方式に絞る。
部品は寸法範囲、接続点、許可角度、接続相手、支えの条件、材料要求、加工方法、衝突形状を持つ。
寸法と配置は制限付きの数値で提案できる。色違いだけを創造の中心にしない。
設計者は「片側に屋根、反対側に空を見る余白」「二人が向き合う台」「狭い材料で作る低い台」などを構成できる。
V1 の配置は、地形検証で向きを決めた敷地座標内の 25 cm 格子と、部品の水平回転 90 度刻みを出発点とする。
格子は接続と検査を簡単にするためのもので、地形全体や部材の外観を立方体にしない。
接合部の細かな形や表面の曲がりはカタログ側で連続的に表現し、接続点と衝突形状との整合を保つ。

V1 の提案上限は、1 設計 32 部品、敷地の長辺 6 m、高さ 2 m、地上 1 層、同時施工 1 計画。
実行中はWorkごとの現存施工部品の合計も32以内とし、改修の旧部品・新部品・仮支えをすべて数える。撤去済みの回収材は在庫へ移るが、資材置き場の占有上限は別に検査する。設計版を増やして上限を回避しない。
数値は最初の検証用予算であり、実装時に住民モデルの体格、搬送能力、描画負荷を測って確定する。
建物の完成テンプレートを内部で選んでいるだけのものを「自由設計」と報告しない。
最低限、部品の配置・寸法・接続の違いが外観と利用位置に反映されることを受入条件にする。

部品の接続グラフ、地面からの支持関係、組立順序の DAG を分ける。
「脚を固定 → 梁を接続 → 天板を置く」の依存があり、支持のない板を先に確定させない。
四角い枠のような接続の輪は許せるが、施工の循環依存は差し戻す。空中接続、材料より長い部材、到達できない接合位置も検査する。
完成形の支持だけでなく、各工程で施工者が届き、運べることを確かめる。高さ2mは上限候補であって、ドットがそこへ無条件で手を伸ばせる意味ではない。V1は実際の体格・工具で組める高さと部材寸法に絞り、未実装の登攀や重量物の持ち上げを計画の前提にしない。
複雑な連続物理・構造解析は V1 に含めず、検証済み接合と寸法範囲による簡略な構造ルールを使う。

AI の出力はカタログ内の構成案と理由であり、任意 JavaScript、シェーダー、任意メッシュを世界の正本に実行しない。
V1 は設計生成器が組み立てた複数の合法な部品グラフから、敷地・配置・用途・好みを選ぶ。グラフの直接編集提案は後続段階にする。
レンダラーは検証済みの実物状態から形を作る。低画質になっても、柱の位置や通行可否は変わらない。
新しい接合方式や新機能は、開発側が挙動と検査を追加したカタログ版から利用可能になる。

## 5. 完成すると、本当に何ができるのか

V1 の機能は `supportSurface`、`rainShelter`、`restSeat` の 3 種に限定する。
機能は実物の組立状態から導出し、AI が「完成した」「便利」と言ったことだけでは有効にしない。

| 機能 | 成立条件 | 実際の暮らしへの効果 |
|---|---|---|
| `supportSurface` | 支持が揃い、傾き・高さ・面積が許容範囲で、利用位置まで到達できる | ランタンが手帖の制作場所として選べる。道具を置く位置が決まる |
| `rainShelter` | 対象領域を屋根が連続して覆い、支持があり、利用者が収まる | その領域で雨による制作中断を減らせる |
| `restSeat` | 座面の支持、体格への適合、着座と退出の空間がある | 適合する住民が休憩先として選び、実際に座る |

効果の範囲を限定する。屋根の存在が星の観察を可能にしたり、制作の才能を直接上げたりはしない。
屋根付きの描画域と屋根のない観測域を別の利用位置として持ち、移動経路でつなぐ。
星を見る位置では、設計した対象方向と上空の遮蔽を検査し、屋根が被れば候補から外す。
天候・天体の入力元と時刻を記録し、屋内で星を「観測した」という記憶を作らせない。

雨の検査は最初は鉛直方向の被覆と支持による簡略判定とする。
横殴りの雨や材質の吸水を再現していない段階で、完全防水・耐候建築とは呼ばない。
検査器による仮想の降雨試験と、共有世界で実際に降った雨の中の使用記録は区別して保存する。
晴れが続く間も試用は進められるが、「雨の日にも役立った」という経験は実際の入力があるまで生まれない。

音を出す `instrument`、上を歩ける `walkableDeck` は後続段階とする。
音響、接触、荷重、経路の切替など、それぞれの作用を実装する前にラベルだけ増やさない。
棚を追加する段階では、保管位置・容量・出し入れ・運搬距離を実装し、物を飾る見た目だけで終えない。
道の段階では経路としての到達性と移動コストを更新し、近道・雨天時の歩きやすさなど採用した効果を実際の移動へ反映する。

## 6. 材料の出所と保存則

建築用の流入元を登録する。V1 は乾いた漂着木、出所を記録した回収材、初期配置された有限の工作用資材が候補。
初期配置は「創作世界の開始時の備蓄」であり、現実の島に実在する資材を計測したとは扱わない。
採取可能な物と、地形・生息場・景観の一部を区別し、目に映る全ての木や石を建築在庫にはしない。
新たな漂着を採用する場合は、上限・発生条件・入力元を持つ独立した流入イベントにする。
不足した材料を、住民の計画を成功させるためだけに補充しない。
木の成長・伐採・再生を扱う後続段階では、生育個体と採取ロットを結び、木材を生む時間と植生への影響を記録する。
V1 の補充を「木が育った」と説明する代用はしない。

材料は「地面」「保管場所」「運搬者」「加工中」「取り付け済み」「端材」「廃棄」のいずれか一つの所在に属する。
同じ木を二人が予約しても、引き渡しの確定で二重取得できない。
加工では親ロットから子ロットと端材を作り、投入量・歩留まり・損失を記録する。
数量の台帳は固定小数点の基準単位で扱い、例として乾燥木材の質量を整数 g で保持する。
寸法と材質も検査する。質量が足りるだけで、短い端材から長い柱を生成しない。

`流入 + 開始時在庫 = 未使用 + 運搬中 + 加工中 + 組込済み + 再利用材 + 記録済み損失` を守る。
吸水・乾燥などを後で加える場合も、乾燥材量と含水量を分け、資材が増えたことにしない。
雨や放置による劣化は状態を悪くするイベントであり、毎フレームの描画乱数で在庫を変えない。
予約の期限切れは所有権の予約を解く処理であって、手元や現場の資材を元の浜へ戻す処理ではない。

## 7. 場所の選定と、工事が世界を塞ぐ問題

候補地は地形・植生・既存作品・住民の動線を参照して世界側が検証する。
AI は候補 `SiteId` と敷地内の許可配置から選び、未検証の座標に直接建物を置けない。
急斜面、浸水域、生息環境への影響が大きい領域、既存作品の占有地を V1 の建築候補から外す。
保全上の実データがない範囲は、現実の許認可が確認済みであるようには表示しない。
V1 では新たな伐採や掘削を伴わない候補地を用い、地形改変は後続の独立機能とする。

予約は敷地の永久所有を意味しない。施工に必要な期間、資材置き場・作業位置・占有範囲の競合を調整する。
搬入路、住民の通常経路、施工者の退路、他の住民の家と水辺への経路を確認する。
資材置き場と途中までの柱も衝突対象になる。図面の半透明表示は衝突を持たない。
一つの部品を確定する直前に、施工者と周囲の住民が新しい衝突形状の中に閉じ込められないか再検査する。
通路幅は最も小さい住民だけで決めず、そこを使う住民と運搬物の外形に余裕を足して判定する。

経路が塞がったときは、その行動を保留し、資材置き場の変更・別の接近位置・計画変更を選ぶ。
住民を瞬間移動させたり、衝突だけ無効にして施工を成功扱いしたりしない。
施工後の経路更新と部材消費は同じ確定に含め、メッシュだけ建った状態を正本に残さない。
この検査は設計時の一回だけでなく、設置・接続・除去の各一手に行う。
地形、支持、衝突、施工者の届く距離、資材の所在、利用中の住民を、直前の確定状態で再検査する。

## 8. 施工の進み方と中断

計画段階は `proposed → surveying → designing → ready → building → trial → active`。
中断は `paused` と `resumeStage`、終了は `abandoned` / `retired` を使う。詳細は [CONTRACTS.md](CONTRACTS.md) に従う。
段階が `building` でも、完成済みで安全な台を部分的に使える場合がある。
ただし作業中の領域との分離ができなければ利用を止める。利用可否は計画段階とは別の、実物の機能・占有状態で判断する。

1. 現地を見て、使う位置と搬入路を調べる。
2. 複数の構成案を比べ、必要な材料・手順・検査条件を確定する。
3. 実在する材料を予約し、拾い、運び、現場または作業台へ置く。
4. 材料を加工し、出来た部品を運び、依存関係の揃った接続点へ取り付ける。
5. 世界側の検査を通し、試用者が実際に到達して使う。
6. 利用実績と本人の感想を受け取り、継続使用・改修・保留を選ぶ。

利用記録には誰が、いつ、どの部位を、何に、どれだけ使ったかと、中断・不便の原因を残す。
作者の記憶には事実の参照と本人の受け止めを分けて渡す。利用回数の少なさだけで失敗作と断定しない。
作者が直接見た、利用者から聞いた、後で摩耗を調べたという知覚を経て伝える。世界の全利用ログを自動的に作者の知識にしない。

各段階で必要な移動・手作業の時間が経過してから、行動の完了を検査する。
LLM の返答やブラウザのアニメーション終了通知は、材料消費や設置を確定する根拠にしない。
疲労、充電、睡眠、会話、天候、材料不足で中断でき、理由と実際の残置状態を残す。
世界実行プロセスが停止していた期間の扱いは共有時計の規約に従い、訪問者のブラウザが独自に工事を進めない。
再開時は実在する部品・在庫・予約と残手順を照合し、すでに終えた加工をもう一度消費しない。
資材の移動、接続、破損、取り外しは世界時刻付きのイベントとして順序付け、確定前後の状態をたどれるようにする。
過去の制作の再生は記録済みの結果を映す読み取り機能とし、再生中に施工や材料消費をもう一度実行しない。
細かな手の動きを記録していない場合は、復元した演出であることを区別し、完全な映像記録とは呼ばない。
LLM は動機・設計案の比較・試用後の反省などの節目に使い、運搬の一歩や板の取り付けごとには呼ばない。

## 9. V1 の一つの出来事を、材料と行動で追う

以下はテスト用の一例であり、全ての住民が毎回同じ展開をたどる台本ではない。
材料の量・敷地・天候は試験条件であり、現地の実測値ではない。

| 順 | 共有世界で確定すること | 在庫・通行・機能の変化 |
|---|---|---|
| 0 | 工作可能な木材 48,000 g と、必要な登録済み接合材が有限在庫としてある | 出所・寸法・個数と所在を登録。既存の小屋はそのまま |
| 1 | ドットがランタンの制作中断を見て、共同作業場を提案 | 動機は体験イベントを参照。未施工なので衝突は増えない |
| 2 | 検証済みの候補地を比較し、屋根付き作業域と露天の観測域を設計 | 支持グラフ、空を見る方向、搬入路を検査。材料を予約 |
| 3 | ドットが材料を数回に分けて運び、脇へ積む | 地面から運搬中、現場在庫へ移る。仮置きの衝突が増える |
| 4 | 加工と施工を進め、台、柱、梁、屋根を取り付ける | 完了した部品だけ衝突が有効。退出を塞ぐ配置は取り付け前に拒否 |
| 5 | 木材 32,000 g が組込済み、12,000 g が未使用・再利用可能、4,000 g が記録済みの加工損失になる | 48,000 g の総量が一致。接合材も別台帳で同様に保存 |
| 6 | 台の支持・到達性、屋根の被覆、観測域の遮蔽を検査して試用へ | 条件を通った機能だけ有効。図面への賛辞で完成を代用しない |
| 7 | ランタンが観測域で空を見て、屋根側へ移動して手帖を描く | 実際の利用位置、移動、制作時間、中断理由を記録 |
| 8 | ランタンが「台をもう少し低くしたい」と感じ、利用記録とともに伝える | 感想は主観。到達不能・動作の無理など客観条件と分ける |
| 9 | ドットが寸法変更案を作り、利用を一時止めて脚を加工・再接続する | 同じ `WorkId` に新しい設計版。旧部品が外れるまでは旧形状が残る |
| 10 | 再試用で姿勢・到達性と本人の反応を確かめる | 差分の材料収支、衝突、利用記録を保存。改善しなければ追加改修を保留できる |

例の屋根に雨の有用性を与えるには、世界側に雨と制作中断・回避の関係を実装する必要がある。
現在の制作処理にその関係がなければ、屋根の見た目だけを追加して V1 完了とはしない。
通常実行で改修理由が生まれないときに不満を捏造しない。受入試験では、改善余地のある初期寸法と利用者条件を用意して一巡を確認する。

## 10. 修理、解体、再利用にも手順を持たせる

改修は元の設計版を上書きせず、新しい `ProjectRevision` と `BlueprintRevisionId` を持つ改修計画として扱う。
同じ作品を育てる場合は `WorkId` を維持し、旧版と新しい施工差分の関係を記録する。
屋根を交換する際、下の机を使い続けられるかは工区の検査で決める。無条件に作品全体を消さない。
支持している柱を先に抜く手順は拒否し、必要なら一時支持の部品・材料・動作を要求する。

解体は組立依存を逆にたどり、接合解除、搬出、回収材の検査と保管を行う。
再利用できる量をレシピで決め、損耗した材料から新品を無限に取り出せないようにする。
中止した作品の全消去や、図面の削除による材料の自動返却を行わない。
`retired` は使う目的から退いたことを表す。実物の撤去済みとは別に扱い、残るものの所在を記録する。
使わなくなった作品も、撤去前の形・作者・使用の履歴から振り返れるようにする。

耐久・嵐による損傷は、使用頻度、材質、経年、記録済みの世界の天候を根拠として後続段階で導入する。
閲覧者が嵐のプリセットを選んだことは、共有世界の破損原因にならない。
破損部位から機能を再判定し、柱が壊れたまま安全な椅子として使える矛盾を防ぐ。
修理ばかりで新しい創作が止まる場合は、劣化率・修理頻度の上限・機能の休止方針を調整する。退席中の罰として大量に壊さない。
休止は傷んだ部材を新品に戻す操作ではなく、利用を止めて必要な修繕を待つ選択にする。

## 11. 全員を同じ職人にしない

| 住民 | 初期に適した関わり方 | 勝手に与えない能力 |
|---|---|---|
| ドット | 運搬、検証済みの加工と接合、組立、利用者に合わせた寸法調整 | 無制限の持ち上げ、道具なしの新材質加工 |
| ランタン | 計測、観測方向の評価、軽い材料の運搬、作品の利用と感想 | 観測していない事実の断定、体格を超えた重作業 |
| カメマル | 水辺の経路を実際に通る、場所で休む、利用しやすさが行動に表れる | 人間の手のような精密接合、工作のための不自然な姿勢 |
| ラッコ | 適合する物の扱い、水中や水際の利用、身近な物への好みを示す | 陸上の大工仕事を一律に担当すること |

能力は身体・到達範囲・運搬量・登録済み操作に基づく。性格が意欲を変えても、身体能力を直接書き換えない。
動物の参加は観察される振る舞いだけでも成立する。机を使わなかったことも、設計者にとって情報になる。
生物として現実に見られる能力と、この島の住民としての架空の会話や共同生活は区別する。
既存の桟橋には動物が施工する工程もある。その完成状態と履歴を消さず、未完了分は対象の旧計画だけで使える互換Actionとして移行する。これは上表の新しい汎用技能への追加ではない。材料不足や不明な進行を勝手に完成扱いせず、同じ世界の実行器で再検査する。

## 12. 実在の地球と、住民が変えた世界

地形・星・生物・天候の元データと、住民の建築・痕跡を別の層で持つ。
実物は基準地形の版と位置を参照し、現実の観光施設や実在の建築物であるようには案内しない。
地形データを更新した際、建物が空中・水中へ移る問題は検出して移行対象にする。見え方だけで誤差を隠さない。
現地の保全上の事実には出典を付け、創作上の立入・採取制限には創作の規則であることを示す。
訪問者が鑑賞時刻を変えても、作品の劣化、雨による中断、住民の建築履歴は共有の世界時刻で決まる。

島に馴染む色と材質は共有カタログで定め、材種・風化・使用に沿った変化を持たせる。
建築可能な区域と密度上限を設け、住民が作り続けても浜や眺望が無制限に埋まらないようにする。
満杯のときは新築を止め、既存作品の共同利用・改修・合意した撤去を候補にする。古い思い出を自動削除しない。
同材質・同形部品のインスタンシングと距離別の LOD を使える形で描画データを派生させる。
遠くで見た目を簡略化しても材料・接続・衝突・来歴は共有状態に残し、画質設定によって世界を変えない。

## 13. 発明と世界拡張の先

最初は部品の組合せ、その次は組合せの再利用、共同作業と用途の転用へ進む。
「以前の台を低くすると椅子として使える」のように、既存の機能条件を新しい構成で満たす発見を可能にする。
その後、楽器や渡れる床などの機能を追加し、音の試作、道、工房、地域間の運搬へ広げる。
新たな地域も同じ `WorldId` に属し、地域の資材条件・生息場・移動時間を持つ。同じ在庫を離れた場所で二重に使わない。
未知の素材や作用を AI の作文だけで導入せず、候補として残し、開発側の検証済みカタログ拡張へつなぐ。
自由度を増やす順番と受入試験は [ROADMAP.md](ROADMAP.md) を参照。
