# 科学工程の設計データ

[工程一覧](PROCESS_CATALOG.md) / [元JSON](process-catalog.json) / [科学モデルの設計](../SCIENCE_AND_CIVILIZATION.md)

このフォルダはアプリから読み込まれない設計資料。`concept-only` の工程を実行するコード、世界の在庫、AI接続は含まない。

## データの意味

- `materials`：入力・生成物の種類。混合物に固定の分子式を付けない。`local-candidate` は島で存在確認済みという意味ではない。
- `capabilities`：必要な設備・操作・評価。`bootstrap` は出発条件候補で、原料自作に先立つ工具等の出所を別に決める。`external-advanced` はカタログ外の未成立能力であり、購入品で代替する指示ではない。
- `processes`：種類としての入力・出力と必要能力。数量・時間・条件・歩留まりは未定義で、実行レシピとして使用不可。
- `scope`：`raw-world` は原料自作の世界の候補、`test-fixture` は既製電材を用いる開発上の対照試験。後者の成果を本世界へ移さない。
- `energyModel`：熱・仕事・電力の主要な関係、供給元の条件、実行ごとの台帳を必須とする宣言。全件未校正。これだけで物理や消費量は計算できない。
- `equation`：一部の純物質反応の理想化した元素収支。熱の供給、混合物の反応、反応速度、収率を証明するものではない。
- `milestones`：確認する働き。必要な能力が静的に揃っても、本番では実在設備・実行結果・原料の来歴・現状の品質を再検査する。

現カタログの `import-or-recovery` は対照試験の既製電材に使う。本世界への原料の島外輸送を禁止する分類ではない。輸送を実装するときは、原料の地域・出所・搬出入と所在を本体の材料契約へ追加する。

実行用の工程定義に昇格させるには、[出典カード](../SCIENCE_EVIDENCE.md)、量/条件/時間、実在設備、収支と失敗時の行先、評価器、実行試験が必要。

## 静的検査と一覧の再生成

リポジトリのルートで、Python 3の標準ライブラリのみを使う。

```sh
python docs/proposals/creative-world/science/validate_catalog.py
python docs/proposals/creative-world/science/validate_catalog.py --write-index
```

前者は結果をJSONで出力し、失敗時は終了コード1。後者は検査が通った場合だけ、JSONと同じフォルダの `PROCESS_CATALOG.md` を再生成する。未知のJSONキー重複、ID重複、参照先、分類、未検証状態、主要なエネルギー関係、対照試験の混入、記載された反応式の元素数を確認する。材料/能力を作る工程の欠落も検出する。

到達性の診断は、**全ての候補原料と初期能力が仮に与えられた**条件で、種類の依存だけを追う。材料を消費せず、能力も消耗しない楽観的な検査。処理が閉じている場合は未成立の能力や循環依存を調べる手がかりになるが、到達しても現実やゲームの実行に十分とはいえない。

反応式の検査は、中性の単純式と括弧・整数係数のみ。水和物・イオン等の未対応記法は拒否し、推測して通さない。化学式が平衡でも、反応条件や工程の成立は別に照合する。

## 今回は検査しないもの

原典の科学的妥当性、嘉弥真島の資源量、材料の使用可能量、化学組成の実測、燃料・熱・電気の量、装置の性能、危険な工程の世界内制御、実行時の同時処理・再起動、AIの研究能力。これらは設計本文の後続条件であり、静的検査の合格をもって実装済みとはしない。
