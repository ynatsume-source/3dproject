# 適度な向かい風と、立て直す暮らし

2026-10-02 追補。状態：設計案、未実装。

ユーザー要望：「マイクラのデスペナルティや持ち物の破壊に近い向かい風を適度に入れたい。ただし、あまりに可哀想な理不尽さは避けたい」。本書はそのための初期案であり、損失量や発生間隔は検証前の調整値。部品・材料・履歴の正本は [CONTRACTS.md](CONTRACTS.md) に従う。

## 1. 何を面白さにするか

作品や道具が傷む、材料を失う、予定した仕事ができなくなる。その後、住民が何を守り、誰を頼り、何を直し、何を作り替えるかに個性が出る。補強した跡や失敗作の転用が、島の来歴になる。

実際に失う時間・使い勝手・少量の材料を用意する。結果は常に全回収でなくてよい。一方で、住民の存在・人格・記憶・関係を永久に失う仕組みは初期案に含めない。

住民が事前に把握できない出来事も起こり得る。対策していても小さな不運は残るが、原因と結果は世界の規則に沿う。視聴者を驚かせるためだけに、説明のつかない物品削除や、最も大切な物を狙う処理は置かない。

## 2. 逆境の種類

| 種類 | 出来事の例 | 実際に失うもの | 次に選べること |
|---|---|---|---|
| 足止め | 雨で加工が進まない、潮で搬入路が使いにくい | 作業時間、予定どおり進める機会 | 待つ、別の作業、材料の置き場を変える |
| 回収できる事故 | 運搬中に荷が落ちる、留め具が緩んで屋根板が外れる | 一時的な機能、回収/修理の手間 | 探す、拾う、手伝いを頼む、固定方法を変える |
| 小さな不可逆損失 | 浜の一般材料が少し流出する、加工に失敗して一部が使えなくなる | 再利用できない少量の材料 | 別材料を探す、寸法を縮める、端材を別用途へ使う |
| ロボットの行動不能 | 電池不足などで、作業を中断して一時的に動けなくなる | 行動時間、運搬の進捗 | 充電/休養、仲間による回収支援、運搬計画の見直し |

行動不能は実際の充電・回収・帰還の技能が用意できてから追加する。安全な場所への瞬間移動や、無条件の持ち物全ロストを前提にしない。カメマル・ラッコにはロボットの電池切れを流用せず、初期の事故対象から外す。動物の苦痛や死亡を見せ場にする設計にはしない。

最初の対象は、新方式で登録した小さな作業場と、来歴・所在がわかる一般材料。来歴が不明な旧建築を突然損傷対象にしない。

## 3. 守るものと、失ってよいもの

| 対象 | 初期方針 |
|---|---|
| 住民のID・性格・記憶・関係、作品の作者/来歴 | 消さない。経験値の一律巻き戻しも行わない |
| 最低限の休養/充電/退避先、復旧に必要な最後の工具や資材 | 事故で失う対象から除く。回復を始められる条件を残す |
| 最初の作品、一点だけの記念品、登録した思い出の品 | 初期は不可逆喪失の対象外。手入れ・修理できる傷みは別途検査 |
| 屋外の一般材料、交換できる屋根板、消耗品 | 所在・用途・回復手段と上限を検査し、損傷や一部喪失の候補にする |
| 過去の図面、作品画像、施工履歴 | 現物を失っても残す。材料なしで現物を復元する権利にはしない |

保護区分はカタログと世界の保存状態に持つ。初期の保護対象は移行/初期化時に確定し、AIが「すべて宝物」と宣言して上限や検査を回避する入口にはしない。将来、住民が大切な品を選ぶ仕組みを追加する場合は、登録枠と変更の履歴を別途設計する。

必須の生活機能を同時に失わせない。例えば二つの作業台の一つが使えなくなることは候補にできても、唯一の復旧経路や最後の工具を失わせる案は受理しない。

## 4. 最初の強度と間隔

下記は初期試験の仮値。自然現象の実測確率でも、必ずその間隔で事故を起こす予定表でもない。世界の時刻で数え、閲覧者数・ログイン・API呼出回数は発生率に使わない。

| 制御 | 初期案 |
|---|---|
| 導入の猶予 | 機能有効化から72時間以上、かつ少なくとも一回の正常な制作/利用/回収を検証した後に破損事故を有効化 |
| 同時に扱うもの | 島全体で、損傷・喪失・行動不能を伴う事故は未解決1件まで |
| 静かな期間 | 立て直しの確認後、島全体で24時間、同じ住民とWorkでは48時間、次の破損/喪失事故を抑制 |
| 少量の不可逆喪失 | 島全体で直近7日間に最大1件。全回収できるケースを基本に、たまに実損が残る |
| 素材の実損上限 | 1事故につき、対象素材種の事故前の未保護・利用可能な総量の5%以下。回収・修理で追加消費する損耗も同じ事故枠に含める |
| 回復の手間 | 1事故から再び使える状態まで、初期の標準回復経路で実作業30分以内という検査用見積もり。任意の増築・新作は別 |
| 機能の低下 | 最初は交換可能な一部分。構造全体の崩落、唯一の生活基盤、復旧経路の閉塞は対象外 |

5%は素材ごとの整数最小単位で切り捨てる。1個を失うだけで上限を超える在庫なら、その不可分な物は喪失対象にしない。異なる素材の個数や重さをそのまま合算しない。消耗・派生被害を複数事件に分割して上限を回避しない。

不可逆喪失の7日枠は、採用時に予定分を予約し、実損を確定した時刻で数える。修理による後日の不可逆損耗も同じ事故IDに積み、予定された損耗が残っている間は予約を維持する。最後の実損から7日以内に、別の不可逆事故を採用しない。猶予・冷却期限・設定版も保存し、再起動や単なる再有効化では期間を取り直さない。

30分は本人が望む完全な原状復帰の期限ではなく、事前に確認する最低限の回復経路の標準作業量。手がかりの確認/探索、移動、回収、必要な加工、設置を含み、休息・天候待ち・任意の設計変更は別に記録する。世界だけが場所を知っていても回復可能とは扱わず、本人か協力者が知覚を通して発見できる経路を要求する。費用や経路を評価できない事故は初期には発生させない。

上限を超える場合は、確定前に候補を棄却する。例えば強風は続いていても、これ以上の部材破損を追加しない。これは創作世界の被害モデルの範囲であり、現実の嵐の被害を忠実に再現しているという説明はしない。

雨による通常の作業待ち等と、新たな破損事故は区別する。同じ雨や未修理状態を毎回新しい失敗として数えない。慢性的な材料不足・摩耗・修理で同じ上限を迂回して負担が増えていないかも、7日/28日の記録で評価する。

## 5. 後出しで傷を消さず、起こす前に範囲を決める

事故の候補は、世界の記録された風・潮・使用・素材状態などから作る。例えば緩んだ接合、浜に置いた木材、運搬荷重と足場の組み合わせ。抽選がある場合は、規則版・原因・乱数結果を保存し、再接続で振り直さない。

確定前に、直接被害と派生被害、素材の上限、冷却期間、保護対象、代替機能、少なくとも一つの実行可能な回復経路を検査する。材料や救助役は直前の状態で確認し、必要な最小回復資源は予約する。他の通常作業が先に使い切って立て直せなくなることを防ぐ。

最小回復資源の確保は事故に紐づく有限の保護枠で、通常Actionの短期leaseと分ける。休息・再起動・作業leaseの失効でも消えない。具体的な運搬や修理は通常のleaseで行い、使用分を一度ずつ精算する。別経路へ切り替えるときは新しい回復手段の成立を検査してから旧予約を解放し、必要なら原子的に置き換える。

補償材料をその場で無限に発生させたり、確定後に「実は失っていなかった」と履歴を改変したりしない。回復資材を使わず別案で済ませた場合は、予約だけを解放する。

外れた部品は、検査済みの回収可能な場所へ所在を移し、衝突・支持・用途も同じtransactionで更新する。初期は危険な連鎖崩落を生む支持部材を対象にしない。損傷後の足場・避難路が成立しない候補は棄却する。

海へ流れ出て回収不能になった分は、在庫から消すだけでなく出所と量を保持した `unrecoverable` の記録へ移す。漂流中で追跡できる物は所在を残す。「行方がわからない」と「世界から完全に失われた」を区別する。

## 6. 世界が知ることと、住民が知ること

世界は原因と被害の正本を持つ。住民は、音を聞く、見に行く、棚を点検する、仲間から聞く等を経て知る。秘密の落とし物の位置や、必ず成功する復旧法を自動で本人へ教えない。

予兆は可能な範囲で用意する。風が強い、部品が揺れる、材料が濡れている等。すべての結果を正確に予告する必要はなく、住民が予兆を見逃したり、対策していても小さく失敗する余地は残す。

AIは事故・被害量・救済を確定しない。出来事を知った後、休む、調べる、拾い直す、助けを頼む、補強する、規模を縮める、別用途へ転用する、諦めて残す等を提案する。補強や保管が有効な条件では、次の同条件のリスクが実際に下がる規則を持たせる。

失敗の度に全員が同じ励ましの台詞を言ったり、必ず立派に成長したりする脚本にしない。本人の心残り、修理跡、慎重になった運び方、仲間に借りた物など、違う変化を残せる。失敗を住民の人格の欠陥として記憶へ固定しない。

## 7. 立て直したと判定するまで

「解決した」とAIが宣言するだけでは事故枠を解放しない。世界が、損傷した用途の復旧、実際に使える代替手段、または残置物を処理した上での用途の取りやめを検証する。作品の完全な原状復帰を義務にしない。

必要な材料・工具の所在と休養先を確認してから冷却期間を開始する。なお回復途中の住民や作品を、別事故の巻き添えにしない。同じ原因から派生した影響は元の事故へ束ね、途中で枠をリセットしない。

住民が修理しない選択をした場合も、別の利用先と暮らしが成立すれば受け入れる。新しい事故を起こすために、AIへ修理完了や見切りを強制しない。

## 8. 追加する状態と確定イベント

通信形式は未実装。既存の契約に、次の意味を追加する。

| 記録 | 内容 |
|---|---|
| `Incident` | `incidentId`、原因イベント/環境、対象ID、規則版、開始時刻、直接/派生影響、段階 |
| `ImpactReservation` | 事前に許容した損失量・素材ごとの基準残高・回復工数・保護対象検査・回復資源の予約 |
| 事故の段階 | `candidate → admitted → active → recovering → resolved`。採用前の不成立は `rejected`、採用後かつ被害未発生の取消は `cancelled`。同一正本で更新 |
| 物の状態 | 品質/耐久の `damaged`、所在変更の `displaced`、回収可能性の `recoverable / unrecoverable` は別軸。傷んでいても回収可能な物を表せる。数量・所在・用途をともに更新 |
| 回復と履歴 | 目撃/発見、回収、損耗、修理、代替案、解決判定、冷却期限、住民が知った経路 |

`IncidentAdmitted / IncidentCancelled / MaterialDisplaced / MaterialLost / PartDamaged / FunctionChanged / RecoveryCompleted` 等を、既存の `worldVersion / worldEpoch / commandId` に従って保存する。新しい予約確保と事故枠の消費は原子的に確定し、二つの同時候補が上限をすり抜けないようにする。

採用後に対象の移動等で不成立になり、まだ被害が確定していなければ `cancelled` とし、未消費の回復資源・事故枠・不可逆喪失の予定枠を同時に解放する。被害発生後は取消で枠を戻さず、回復か安全な用途取りやめの検証へ進む。損傷や喪失の適用時にも直前の状態を再検査する。

再起動後も未解決枠・素材損失・冷却期限を復元する。同じ事故を二度適用せず、履歴再生も被害を再実行しない。対象が直前に片付けられた、棚の場所が変わった等の場合は再検査し、古い候補をそのまま適用しない。

## 9. 運用障害と、不在の扱い

閲覧者がいなくても正常な共有サーバーは同じ世界を進め、同じ確率と上限を使う。訪問時にまとめて罰を与えたり、久しぶりの訪問に合わせて事故を起こしたりしない。

サーバー停止・保存不整合・API障害・デプロイ失敗・移動コードの不具合は、この事故機能の発生原因にしない。未実行期間の被害を後付けせず、最後の整合状態から運用上の復旧を行う。必要な管理者修正はその出所を残す。

AI停止や予算終了時でも使える規則による回収・手入れ・休息経路を用意する。課金しなければ助からない住民や、復旧に必ずモデル応答が必要な状態を作らない。

## 10. 最初に試す一件と、導入順

最初の制御試験は「共同作業場の交換可能な屋根板が一枚外れ、雨よけの範囲が狭くなる」。目撃や利用からドットが知り、拾って付け直すか、接合を補強するか、台の位置を変えるかを選ぶ。外れた物の所在・雨よけ・修理材料・改修履歴まで検証する。

次に、一般材料のごく一部を回収不能にした試験を行い、残る材料で作り替えることや、別の通常の供給機会を待つことを確かめる。最初から本番で抜き打ちの被害を起こさない。

- G1/G2：事故は無効のまま、通常の回収・修理・保存・用途評価を成立させる。
- G3：実AIの創作を見る通常期間では事故を無効にし、独立した試験世界で応答と回復を評価する。
- G4：修理・材料・環境・共有同期が揃った後、軽い事故を限定運用する。7日/28日の通常生活との比率を見て調整する。
- ロボットの行動不能、複数作品へ及ぶ被害、広い世界での漂流は、実際の回収手段を追加した後に検討する。

### 受け入れ条件

1. 損傷や喪失が実際の機能・所在・材料量に効き、履歴は残る。図面を読むだけでは現物が復元されない。
2. 1回の事故、派生被害、修理消耗をまとめて上限を守り、最低限の回復経路と資源を維持する。
3. 保護品・唯一の生活基盤・来歴不明の旧物件を喪失候補から除き、復旧中の次の事故を抑制する。
4. 落ちた物を棚と地面に二重に残さず、失った物の予約を解除し、支持と機能を同時に再評価する。
5. 課金なしの規則でも回収/休息へ進める。未観測の原因や回収場所がAIに漏れない。
6. 再送・再接続・再起動・再生で抽選や被害を重複させない。視聴者が増えても被害率は変わらない。
7. 荒天が長引いても連続して破損させず、上限超過なら新しい被害を確定しない。
8. 7日/28日の観察で、修理ばかりにならず、休息・会話・新規制作に戻れているかを確認する。

確認したい体験は「気にかけたくなる」「その子らしい立て直し方が見える」「思い出として残る」。苦境の回数・悲しむ台詞・視聴時間を増やすことを成功指標にはしない。
