## Blender資産と現在の描画の適合

- `.blend`と再生成用Pythonを`tools/lab/casuarina-art`に保存。オリジナルGLBを`public/lab/casuarina-art`に保存。
- 現行Three.js 0.186.1にはGLTFLoaderが同梱済み。ただし本体でのGLB読み込み経路はまだない。
- `COLOR_0`→`color`→`aTint`、カスタム`_SWAY`→`_sway`→`aSway`としてステージで読み込みを確認。Y-up、根元原点、約1単位の高さへ正規化。
- 風の変位式は`shore.ts`と同じ。Blenderで作る葉の束には連続した風の重みを持たせる。既存の配置行列を使うことは可能だが、本体への接続は未実施。
- GLBのPBR材質や多数の部品をそのまま場面に追加する方法は、現在の共通材質・照明・インスタンス描画とは異なる。1 geometryに統合し、既存材質へ必要な属性を渡す案が小さい。
- 本体に直接ロードする場合は非同期読み込みとThree.jsオブジェクト生成の乱数消費を別途検証する必要がある。初回はBlender/GLBから頂点データへ事前変換し、既存のBufferGeometry生成箇所へ渡す案もある。

Blenderは輪郭、枝の間、葉の塊を見ながら直せる点で今回の造形に向く。コード生成は軽い変更と再現性に強い。どちらも細い輪郭・細かい透過模様を大量に入れればちらつくため、Blenderを使うだけで解決するとは判断しない。

## 小さな移動比較（本体のちらつき検証とは別）

1280×720、SwiftShader、風を停止。4m先の1/4画素に相当する1.122mmずつカメラxを8フレーム移動し、注視点はその20%だけ追従する。輝度2階差分の最大値が0.12／0.25を超えた画素の割合。近遠各1回の限定診断で、長時間の飛行・風を含むちらつき全般の合格判定ではない。
