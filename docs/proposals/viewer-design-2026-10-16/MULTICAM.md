# 中継の仕組み：ドロンの隊（複数のカメラと切り替え）（2026-10-31）

ライブのカメラワークを、土台から考え直す案。オーナーと話して決めた方向（10/31）に、視聴者設計班が骨組みと決まりを書いた。作り方は本体と相談し、決まったら ADR にする（土台の組み替えなので）。

> **2026-10-31 オーナーと決めた方向（D35）**
> - カメラは**いつも何台も動かしておき、見どころのカメラへ中継を切り替える**。住人ひとりに1台、自然を巡る1台、住人が作ったもの（小屋・畑など）を見張る定点が1〜3台。
> - 見る人には、ふだんは**1画面だけ**を見せる。小窓や、メンバー向けの「マルチビュー」は、いずれ考える。
> - 定点で見張るもの：**小屋（家）・畑・浜の筏・野焼きの場・灯り（夜）**。

## 0. いまの仕組みと、弱いところ

- いまは**カメラが1台**。監督（`src/live/director.ts`、PROGRAM.md §4）が、0.5秒ごとに「誰を映すか」を決め、付き添いのカメラが斜め後ろ・少し上（5.5 m）から追う。撮り方は1種類。
- 弱いところ：
  1. 住人を替えるたびに、島の上を長く飛ぶ（間延び、酔いやすい）。
  2. 結果が出た瞬間も、歩いているところと同じ画になる。
  3. 画がいつも同じ距離・角度（VIEWER.md §1 の③「画が変わらない」）。
  4. 作ったものが増えていく様子を、同じ構図で見せる手段がない。

## 1. ドロンの隊

画面に出す1台だけを描き、ほかのカメラは「位置と構図」をいつも持っておく（**仮想のカメラ**）。描く負担は、いまとほとんど変わらない。

| 番号 | 役目 | 動き方 | 選ばれるとき |
|---|---|---|---|
| **01〜04** | 住人ひとりに1台（ドット・ラッコ・カメマル・ランタン） | いつも付き添う。動きに合わせて、カメラの中で撮り方を変える（A 基本・C 手元・F 正面側・B 迎える。CAMERA.md、D27） | その住人に、順位1〜3のことが起きているとき |
| **05** | 海と自然 | いまの海の巡航カメラ（`src/director.ts`：マンタ・群れ・ウミガメなどを探して撮る）を、ライブにもそのまま使う | 海の見せ場（PROGRAM.md §4 の順位4）、住人がみな静かなとき、夜 |
| **06〜08** | 定点：小屋（家）・畑・浜の筏・野焼きの場・灯り（夜） | 置いたまま、ごくゆっくり首を振る。**いつも同じ構図**なので、日ごとの変化が見える | そこで何か起きたとき（部材が付いた、野焼きの火、灯りがともった、集まり）。場面の始めに場所を見せる引きの画 |
| **空** | 島を高く広く | 島の上をゆっくり回る | 離れた場所へ切り替えるときのつなぎ、章の札、夜明け・夕日 |

- 定点は、**そのとき世界にあるもの**から、多くて3台。小屋ができる前は作業場、畑ができたら畑、筏が組まれたら浜、野焼きの場ができたらそこ、灯りがともったら夜の灯り。置き場所は、世界の物の位置から本体が決める（見る人のために物を動かさない）。
- 画面左下の帯の `01 DORON` の番号を、このカメラの番号にする（いまの帯にすでに番号がある。「撮影役のドローン『ドロン』たち」として、世界の見立てとも合う）。

## 2. 選び方（監督）

- 0.5秒ごとに、各カメラの**点**を出す。
  - 01〜04：いまの順位のまま（PROGRAM.md §4。1 決めた瞬間・結果・初めて、2 協力・会話、3 進んでいる仕事、6 休む）。
  - 05：海の見せ場の強さ（跳ねる・群れ ＞ 泳ぐ ＞ 海の景色）。
  - 06〜08：その場で起きていること（物が増えた・火・灯り・集まり）。何も起きていなければ低い。
  - 空：切り替えのつなぎと、定時の見どころ（夜明け・夕日）。
- **画面に出すのは、いちばん点の高いカメラ**。ただし次の決まりに従う。
  - 順位1は何にでも割り込む。ただし台詞の途中なら、最大10秒待つ（いまと同じ）。
  - 1つの画は**20〜40秒**を目安にする。切り替えは出来事が起きたときに行い、時間で切ることは基本的にしない。
  - 休んでいる住人は、ほかに何か起きていれば12秒で離れる（いまと同じ）。
  - 何も起きていないときは、住人・海・定点を**60〜90秒ずつ**ゆっくり巡る（BGM として流せる落ち着き）。
  - **被写体が隠れているカメラは選ばない**。各カメラは、自分の被写体の頭・体の中ほど・足もとが見えているかを、いつも測っておく（CAMERA.md「隠れない位置だけ」）。
- 夜は、04（ランタン）と05（海）と定点の灯りを主にする（NIGHT.md、D24 の夜の構成）。

## 3. 切り替え方

| 場合 | 切り替え方 |
|---|---|
| 同じ場所の中（例：作業場で、ドットのカメラから定点へ） | **すぐ切り替える**（カット） |
| 離れた場所へ（例：作業場から、沖のラッコへ） | **空の画を3〜5秒はさむ**。空のカメラが使えないときは、0.6秒のフェード |
| 台詞の途中 | 切らない（最大10秒待つ） |
| 吹き出しが出ているとき | 話し手の頭が入っているカメラだけを選ぶ（BUBBLE.md） |

- 切り替えたら、帯（左下）を新しい被写体に合わせる。
  - 01〜04：いまと同じく、住人の名前と状態。
  - 05・定点・空：カメラの番号と場所の名前（例：`06 DORON　作業場`）、その場で起きていること（世界の事実だけ）。言い方の詳しい形は、作る段階で決める。

## 4. 見る人に見せるもの

- ふだんは**1画面**（いまと同じ）。カメラが何台あるかは見せない。番号で分かる人には分かる。
- いずれ：
  - 夜の小窓（D24）：海（05）を大きく、ランタン（04）を小窓に。2台めを小さく描く仕組みは、アプリにもうある（HUNT の小窓）。
  - メンバー向けの「マルチビュー」：好きなカメラを選んで見る（`../viewer-design-2026-10-16/README.md` のメンバーシップと合わせて）。
- 画：`screens/multicam-wall.jpg`（8台を並べたモニター壁と、画面に出す1台。ビルドしたアプリで撮った画）。

## 5. 切り抜きと記録

- 定点は**毎日の早回し**（タイムラプス）を作れる。家が一本ずつ組み上がる、畑が育つ、灯りが毎晩ともる。切り抜き（CLIPS.md）とダイジェストの強い材料になる。
- 記録（`?rehearsal` の cam 行）に、カメラの番号・被写体・点・選んだ理由を残す。`rehearsal-read.mjs` で、カメラごとの時間、1時間あたりの切り替えの数、1つの画の平均の長さを出す。
- 目安：1つの画の平均は昼20〜40秒、夜60秒以上。切り替えは1分に3回まで。

## 6. 作り（本体に相談したいこと）

- 監督が選ぶものを、「住人」から「カメラ」にする。いまの順位づけは、そのまま 01〜04 の点になる。
- 描くのは画面に出す1台だけ。ほかのカメラは、位置・向き・隠れているかを安く更新する（地形と、通れない物の登録 `src/robots/solids.ts` で、視線をさえぎる物を測る）。
- 05 は、いまの海の巡航カメラを、ライブのカメラの1台として動かせるか。
- 定点の置き場所：小屋・畑・筏・野焼きの場・灯りの世界の位置（`worksiteSpots` などから）。
- 費用：仮想カメラ8台ぶんの更新と、隠れているかの測りを0.5秒ごとに行うことと、小窓を描くこと。

## 7. 段階

| 段階 | 入れるもの | 効き目（見立て） |
|---|---|---|
| 1 | 01〜04 の住人のカメラをいつも置いておき、**すぐ切り替える**。離れた場所へは空の画をはさむ | 飛ぶ移動がなくなる。切り替えが中継らしくなる |
| 2 | 定点（作業場・小屋、浜の筏、野焼きの場）と毎日の早回し | 作ったものが増えていくのが見える。切り抜きの材料 |
| 3 | 05 海（順位4）、夜の構成（海を大きく、ランタンを小窓） | 夜と静かな時間の画が豊かになる |
| 4 | 01〜04 の中で撮り方を混ぜる（D27）、植物を1本ごと半透明に | 画の距離・角度の変化 |

- 試し回しとの合わせ方（案）：段階1を5回目（11/9）に入れる。これまで5回目に予定していた「撮り方の混ぜ方」は、段階4に回す。段階2は6回目（11/12）に間に合えば入れる。本体と決める。
- 毎回、強い出来事のある分の割合、結果が画面に出た割合、初見60秒テスト（PROGRAM.md §7-2）で、効き目を測る。
