# 実機のリハーサルで、視聴者として記録すること（2026-10-23）

科学班からの依頼（2026-10-23、オーナー同意済み）への答え。実機のリハーサルは、家の PC・本物の LLM で24〜48時間、1〜2週間後に1回行う。

- **この文書が決めること**：視聴者として何を見て、どう感じたかを記録する項目と、記録のしかた。
- **照らし合わせ**：実機の上の記録は、**アプリが書き出すファイル**から取る（科学班が本体に頼んだ。2026-10-23 の科学班の返事）。リハーサルのあと、そのファイルと視聴者の記録を時刻で突き合わせて、科学班が照らし合わせる（§4）。保存の大きさは科学班が見る。
- **`TEST_REVIEW.md` の A（画面レビューの合否）との違い**：A は「決まりどおりに出ているか」を見る。ここは「気づけたか・どう感じたか」を残す。A の項目は、リハーサルでは見られる分だけ見ればよい。
- この担当は、記録を受け取ってまとめ、直すことの一覧を作る（§5）。

## 3. 記録する項目

各回の初めに、**見た経路・端末・遅れ**を書く。あとは、気づいたことを**起きた時刻**とあわせて1行ずつ書く。評価は3段階（**◎ よい／○ ふつう／△ 気になる**）と、ひとことの理由でよい。

### 3-1. 入った瞬間（W1、抜き打ちの3分ごと）

| 項目 | 記録 |
|---|---|
| I1 何の配信か分かったか | 分かった／なんとなく／分からない。何で分かったか（左上の名前・右上の「住人はAIです」・画そのもの） |
| I2 誰が何をしているか分かったか | 画面の住人の名前と、していることを自分の言葉で。あとで同じ時刻のログと比べる |
| I3 引き込まれたか（美しさ） | ◎○△。D22 の「パッと見たときにその世界に引き込まれるか」 |
| I4 続けて見たいか | ◎○△。やめたくなった理由があれば |

### 3-2. 住人の出来事に気づけたか（全部の回）

- **気づいた出来事**を時刻つきで書く。例：「ラッコがドットに流木を渡した」「ランタンが初めて灯りをともした（節目の札が出た）」「縄の段階が進んだ」。
- 見ていた間に**実際に起きた出来事**は、あとで科学班・本体のログ（出来事のログ・日記）から拾い、気づいた分と比べる（§4）。
- 気づけなかった出来事には、あとで理由を付ける。たとえば：
  - カメラが別の住人を映していた
  - 画面には映ったが、変化が小さくて分からなかった
  - 状態の1行が変わらなかった
  - 字幕が速すぎた

### 3-3. 待ち時間・退屈（全部の回）

- **画面で何も変わらないように見えた時間**を、始まりと終わりの時刻で書く。目安は3分以上。
- そのときの感じを分ける：
  - **落ち着く**（静かでよい）
  - **どちらでもない**
  - **退屈**（ほかへ行きたくなった）
- 「同じ作業が続いて飽きた」ときは、作業の名前を書く（例：殻を打つ）。巡回の決まり（README §3-1 の2周目・3周目）を直すのに使う。
- 住人が**止まって見えた**ときも書く。たとえば「考えている」が長い、同じ所を行ったり来たりする、「回り道を探している」が続く。本物の LLM の待ちや失敗が、画面でどう見えるかを照らし合わせる（§4）。

### 3-4. 潮（潮が入っていれば。主に W3・W4）

| 項目 | 記録 |
|---|---|
| P1 いま潮が引いているか満ちているか、画面だけで分かったか | 分かった／たぶん／分からない。何で分かったか（礁・波打ち際・桟橋の柱・住人の足もと） |
| P2 干潮で礁が水から出ているのが分かったか | 分かった／たぶん／分からない。◎○△（美しさ） |
| P3 20分のあいだに、水際の線が動いたのに気づいたか | 気づいた／気づかない。気づいた時刻 |
| P4 満潮の浜で、水が作業場や小屋に近づいたのが分かったか | 分かった／分からない |
| P5 住人が潮に合わせて動いたように見えたか | 例：礁へ出た・満ちる前に戻った・潮だまりの殻を見に行った。見えたことだけを書く |
| P6 潮でおかしく見えた所 | 下の「違和感」と同じ書き方。カメラが水面をまたいで半分水中になる、潮だまりの水面が海と一緒に動く、物が水に浮く・沈む、など |

### 3-5. 止まり・カクつき・音（全部の回）

- 絵が止まった・カクついたと気づいたら、**その瞬間の手元の時計を秒まで**と、およその長さを書く。
- あわせて書くこと：
  - 音も止まったか
  - YouTube の読み込みの輪が出たか（配信の問題か、描画の問題かを分ける）
  - 気になったか（◎ 気にならない／○ 少し／△ 気になる）
- 科学班から：遠くへの道探しで、1日に数回、1フレームだけ 0.5〜1 秒止まることがある（12月のあとに本体が直す予定）。これに**視聴者が気づくか、気になるか**が分かれば、直す順番を決める材料になる。
- 音：音量の急な段差、音割れ、長い無音。

### 3-6. 違和感（全部の回）

見て「おかしい」と思ったことを、時刻と一緒に書く。次のようなものを含む：

- 住人：宙に浮く・物をすり抜ける・同じ台詞のくり返し・状態の1行と画が合わない
- 生き物：急に現れる・その場で消える（「無から出ない」の決まり）
- カメラ：ウミガメなど驚かせる距離のある生き物に近づきすぎて、逃げさせる（#94 の決まり）

### 3-7. 一日の終わり（1日に1回、ログを見る前に）

- **4人それぞれの今日を、見ないで1行ずつ**書く。例：「ドットは小屋の部材をつけていた。朝ラッコに会えなかった」。あとで日記・ログと比べて、画面が本当の暮らしを伝えたかを見る。
- いちばん心に残った場面を1つと、その時刻。
- また見たいか（◎○△）と、その理由をひとこと。

### 3-8. 文字（気づいたときだけ）

- 読めなかった文字、邪魔に感じた文字を書く（D22：控えめに。世界観が先）。
- 合否は `TEST_REVIEW.md` の A-1・A-2 で見る。

## 4. 記録の形と、科学班のログとの照らし合わせ

**記録の形**：1行に1つ。スマホのメモや表計算に、次の列で書く。

```
時刻(日本時間 hh:mm:ss), 回(W1〜W7/抜き打ち), 端末, 画面(DORON番号と住人), 種類, 内容, 評価(◎○△), ひとこと
```

- 種類は次のどれか：入った瞬間／出来事／退屈／止まって見えた／潮／止まり／音／違和感／文字／一日の終わり
- 各回の最初の行には、見た経路と遅れを書く。例：`10:24:31, W3, スマホ横, -, 遅れ, YouTube 限定公開, , 隅の時計 10:24:02 を手元 10:24:31 に見た（遅れ29秒）`

**照らし合わせ**：アプリが書き出すファイル（`?rehearsal`、PR #105）を、リハーサルのあと科学班が受け取り、視聴者の記録と照らし合わせる。
- ファイルは1行に1つの JSON。どの行にも `jst`（日本時間、秒まで。フレームはミリ秒まで）、`isl`（画面の島の時計）、`world`（世界の時計）が付く。
- 行の種類：`sec`（毎秒のフレーム）、`slow`（250 ms を超えたフレームと処理の内訳）、`event`（島の出来事・タブ・エラー）、`ai`（頭の呼び出し。中身は記録しない）、`status`（状態の文の変化）、`sea`（5分ごとの海面）。
- 書き出しは Alt+Shift+R。**配信を止めてから**行う（ダウンロードの表示が配信に映らないように。PR #105 にコメント済み）。

| 視聴者の記録 | アプリの記録（照らし合わせは科学班） | 分かること |
|---|---|---|
| 止まり・カクつき（時刻・長さ） | 毎秒のフレーム時間（中央値・95%・最大）、250 ms を超えたフレームの一覧と、その時にしていた処理（道探しなど） | 何 ms から気づかれるか。気づかれなかった止まり。配信側の止まりとの区別 |
| 気づいた出来事 | 出来事のログ（節目、頼む・渡す・教える、工程の段階、航海）と AI の節目 | 気づけた割合と、気づけなかった理由 |
| 退屈・止まって見えた | 状態の文が変わった時刻、AI の呼び出しの時刻・応答時間・失敗、習慣に戻った時刻 | 退屈の原因が「世界が静か」か「映していない」か「AI の待ち」か |
| 潮 | 5分ごとの海面の高さ、住人の位置と行動 | 何 cm の変化から気づけるか。住人と潮の動きが画で伝わるか |
| 一日の終わりの「4人の今日」 | 日記と出来事のログ | 画面が暮らしを正しく伝えたか |
| （保存の大きさ） | 科学班が見る | 視聴者の側では見ない |

## 5. まとめ（リハーサルのあと、この担当）

科学班の照らし合わせを受け取ってから数日のうちに、次をまとめる。

- 気づけた出来事の割合と、気づけなかった理由の内訳
- 退屈に感じた時間の地図（時刻ごと、原因つき）
- 止まりに気づかれる長さの目安と、12月までに直すべきかの意見
- 潮の分かりやすさ（P1〜P6）
- 直すことの一覧と持ち主（本体・自然班・この担当）。持ち主の分け方は、2026-10-15 の担当の境界と、科学班の全班共通の決まりに従う

## 6. 決まったこと（2026-10-23）

- **日取り**：オーナーは「11/6 か 11/7 の夕方を含める」と決めたが、潮が間に合わないので（本体の答え）、潮の理由はなくなった。リハーサルの日はオーナーの都合で決めてよい。潮は **11/23** の短い回で見る（§2、オーナー決定）。
- **YouTube の限定公開で配信する**（オーナー）。準備はオーナーの作業（§7）。開く URL は `?live&rehearsal`（本体）。
  - 試験配信で撮る予定だった安全な範囲の撮影（README §13-1）も、同じ日に行う。
- **初めての目**：島を知らない人1人に、できる範囲で見てもらう（オーナーが頼む）。
  - **前もって島の説明をしない**（初めての目でなくなるため）。伝えるのは「ライブ配信なので、見て感じたことを」だけ。
  - 頼むのは §3-1 の4つ（何の配信か分かったか・誰が何をしているか・引き込まれたか・続けて見たいか）と、気づいたことのひとことだけ。評価の記号や列の形は求めない。オーナーが聞き取って、記録の形に書き写す。
  - 抜き打ちの3分は、できる範囲で1日1〜2回でもよい。
- **隅の時計**：PR #105（5e032a1）に入った。`?rehearsal` のときだけ、右下の余白の内側（右 5%・下 8%）に `JST 20:01:41` の形（IBM Plex Mono、1080p で 22px、ライブ画面と同じ薄い白 ink3。867c9b0）。`?live` だけの公開配信には出ない。
- **記録の書き出し**：リハーサルのあと、**配信を止めてから** Alt+Shift+R で書き出し、科学班に渡す（本体）。

## 7. 配信の準備（オーナーの作業。配信 PC と YouTube Studio）

本体のコードの外の作業なので、オーナーが行う。数字は README §13 と `TEST_REVIEW.md` S1b で決めたもの。

**YouTube Studio**（ライブ配信を開始 → ストリーム）
- 公開の範囲：**限定公開**。「子ども向けではない」。
- ストリームキー：新しく作る（使い回せるキー）。12月の本番でも同じキーを使える。
- **自動開始・自動停止は、どちらもオフ**（配信 PC がつなぎ直したときに、配信が勝手に終わらないように）。
- 遅延：**通常の遅延**。
- 12時間を超える配信は、YouTube にアーカイブが残らない。後から見る分は、配信 PC で録画する（下）。

**配信ソフト（OBS など）**
- 取り込み：ブラウザの画面を 1920×1080 で全画面にして取り込む。マウスの矢印は映さない。開く URL は `?live&rehearsal`。
- 映像：1920×1080、30 fps、H.264、**14 Mbps 前後**、キーフレームの間隔は 2 秒。
- 音声：AAC、ステレオ、44.1 kHz、128 kbps。
- 録画：
  - 録画の品質は「**配信と同じ**」にする。別の設定で録ると、PC の負担が増えて、フレームの記録（リハーサルで測りたいもの）が変わってしまう。
  - 形式は mkv（途中で落ちても、そこまでが残る）。
  - 大きさの目安：14 Mbps で1時間あたり約 6 GB。24時間で約 150 GB。全部は録らず、**夜寝る前に始めて朝止める**（W7 用。6〜8時間で約 40〜50 GB）でよい。
- 始める前に、ブラウザで `seaglassRehearsal.clear()`（本体の記録を空にする）。
- **終わりの手順**：① YouTube の配信を止める → ② ブラウザで Alt+Shift+R（記録の書き出し）→ ③ 書き出したファイル（`rehearsal-….ndjson`）を科学班に渡す。配信中に書き出すと、ブラウザのダウンロードの表示が配信に映る。

**当日の最初に確かめること**
- 画面の右下に `JST hh:mm:ss` が出ている（`?rehearsal` が効いている）。
- スマホで限定公開の URL を開き、遅れ（隅の時計と手元の時計の差）を一度読む（§1）。
