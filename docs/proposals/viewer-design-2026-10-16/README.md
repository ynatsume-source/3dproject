# ライブ配信を中心にした視聴体験の設計（2026-10-16）

視聴者と発信の設計担当より。10/11 の提案（`../viewer-design-2026-10-11/`）を、オーナーとのブレスト（2026-10-16）を受けて**ライブ配信を中心にした形に書き直した**もの。

- これは**設計の方向**。オーナーが採用した項目は下の「決まったこと」に書く。実装・配信開始・費用の発生・公開の変更は、それぞれ別に承認を受けてから。
- 住人の言葉・判断・科学の中身は変えない。住人の行動・記憶・中断と再開は main、物の形と色は自然班、科学の中身は科学班の担当（2026-10-15 の担当の境界）。
- 未完成の基盤（共有の世界サーバー G2、配信用の描画、ログの記録）は、まだ**ない**ものとして書く。

## 3. ライブ配信の設計

### 3-1. 視点と巡回

- **視点は5つ**：付き添いドロン 01 ドット・02 ランタン・03 カメマル・04 ラッコ、巡回ドロン 13（海と浜）。**実装済みのカメラはこの5つだけ**。上空の 14 と定点の 05〜12 は未実装で、できたら巡回に加える。
- **巡回の規則（案）**

| 状況 | 動き |
|---|---|
| ふだん | 起きていて動いている住人を順に。1視点に数分（目安2〜5分、試験で決める） |
| 節目が起きた | その住人の付き添い（01〜04）か 13 へ寄せる。節目の札を出す |
| 同じ動作の繰り返し（例：殻を打つ） | 数回見せたら次の視点へ |
| 朝の集まり・焚き火の会 | 会の間は会の場所に留まる（13 か、話している住人の付き添い） |
| 夜 | ランタン（02）中心。補う絵：眠っている3人を順に、13 で夜の浜と星空 |
| 視点の投票（§6） | 投票の結果は「次に寄る視点」の候補として使う。世界には影響しない |

- 巡回は表示側の都合で住人を動かさない。住人が退屈な行動に縛られないことを優先する。
- **夜の確認事項（main へ）**：ランタンの夜に見ていられる行動（灯りの番・星を見る・探索など）が十分あるか。灯りとウミガメの利害（ロードマップ段階4）は夜の見どころ候補。

### 3-2. 映像に焼き込む表示（HUD）

YouTube の映像は押せず、端末ごとに並べ替えもできない。横1920×1080の映像を、スマホの幅390pxに縮めても読めるようにする。

| 出すもの | 出さないもの |
|---|---|
| 視点の名前（住人の名前＋ドロン番号） | 操作ボタン、常時の詳細 |
| 状態の文1行（今と同じく実際の状態から） | 残り時間、進捗％、Next |
| 島の時刻と島暦の日付（遅延があるので「今」とは書かない） | 住人の内部の数値（報酬・信頼など）、AI の入出力 |
| 節目の札（起きたときだけ数秒） | 科学の隠れた値（強さ・キメ値など） |
| 今日の予定（朝の集まりで本人が言ったこと。§6） | |
| 「住人はAIです」の常時表記（小さく） | |

- 文字の目安：1080p で本文60px以上、1つの表示は2行まで。
- YouTube の操作バーや題名と重ならない位置に置く（**安全な範囲は要確認**）。
- 字幕：会話はルマウ語の吹き出しに日本語訳（いまの仕組みのまま）。

### 3-3. チャット

- 開く。住人には届かない（D4）。チャットの文は世界にも住人の AI にも渡さない。
- モデレーション（荒らし・個人情報）の方針と担当を決める必要がある。
- 見る人ができること：視点の投票（§6）、感想。できないこと：住人に話しかける、世界を変える。

### 3-4. 配信の基盤（main・本体の担当。ここでは要件だけ）

- 島は **1つだけ**。共有の世界サーバー（G2）が持ち、配信用の描画はそれを**読むだけ**。
- 描画が落ちても世界の時間は止めない。描画はすぐに復帰する。世界は保存と復旧ができる。
- 配信用の描画では、観賞用の早回し・季節・プリセットを使えない設定にする。
- 常時描画には GPU のある機械が要る（ソフトウェア描画では遅すぎることを 10/11 に確認）。
- 12時間を超える配信は YouTube にアーカイブされない（YouTube ヘルプ）ので、記録は §4 のログで持つ。

## 4. 島のログ（記録と再現）

ライブを録画せず、**ログから島を再現する**（D5）。ダイジェスト・ショート・島だよりの写真・メンバーシップの再現視聴は、すべてこのログから作る。プロジェクトの原則「世界の事実と見た目を分ける」にそのまま沿う。

### 水準A（採用）：島の再現

| 記録するもの（案） | 粒度（案） |
|---|---|
| 住人の位置・向き・姿勢・持ち物・状態の文 | 数秒ごと（描画が間を補う） |
| 出来事（節目・ふだん）、会話（ルマウ語と訳）、日記 | 起きたとき |
| 工程の開始・状態の変化・結果 | 起きたとき |
| 天気（再生している記録の値）、島の時刻 | 定期 |
| 作った物・置いた物の出現・変化・消失 | 起きたとき |
| 写真を撮った瞬間（住人の写真）と、節目の瞬間のドロンの位置 | 起きたとき |

- 魚や鳥などの生態系は記録しない。描き直すたびに変わるので、再現の画面には「再現」と書く。
- 描画の版が変わると見た目も変わる。事実（ログ）は変わらない。
- コマ単位の完全な再現（水準B：乱数と AI の返答まですべて）はしない。

### main・本体に決めてほしいこと

- ログの**形式と粒度**を G2 と一緒に早めに決める（後から変えると過去のログが使いにくくなる）。
- 保存期間・置き場所・容量の見積もり。
- ログに**入れないもの**：API キー、AI への入力の全文と生の返答、チャット。

## 5. 毎日のダイジェストとショート

### 5-1. 毎日のダイジェスト（15〜30分、自動公開）

ログから場面を選び、カメラを選んで**描き直す**。ライブの録画は使わない。

| 章 | 中身 |
|---|---|
| 1. 朝の集まり | その日の予定、天気の知らせ（ランタンの気圧計・カメマルのうねり） |
| 2. 日中のそれぞれ | 住人ごとの取り組み。工程の前→今→次は世界の記録から |
| 3. 夜の焚き火の会 | 報告と情報の共有 |
| 4. 夜のランタン | 灯り・探索 |
| 5. 今日の節目 | その日の節目のまとめ（なければ省く） |

- 章の時刻は説明欄に書く（YouTube の目次になる）。説明欄には島だよりのその日の記事への案内も書く。
- 字幕は会話と出来事の文だけ。住人の言葉は足さない・変えない。数字は世界が測ったものだけ。
- **自動公開の代わりの自動検査（案）**：出来事の文が世界の記録と一致する／住人の内部の数値・AI の入出力・チャットが映っていない／試作の工程が出ていない／動画の長さが範囲内／描画の失敗（真っ白・真っ黒）がない。どれかに引っかかったら公開せずに止め、運営に知らせる。
- 公開の時刻は、島の一日（夜のランタンまで）が終わったあと。島だよりの毎日の実行と時刻をそろえるかは要相談。
- 描き直しは時間がかかる。毎日15〜30分の動画を GPU で描くのにかかる時間と費用の見積もりが要る。

### 5-2. ショート（30〜60秒）

- その日の節目を1つ、縦9:16で。材料はダイジェストと同じログ。
- 節目のない日は出さない（無理に作らない）。

## 7. 島だより（D3）

- 役割：**住人の語り**の場。ライブ・ダイジェスト（ドロンの観察）とは別の、本人の言葉と写真・絵。
- いまの仕組み（毎日の実行 → 記事の PR → マージで公開）は続ける。島を非公開にしても、島だよりは公開のまま。
- 10/11 の時点で本番の記事は0本だった。**ライブ開始の前に、まず続けて出せる状態にする**（原因の確認は運営と本体）。
- ダイジェストの説明欄・「いまの島」カードから、その日の記事へ案内する。
- 住人の写真と記事は、ライブの島（G2）のログから描き・書く形に移す。ライブの島は新しく始め、いまの島だよりの島は試験用に残す（D8）。

### 10-4. 自宅で描画する（D9）ための確認

- 描画が止まっても島の時間は進み続ける作り（世界は VPS）。配信が途切れても世界の記録は失われない。
- 上り回線：1080p の配信で安定して10Mbps程度出るか。
- 停電・回線断・再起動のあとに、配信が自動で戻るか。PC を別の用途に使う時間をどうするか。
- ダイジェストの描き直しも同じ PC で行う場合、ライブを描きながら並行で描けるか（GPU の余裕）。

## 11. 見られ方の指標（ライブ前提に更新）

10/11 の指標は Web 前提だった。ライブ中心に置き換える。

| 目的 | 指標 | 出どころ |

| 忙しい人に届く | ダイジェストの視聴数・平均視聴時間・章ごとの離脱 | YouTube Analytics |
| 読み物 | 島だより・科学ノートの閲覧、ダイジェストから島だよりへの移動 | Web の計測 |

開始の前に、取れるものは基準値を取っておく。
