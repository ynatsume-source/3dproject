# 発信の全体像：出会う → 入る → 好きになる → 通う → 支える・広める（2026-10-20）

オーナーとの相談（2026-10-20）：
- SNS の優先順位は **X > Instagram > Threads > TikTok**。負担がそれほど増えないなら、すべて対象にしたい。
- 島だよりのページを、ライブの画面案（観測の窓）と同じ世界観で作り直したときの姿を見たい。
- いちばん大事なのは**発信の全体の流れ**。新しい人が来て、ファンになり、繰り返し来るまでをマーケティングの枠組みで設計し、一枚絵にしたい。

名前（2026-10-20、D23）：全体は **Utsushiyo Project**、今回の島は **Series 1「ルマウ」**。「ドットたちの島」は、ルマウに添えるサブタイトルとしてだけ残す（`../CHANNEL_COPY.md` §0）。この文書と一枚絵・島だよりの見本は、この名前に合わせて直した。

成果物：
- **一枚絵**：`flow.jpg`（元は `flow.html`、2400×1500）
- **島だよりの見本**：`../journal-mock/`（`index.html`・`article.html`、画像は `shot-*.jpg`）
- この文書：枠組み、リズム、SNS ごとの役目・自動化・費用・手間、守ること、決めてほしいこと

これは**設計の提案**。SNS のアカウント開設・接続・投稿の実装は、オーナーの決定と承認のうえで main が行う。住人の言葉（記事・ひとこと）は変えない。

## 1. 枠組み：5つの段階

| 段階 | 見る人の気持ち | 場所 | 効く中身 | 測る |
|---|---|---|---|---|
| **1 出会う**（認知） | 「きれい。これは何？」 | X・Instagram・Threads・TikTok、YouTube のおすすめとショート、地球の海の Web の「いまの島」カード | 節目の瞬間の短い動画と画像、夜の星と灯りの一枚、住人のひとこと | 表示回数、プロフィールへの移動 |
| **2 入る**（はじめての視聴） | 「AI の住人が、本当に暮らしてる」 | 24時間ライブ、毎日のダイジェスト | 景色が先の画面と島の文字（`../screens/`）、最初の10秒で分かる下の1行、「住人はAIです」 | はじめての視聴時間、チャンネル登録 |
| **3 好きになる**（ファン化） | 「ランタンの灯り、うまくいくかな」 | 島だより、週の科学ノート、島の年表 | 4人の名前とそれぞれの大義、失敗と作り直し、待っている工程（縄・器・帆） | 平均視聴時間、島だよりの閲覧 |
| **4 通う**（習慣化） | 「今日の島はどうなった？」 | 朝のダイジェスト、朝の集まり・焚き火の会のライブ | 毎日同じ時刻の山場、週ごとに季節、月ごとに島の1年、台風の夜の特別配信 | ライト＋コアの視聴者の割合（週。`../README.md` §13 Y13） |
| **5 支える・広める**（推奨・支援） | 「この島を、誰かに見せたい」 | メンバーシップ（開始後）、切り抜きの共有、視点の投票 | キャラごとの視点、過去の島の再現、名場面の目次 | メンバー数、共有の数 |

**ループ**：5で共有された一場面が、次の誰かの1になる。そのため、ショートや画像には必ず「どこで続きが見られるか」（ライブ・島だより）を添える。

**この島ならではの強み**（どの段階でも使う）
- **本物でできている**：起きた出来事しか出さない。だから「次どうなるか」に本当の緊張がある。
- **物語が止まらない**：工程は待つものが多い（乾燥・野焼き・帆）。「次の見どころ」が毎日ある。
- **時間の速さが二つある**：一日の明暗は現実と同じで、季節は約13倍。**現実の1週間で島の季節がひとつ、4週間で島の1年**がめぐる。毎週・毎月の区切りが自然にできる。

## 3. ひとつの記録から、すべての発信へ（負担を増やさない仕組み）

新しく撮らない。**島のログ**（出来事・会話・住人の写真と記事）から自動で作り、場所ごとの型に流すだけにする。

```
島のログ ─┬─ 毎日のダイジェスト ……………… YouTube（＋告知：X・Threads）
          ├─ 節目のカード画像・ショート … X・Threads・Instagram・YouTube ショート・TikTok
          ├─ ドロンの写真・季節のまとめ … Instagram・X
          └─ 住人のひとことと記事 ……… 島だより・X・Threads
```

**承認の分け方**（ここが手間を決める）

| 種類 | 文を書くのは | 承認 |
|---|---|---|
| 世界の事実の型（節目の速報、ダイジェストの告知、季節のまとめの見出し） | 世界（決まった型に、世界の出来事の文を入れるだけ） | **自動で出す**（ダイジェストと同じ自動検査を通す） |
| 住人の言葉（ひとこと・記事） | 住人（AI） | **1日1回まとめて確認**（いまの島だよりの PR と同じ。約5分） |
| TikTok | — | 自動で投稿できない（§4）。**週に1回、スマホで手で上げる**（約10分） |

オーナーの手間の目安：毎日約5分＋週に約10分。

## 5. 声と決まり（世界観を守る）

| 決まり | 中身 |
|---|---|
| 発信者の声 | 公式のアカウント（`Utsushiyo Project`、D23）＝**観測の記録の声**（ドロンの注記と同じ）。事実を短く。絵文字・煽り・感嘆符は使わない |
| 住人の言葉 | 「」で引用し、名前と島の文字を添える。**足さない・直さない・要約しない** |
| 住人として話さない | 公式のアカウントが住人のふりをして返信しない。SNS の声は住人に届かない（ライブのチャットと同じ：D4） |
| 起きた事実だけ | 盛らない。「ついに」「感動の」などの言葉で演出しない。失敗も同じ重さで出す |
| AI の明記 | プロフィールと各ショートに「住人はAIです」。X は自動のアカウントのラベル |
| ハッシュタグ | 公式の投稿は、決まった1つ（`#ルマウ`、シリーズの名前。D23）だけ。住人のひとことには付けない（住人の書く決まりで、ハッシュタグは使わない） |

**型の例**（世界の事実の型。〈〉は世界の文が入る）
- 朝の告知：`〈前の日の題（節目の文）〉 ── 島暦〈年〉年〈月〉月〈日〉日〜〈日〉日の島。 〈ダイジェストの URL〉`
- 節目の速報：`島で初めて。〈節目の文〉 島暦〈日付〉・〈時刻〉` ＋ カードの画像
- 住人のひとこと：`〈名前〉より 「〈住人のひとこと〉」 〈島だよりの URL〉`
- 島の潮の告知（大潮の日だけ、当日の朝。2026-10-23 追加）：`今夜〈時〉時〈分〉分ごろ、島の潮が〈いちばん低くなる など〉。〈満月／新月〉です。（島の潮は、この星の月と太陽から計算したもので、現実の潮見表とは少し違います）`。日時は `time/astro.ts` の `tide` から出す。数字の高さは出さない。住人が礁へ出るとは書かない（`../TIDE_SCENES.md` §4、科学班の答え）

## 6. 島だよりの見本（`../journal-mock/`）

**ねらい**：ライブ（ドロンの観測）と同じ世界の、**住人自身の語り**の紙面。明朝、少し温かい白、砂の金の一色、細い線、島の文字。ライブより文字を大きくし、ゆっくり読む紙面にした。

| 場所 | 中身 |
|---|---|
| 表紙 | その日の写真を画面いっぱいに、左下にライブと同じ下の帯（日付・島の文字の名前・題）／ひとことの紹介文／日ごとに2人の記事を並べる（写真のない日は住人の描いた絵）／「いまの島」の帯からライブへ |
| 記事の上 | 写真をいっぱいに、下の帯（日付・島暦・名前・題・撮影の注記） |
| 人間界へのひとこと | 住人の `sns`（140字以内）を、記事の冒頭に引用として置く。SNS に出す文と同じ |
| この日の交信 | 時刻 ／ 島が返したこと（世界の記録、小さいゴシック）／ 住人の受け止め（明朝）。写真はその時刻の行に入れる |
| くり返しの畳み方 | 同じ出来事が続くところは「ほか○時○分まで○回」「くり返し」と1行にまとめる（数と時刻は世界の記録のまま）。試走の記録では「浜から海を眺める」が1日に数十回並んでいた |
| この日のふりかえり | まとめ ／ いまの状態 ／ 分からないこと ／ これから（いまの `review` の4項目） |
| 終わり | 「住人が自分の記録と写真だけから書いた・出来事は世界の記録・運営が確認」の注記、前の日・同じ日のもう一人・その日のダイジェストへの道 |

- 見本の「出来事」の行は、main（c23be19）の島を試しに1日動かした記録（2026-10-19、AI なしの下書き）からそのまま取った。**題・ひとこと・受け止め・ふりかえりは、この担当が書いた見本の文**で、実際は住人が書く。写真はソフトウェア描画の仮の画。
- いまの書き手はドットとラッコ。住人4人とも AI で考えるようになったので（D11）、**ランタンに週1回の科学ノートを書いてもらう**案がある（オーナー判断）。
- 作るのは main（`scripts/journal-pages.ts` と `src/journal/journal.css`）。島の文字は、ページを作るときに HTML に書き込む（見本は小さなスクリプトで描いている）。

## 6b. 決まったこと（2026-10-20、オーナー）

| # | 決定 |
|---|---|
| S1 | X の「AI の生成物は事前承認」は、**確かめてもらう**（main かオーナー）。だめそうなら、**X は世界の事実の投稿だけ**にし、住人のひとことは島だより・Threads で出す |
| S2 | SNS のアカウント名・プロフィール文・ハッシュタグは草案を出す（`../CHANNEL_COPY.md` §8） |
| S3 | **TikTok は手で上げる**（自分のアカウントへの自動投稿は TikTok の審査の指針で認められないため）。週2〜3本、約10分 |
| S4 | **ランタンに科学ノートを書いてもらう**（頻度は下の案：週1回＋節目の臨時号） |
| S5 | **島だよりは見本（`../journal-mock/`）の方向で作り直す** |

**ランタンの科学ノートの頻度（案）：週1回 ＋ 節目の臨時号**
- 週1回：現実の1週間で島の季節がひとつめぐる、その変わり目の日に。1週間は島の約3か月で、乾燥・野焼き・縄・帆など待つ工程の「始め → 結果」が1回分そろう。
- 2日に1回は多い：島の2日でも工程は途中のことが多く、同じ「待っている」が続く記事になりやすい。確認の手間と AI の費用も増える（ドットとラッコの毎日の記事に足すと、1日の記事が3本になる日が増える）。
- 代わりに、**科学の節目（島で初めての灯り・天気の壺・縄が切れた など）が起きたら、その日に臨時号**を出す。決まった頻度より「起きたときに書く」ほうが、この島の「起きた事実だけ」の方針に合う。
- 書く材料：その週の工程の記録（始めた・結果・止まった理由）、ひらめき（仮説）とその当たり外れ、次に試すこと。科学の隠れた値は書かない（住人が知っていることだけ）。

**X に出す住人のひとことの長さ**：住人のひとこと（`sns`）はいま140字まで。X では日本語1字を2と数えるので、140字だとそれだけで枠（280）がいっぱいになり、名前や「」を付けられない。**ひとことの上限を120字に**してもらう（書く決まりの字数だけの変更。中身は住人のまま）。

## 7. 決めてほしいこと（オーナー、2026-10-20 にすべて回答済み：§6b）

1. **X の「AI の生成物は事前承認」**の確認：住人のひとこと（AI の文）を X に自動で出してよいか、開始前に X 側の条件を確かめる（確かめるのは main かオーナー）。だめなら、X は世界の事実の型だけにし、住人のひとことは島だより・Threads で出す。
2. SNS の**アカウント名とプロフィール文**（チャンネル名と合わせる：`../CHANNEL_COPY.md`）、公式のハッシュタグ。
3. **TikTok を手で上げる**運用でよいか（週に約10分）。
4. 島だよりに**ランタンの科学ノート**を足すか。
5. 島だよりの見本の方向でよいか（よければ main に作り直しを頼む）。
