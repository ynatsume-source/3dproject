# ライブ配信の画面案「観測の窓」第2版（横 16:9、2026-10-17）

オーナーの指示：横画面だけでよい。YouTube のライブ配信に最適化し、世界観を大事にした洗練された画面に（2026-10-17）。
第2版でのオーナーの決定と指示（2026-10-17）：

- **書体は明朝**。**名前と会話に島の文字を出す**。**会話は下の中央の字幕**にする。**多言語に対応**させる。**左上のブランド表記は `UTSUSHIYO / ドットたちの島`** でよい。
- 文字の主張が強すぎる。**もっと控えめに**。スマホでもそこまで大きくしなくてよい。**文字の大きさを土台から考え直す**。
- 後ろを暗くしすぎると世界観を壊す。**文字がはっきり読めることより、世界観を優先**する。
- **パッと見たときに、その世界に引き込まれる美しさ**が何より大事。

この文書は `../README.md` §3-2（HUD の文言表）の**見た目の設計**。文言・出す条件・出さないもの（残り時間・隠れた値など）は §3-2・§3-6 のまま。文字の大きさの下限（状態の1行 72px など）は、この第2版で**置き換える**（§3）。

- モック：`live-screens.html`（1920×1080。場面 `#day` `#rope` `#isle` `#night` `#talk` `#milestone`、`&en` で英語）
- 画像：`screen-1-day` 昼・付き添い／`screen-2-rope` 縄づくり（`-en` 英語）／`screen-3-isle` 夕方・島をめぐる／`screen-4-night` 夜・ランタン／`screen-5-talk` 会話の字幕（`-en` 英語）／`screen-6-milestone` 節目の札（`-en` 英語）。1600×900 に縮めたもの。`*-phone.jpg` はスマホ横の全画面（幅844px）で見える大きさ

- 文言：状態の文・出来事の文・会話（日本語と英語）は `residents.ts`・`islandlang.ts` にある文をそのまま使った。**「ヤシの殻を打っている」と、会話以外の英語の文は仮**（殻と縄は未接続、状態・出来事の英語の型はまだ無い）。日付・時刻は仮。節目の場面の灯りの光は、モックのために描き足したもの

## 1. 考え方：ドロンの「観測の窓」

見る人は、住人には見えないドロンの記録画面をのぞいている。画面の文字は、ドロンが添える**ささやくような注記**で、島の主役ではない。

| 原則 | 中身 |
|---|---|
| **景色が先、文字はあと** | まず景色が目に入り、文字はそのあとで気づく強さにする。文字は四隅に小さく寄せ、画面の中央は空ける。箱・枠線・丸いボタンは使わない |
| **暗くしない** | 文字の下は基本的に何も敷かない。文字自身の薄い影（にじみ）で読ませる。景色がとても明るいときだけ、文字のまわりをごく薄く曇らせる（縁の見えない釣鐘型のぼかし）。夜は何も敷かない |
| **語り手を書体で分ける** | 世界の事実（状態・出来事・節目）と会話の訳は**明朝**。ドロンの記録（番号・DORON）は**英字の小型大文字と等幅の数字**。住人自身の言葉は**島の文字**（ルマウ）で、その下に訳 |
| **島の文字を見せる** | 名前は島の文字＋名前。会話は島の文字の行と訳の行。島に独自の言葉と文字があることが、説明なしで伝わる |
| **色は一つだけ** | 少し温かい白（不透明度 97%）。注記は同じ白を薄く（82%・66%）。強調は**砂の金**（`#e9cf98`、波打ち際＝ルマウの色）だけで、今の段階と節目に使う。住人の色は名前の横の短い線にだけ |
| **線は細く** | 縦の区切り線・下線・節目の罫線は 1px。太字は使わず、500〜600 の太さ |
| **動きは静かに** | 視点の切り替えはフェード。文字は0.6秒ほどでふわっと出て、同じように消える。点滅・跳ねる・滑り込む動きはしない |

## 3. 文字の大きさを土台から

**土台**：画面の高さ 1080 を基準に、1段およそ 1.2 倍の6段。

| 段 | 1080p | スマホ横の全画面（画面の高さ約390px、×0.36） | スマホ縦のアプリ内（高さ約220px、×0.2） | 使う所 |
|---|---|---|---|---|
| s1 | 22px | 約8px | 約4px | ドロンの番号、AI の表記、ブランドの下の行、話し手の名前、節目の見出し |
| s2 | 26px | 約9px | 約5px | 島の日付と時刻、縄づくりの段階、島をめぐるときの4人の名前 |
| s3 | 32px | 約12px | 約6px | 住人の名前、`UTSUSHIYO` |
| s4 | 40px | 約14px | 約8px | **状態の1行** |
| s5 | 46px | 約17px | 約9px | **会話の訳（字幕）** |
| s6 | 56px | 約20px | 約11px | 節目の文 |

**考え方**
- 主に見るのは **PC・テレビ（1080p そのまま）と、スマホを横にした全画面**。主な文（状態・字幕）を、スマホ横で 14〜17px（スマホの本文くらい）に置いた。字幕は読む速さが要るので一段大きい。
- 注記（番号・AI の表記・日付）は、スマホ横では 8〜9px で「あることが分かる」程度。PC・テレビでは 22〜26px で読める。ここは読ませるより、景色の邪魔をしないことを優先した。
- スマホ縦の小さい画面では、文字は読めなくてよい（景色を見る画面と割り切る）。
- 前の案（状態の1行 72px：スマホ縦でも読める大きさ）から、主な文で**約45%小さく**した。
- 英語など欧文は、同じ大きさだと小さく見えるので +4〜6px（`Cormorant Garamond`）。

## 4. 部品

**下の帯（付き添いの視点 01〜04）**：1px の縦線（白 38%）の右に、`01 DORON`（s1）→ 島の文字の名前（高さ 26px）＋ 名前（s3）＋ 住人の色の線（26×2px）→ 状態の1行（s4）。

**下の帯（島をめぐる視点 13）**：`13 DORON` → 4人（色の線・島の文字・名前、s2。眠っている住人は半分の濃さ）→ 直近の出来事の文（s4。10分以内の出来事がなければ出さない）。

**縄づくりの段階**：名前と状態の1行の間に1行（s2）。今の段階は砂の金に 1px の下線、済んだ段階は淡い青緑、まだの段階は白（82%）、省いた段階は 1px の取り消し線。残り時間や％は出さない（§3-6）。

**会話の字幕**：話している間、下の帯は退き、下の中央に字幕。上から、話し手（色の線＋名前、s1）→ 島の文字の行（高さ 30px）→ 訳（s5）。訳が20字（英語は1文）を超えるときは最初の「。」（英語は最初の文の終わり）で改行する。いまのアプリの吹き出し（頭の上）はライブでは小さすぎるので、ライブではこの字幕に置き換える。

**節目の札**：上の中央寄りに、砂の金の 1px の罫線（160px）ではさんで、見出し「島で初めて」（s1、字間を大きく）→ 出来事の文（s6、最初の「。」まで）→ 島暦の日付と時刻（s1）。約8秒でフェードで消える。

**島の時刻**：`島暦1年 6月14日  19:06`（日付は明朝、時刻は等幅）。「今」とは書かない。

## 5. 曇りの濃さと読みやすさ（世界観を優先）

文字の下の曇りは、**景色の明るさに応じて**決める（アプリが文字の場所の明るさを1秒に1回ほど測る。描画だけの処理で、世界には触れない）。

| 景色 | 曇り（黒の重ね・背後の明るさ） | 例 |
|---|---|---|
| とても明るい（白い砂浜の真昼） | 黒 34%・明るさ 74%、ぼかし 6px、縁は釣鐘型で消える | `#day` `#rope` |
| ふつう（夕方・森・海） | 黒 10%・明るさ 92%、ぼかしなし | `#isle` |
| 暗い（夜） | なし | `#night` `#talk` `#milestone` |

文字を消した画（`&notext`）で、文字の下の明るさ（明るいほうから1割の位置）と文字の白との明るさの比を測った。

| 場面 | 状態の1行 | 名前 | 番号 | 日付・時刻 | AI の表記 |
|---|---|---|---|---|---|
| 真昼の白い砂浜（`#day`） | 3.8 | 7.0 | 3.5 | 2.9 | 2.4 |
| 真昼・縄づくり（`#rope`） | 2.3 | 5.1 | 2.3 | 2.9 | 2.4 |
| 夕方（`#isle`） | 14.7 | 13.5〜14.8 | 13.5 | 6.7 | 6.6 |
| 夜（`#night` `#talk` `#milestone`） | 17.3 | 17.8 | 17.5 | 17.6 | 17.7 |

- 真昼の白い砂浜では、ふつうの目安（4.5）を下回る。文字の影で目では読めるが、「はっきり」ではない。**オーナーの方針（世界観を優先）に沿って、これ以上は暗くしていない**。第1版（比 10 前後）では、明るい場面で文字のまわりの景色がはっきり暗くなっていた。
- 夕方・夜は、何も敷かなくても十分読める。
- 試験配信で、真昼の砂浜の場面がどれくらいの割合で映るか、実際の画で読めるかを見て、曇りの最大値（34%）を調整する（`../TEST_REVIEW.md` A-1 の T2 の目安も、この方針に合わせて「目で読める」に改める）。

## 6. 多言語

**文の作り方**：島の文字（ルマウ）は全言語で共通。その下の訳や画面の文は、**言語ごとの文の型**から作る（`islandlang.ts` の決まり：意味から各言語の文を作り、島の言葉を機械的に翻訳しない）。いま英語の型があるのは会話（`SAY`）だけ。状態の文・出来事の文・画面の決まり文句（AI の表記など）の英語の型は、これから main が作る（モックの英語は仮）。

**書体**：日本語は Zen Old Mincho、英語など欧文は Cormorant Garamond（数字は揃い数字）。中国語・韓国語を足すときは、明朝に合う Noto Serif SC・KR などを候補に。どれも Google Fonts。

**YouTube での届け方**（公式の資料で確認、2026-10-17）
- ライブ配信の字幕（YouTube の字幕機能）は、**1本の配信につき1言語だけ**（「YouTube currently only supports one track of captions」）。エンコーダに埋め込むか、HTTP POST で送る。HTTP POST の場合は 30秒か60秒の配信の遅延が要る（[3068031](https://support.google.com/youtube/answer/3068031)）。ライブの自動字幕は英語の音声だけで、住人の声（ルマウ）には使えない（[6373554](https://support.google.com/youtube/answer/6373554)）。
- アップロードした動画（毎日のダイジェスト・ショート）には、**言語ごとの字幕を何本でも**付けられる。API の `captions.insert` は1回400ユニット（[2734796](https://support.google.com/youtube/answer/2734796)、[captions.insert](https://developers.google.com/youtube/v3/docs/captions/insert)）。

**おすすめの組み合わせ**

| | 画面に描く（この画面案） | YouTube の字幕 |
|---|---|---|
| ライブ | 島の文字 ＋ **日本語** | **英語を1本**（会話と節目の文を、HTTP POST で送る。配信の遅延 30〜60秒を足す） |
| 毎日のダイジェスト・ショート | 島の文字 ＋ 日本語（ライブと同じ見た目） | 英語ほか、言語ごとに何本でも（1日2言語で 800 ユニット、1日の枠 10,000 に収まる） |
| 将来、ライブで英語の画面がほしいとき | 英語版の配信をもう1本（同じ描画に、表示だけ英語を重ねる） | — |

- YouTube の字幕の見た目は YouTube が決める（この画面案のデザインにはならない）。そのため、主な言語（日本語）は画面に描き、ほかの言語は字幕に回す。
- 英語版の配信をもう1本出すと、自宅 PC のエンコードが2本ぶんになる。開始時は入れず、見る人の国の割合を見てから決める。

## 8. 作るときのメモ（main 向け）

- ライブモードの画面だけに入れる。地球の海の画面は変えない。
- 曇りは `backdrop-filter: blur() brightness()` と、縁の見えない釣鐘型の `mask-image`。濃さは文字のある場所の明るさを小さく縮めた画（例 64×36）で1秒に1回ほど測り、表（§5）の3段のあいだでなめらかに変える。
- 島の文字は `islandlang.ts` の `glyphs()`（線の太さは 1.25 に細くした）。
- 言語は配信ごとに1つ。字幕の英語は、同じ会話・出来事の英語の型から作り、HTTP POST で YouTube に送る。

## 9. 自然班への依頼（見た目）

- 灯りの光：夜の引きの画で、灯りの届く範囲が見えること（モックでは描き足した）。
- 夜の明るさ：今回撮った夜（22:30、曇り）は、島の輪郭がほとんど見えないほど暗かった。曇りで月のない夜でも、浜と森の輪郭が分かる程度の明るさがほしい。

## 10. 確かめていないこと

- 実際の GPU で描いた画の上での見え方、フェードの動き、配信の圧縮のあとで細い線や小さい文字がにじまないか（1px の線、s1 の文字）。
- YouTube のプレーヤーの表示との重なり（試験配信で撮る）。
- ライブの英語字幕を HTTP POST で送る仕組みの実際（試験配信で）。
