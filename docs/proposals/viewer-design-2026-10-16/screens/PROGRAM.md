## 0. 考え方

### 0-1. 軸は「試み」：考える → 試してみると言う → 試す → 結果

住人は 1時間に約5回、自分で目的を立て、「こうすれば、こうなるはず」と仮説を立てて、試している。結果は、確かめた・違っていた・やりとげた・うまくいかなかった、のどれか。

これは、見る人にとっての**問い（うまくいくのか？）と答え（結果）**。ゲームの実況で見る人を引きつけるのと同じ形が、この島ではもう毎時間起きている。画面に出ていないだけ。

- 1つの試みは、数分〜数十分で答えが出る。**いつ開いても、だいたい何かの試みの途中**にいる。
- 試みが積み重なって、章（小屋・家・筏…）が進む。**小さな問いの答えの先に、大きな行く末がある**。
- 違っていた（うまくいかなかった）も、隠さずに出す。違っていたから次の試みが生まれ、それが見どころになる。

### 0-2. いつ開いても、60秒で3つの問いに答えが出る

初めて開いた人は、どの時刻に来るか分からない。始まりの説明は作れない。そこで、**画面と音だけで60秒以内に次の3つに答えが出る**ようにする。

| 問い | 答えるもの | 何秒で |
|---|---|---|
| ① この住人は、いま何を試しているのか | 帯の**試み**の1行（§1） | 5秒（いつも出ている） |
| ② この世界は、どこへ向かっているのか | 左上の**章**と**道のり**（§2） | 5秒（いつも出ている） |
| ③ 次に、何が起きるのか | 試みの**結果**（数分〜数十分で出る）と、右上の**このあと**（定時の見どころ、§3） | 5秒 |

- 画面の外の語り手は、これまでどおり置かない（D29）。試みは**住人自身の言葉**、章と道のりと時刻は**世界の事実**。
- 確かめる試し（§7）：**初見60秒テスト**。くじで選んだ時刻に開いて60秒だけ見て、3つの問いに答えられたか、見続けたくなったかを記録する。

## 3. 一日の見どころを、時刻で固定する（「ルマウの一日」）

**決まり**：時刻で固定するのは、**世界がもともとその時刻に持っているもの**（集まり・眠り・空）と、**カメラだけで作れるもの**（島めぐり・夕日・潮見）だけ。見せるために住人をその時刻に動かすことはしない。

| 時刻（日本時間） | 見どころ | 中身 | どこから来るか |
|---|---|---|---|
| 日の出の20分前〜日の出 | 夜明けの浜 | 潮見の定点（S1）から明けていく海。起きてくる住人 | 空・起きる時刻（5:48） |
| **9:00〜9:30** | **朝の集まり** | ランタンが夜に見たこと、各自のきょうの試み（§6 の言い方） | 世界（`morningHours` 8:51〜9:30） |
| 12:00〜12:03 | 島めぐり | 島 13 の引きで、いまの章で作ったものを順に。きょう撮った写真 | カメラだけ |
| 日の入りの30分前〜日の入り | 夕日の浜 | 夕日と住人。潮が入ったら潮見 | 空 |
| 19:00 | きょうの島（札、15秒） | きょう起きた事実を3つまで（確かめたこと・節目・段階の進み） | 島のログ |
| **19:25〜21:05** | **焚き火の会** | 点灯、きょうの試みの結果（§1-3）、決めごと | 世界（`fireHours` 19:24〜21:06） |
| 21:30 | おやすみ | 3人が眠りにつく。ランタンの夜の始まり | 世界 |
| 22:00〜翌5:00 | 夜の海とランタン（D24） | 星・灯り・手帖・地図。ランタンの試み | 世界 |

- **朝の集まり（9:00）と焚き火の会（19:30）を番組の柱**にする。朝に試みを言い、夜に結果を言う。見る人の暮らしでも見やすい時刻。
- 台風などで集まりがない日（`storm()`）は、その時刻の見どころを出さない。
- 右上の「このあと」：`このあと　19:30 焚き火の会`（次の見どころ1つ、いつも）。10分前から `まもなく`、始まったら `いま`。夜は `あすの朝　6:12 夜明けの浜`。住人がやると言ったこと（あすの渡航など）は、ここには出さない（本当にそうなるかは世界が決める。住人の試みの行で出る）。
- **配信の題名に章を入れる**（D31）：`ルマウ ― ドットたちの島　第2章「家を建てる」 ｜ AIの住人4人が暮らす、別の星の小さな島（24時間ライブ）`。題名【A】（`../CHANNEL_COPY.md` §2）のシリーズの名前のすぐ後ろに、いまの章を足す。章が変わったら題名も替える（YouTube の API、本体）。

## 4. カメラの優先順位

本体の案の順を使う：**決めた瞬間・初めて ＞ 協力・会話 ＞ 進んでいる仕事 ＞ 海の見せ場 ＞ 振り返り ＞ 休んでいる住人（短く）**。CAMERA.md の撮り方（A〜F）は、どの順位でも同じ。

| 順 | 種類 | 世界のどの事実で知るか | 割り込み | 長さ |
|---|---|---|---|---|
| **1** | **決めた瞬間・結果・初めて** | 考え始めた（`ponder`）→ 答えが入った。試みの結果（確かめた・違っていた・やりとげた・うまくいかなかった）。節目（札）。出来事の結果（縄がもった・切れた、渡航に出た・着いた）。定時の見どころの始まり | **何にでも割り込む**。会話の1行の途中だけは、終わるまで待つ（最大10秒） | 考えている間はずっと。決めたあと・結果のあと **20秒** |
| **2** | **協力・会話** | 話している（`talk`）。頼む・断る・教える・渡す（`requests`）。同じ物に2人が手を入れている | 3〜6 に割り込む | 会話の終わりまで（最大3分）。頼みは渡すところまで |
| **3** | **進んでいる仕事** | 試みの手順を進めている（AI の目的があるもの）。R-017 の一覧で「あり」の行動のうち、世界の数が増えたもの | ふだんの切り替えで | 2〜4分。同じ動作のくり返しは README §3-1 のとおり短く |
| 4 | 海の見せ場 | 生き物の見せ場（跳ねる・群れ）。潮見。夕日・月の道 | 5・6 に割り込む | 30〜60秒 |
| 5 | 振り返り | いまの章で作ったもの（島 13 の引きで順に）。きょう住人が撮った写真 | ふだんの切り替えで | 1〜2分 |
| 6 | 休んでいる住人 | 眠る・充電・待つ | — | **12秒まで** |

**決まり**
1. 上の順位は、下の順位に割り込める（同じ順位どうしは割り込まない）。
2. **試みのある住人を先に**：3 の中では、AI の試みの途中の住人を、習慣で動いている住人より先に映す。結果が近い（手順の残りが少ない）試みを、さらに先に。
3. **退屈な60秒を作らない**：映している住人に 45秒、強い出来事（吹き出し・札・結果）がなく、状態の1行も変わらないなら、もっと上の順位を探して移る。なければ 4（海）か 5（振り返り）へ。6 で12秒を超えない。
4. 同じ住人に戻るのは2分あける（1・2 は例外）。
5. 定時の見どころ（§3）は 1 と同じ強さで寄せる。始まる1分前に、その場所へ。
6. 夜（D24）も同じ順位。メインの海が 4、小窓のランタンが 1〜3 のときメインに戻す（NIGHT.md のまま）。
7. **切り替えた理由を記録に残す**（順位・種類・もとになった出来事）。試し回しで、どの順位がどれだけ映ったかを数える。

## 5. 音の決まり

いまのアプリには、時刻に合わせた生成の音楽（ピアノとパッド）、海と雨と風の音、島の言葉の声がある（`src/audio.ts`・`lumau/voice.ts`）。どれも「何時間聞いても耳にやさしい」作り。**これを土台に、配信の音の決まりを足す**。

### 5-1. 4つの層と大きさ

| 層 | 中身 | 大きさ（声を 0 dB として） | 決まり |
|---|---|---|---|
| **声** | 住人の島の言葉（台詞ごと） | 0 dB | 1人ずつ。話し手の画面の位置に合わせて左右に置く（吹き出しの位置、`lumauVoice` の pan）。声で誰か分かる |
| **知らせの音** | 見どころを知らせる短い音（§5-3） | −3 dB | 声と重ねない（声が終わってから） |
| **環境音** | 波・風・雨・鳥・夜の虫・焚き火 | −12 dB | 世界の事実から（天気・海の荒れ・時刻・火）。映している場所の音 |
| **音楽** | 時刻に合わせた生成の音楽 | −14 dB | 声が出ている間は 6 dB 下げる（0.3秒で下げ、1.5秒で戻す） |

- **全体の大きさ**：1時間の平均で **−16 LUFS**（±1）、瞬間の最大 −1 dBTP。YouTube は大きい音を下げるが、小さい音は上げない。BGM 代わりに流しても、ほかの動画と比べて小さすぎないところ。
- **夜**（3人が眠ったあと、21:30〜5:48）：全体を 3 dB 下げ、音楽の間をあける。
- 台風・雷も −1 dBTP を超えない。驚かせる大きさにしない。

### 5-2. 音楽の流し方（BGM として）

- 「曲」と「間」をくり返す：**曲 3〜5分、間 1〜2分**（間は環境音だけ）。ずっと鳴らし続けない。
- 時刻の色（いまの `MOODS`：夜明け・昼・夕・夜）に、**深夜**（0〜5時、いちばん静か）を足す。色が替わるときは、間をはさんで替える。
- 音楽は、いまのアプリの生成の音楽を使う（自分たちで作った音なので、配信で使う許諾の心配がない）。外の曲を使うなら、オーナーに相談。歌は使わない（住人の声と混ざる）。

### 5-3. 知らせの音（見どころを、耳で呼ぶ）

| 知らせ | 音 | いつ |
|---|---|---|
| **結果**（確かめた・やりとげた） | 明るい2音（木琴のような音） | 結果が出たとき |
| **結果**（違っていた・うまくいかなかった） | 低い2音（同じ音色） | 結果が出たとき |
| **決めた瞬間**（試みを言った） | やわらかい1音（同じ音色） | AI の答えが世界に入ったとき |
| **節目・初めて・章が変わった** | 澄んだ3音（ガラスの鈴のような音）、約3秒 | 札と同時 |
| **集まりの始まり**（朝・焚き火） | 木を2回打つ音 | 始まるとき。5分前に1回、小さく |
| **定時の見どころ**（夜明け・島めぐり・夕日・きょうの島） | 鈴を1音 | 始まるとき |
| 出来事の結果（縄がもった・切れた、着いた） | 出来事そのものの音 | 出来事のとき（自然班・本体） |

- **同じ知らせには、いつも同じ音**。くり返し聞くうちに「この音が鳴ったら画面を見る」と覚えてもらう。試みの音（決めた・結果）は、同じ音色の音の数と高さで分ける。
- **知らせの音は3分に1回まで**（節目は例外）。重なったら、強いほう（§4 の順位）を鳴らす。多すぎると BGM として流せない。
- 驚かせない：立ち上がりをやわらかく、高い音を抑える（いまの `audio.ts` の方針と同じ）。

### 5-4. 目を離していても、耳で分かること

| 耳で分かること | どの音で |
|---|---|
| いまの時刻（朝・昼・夕・夜） | 音楽の色、朝の鳥、夜の虫 |
| 天気 | 雨・風・波の荒さ |
| 誰が話しているか | 住人ごとの声 |
| 集まりが始まった | 木を打つ音、焚き火の音、何人もの声 |
| 試みが決まった・結果が出た | 試みの音（1音・明るい2音・低い2音） |
| 大事なことが起きた | 鈴の3音 |

### 5-5. 配信での鳴らし始めと音量（本体の連絡 10/26：アプリは音を切った状態で始まり、配信画面には音のボタンがない。1回目は、M キーを押していなければ無音だったはず）

| | 決め方 |
|---|---|
| 始めの状態 | **ライブ（`?live`）では、音を出した状態で始める**。音のボタンや「音を出す」の案内は、配信画面に出さない |
| 自動再生 | 配信の PC のブラウザを、クリックなしで音を出せる設定で起こす（Chromium の `--autoplay-policy=no-user-gesture-required`）。`docs/rehearsal/WINDOWS.md` の起動の手順に足す |
| 鳴らし始め | 起動・再起動のあと、**8秒かけて**無音から決まった大きさまで上げる。いきなり鳴らさない |
| 出せなかったとき | 画面には何も出さない（案内が配信に映らないように）。記録に `audio blocked` の行を残し、最初のキー入力で鳴らし始める |
| 音量 | ライブでは、アプリの音量を**固定**する。見る人が保存した音量（`vol`）や声の切り替え（`seaglass.voices`）は使わない |
| 全体の大きさ | 配信の出口で **−16 LUFS**（1時間の平均、±1）、瞬間の最大 −1 dBTP（§5-1） |
| 合わせ方 | OBS のブラウザの音声は 0 dB のまま。OBS 側では音を足し引きしない（瞬間の最大を抑えるリミッター −1 dBTP だけ）。アプリの全体の音量（1つの数）を、配信の音を30分録って `ffmpeg` の `ebur128` で測り、−16 LUFS になるように決める。決めた数はライブの設定に書く |
| OBS の音声 | 48 kHz・ステレオ・160 kbps 以上（声の左右の置き方が残るように） |
| M キー | ライブでも消音の切り替えに使ってよい（オーナーの操作用）。押したら記録に残す（`audio on` ／ `audio off`）。再起動したら、音を出した状態に戻る |
| 記録 | 試しの記録に、音の状態（on・off・blocked）を1分ごとに。その回に音が出ていたかを、あとから確かめられるように |

## 6. 言い方の決まり（R-027）

字幕（吹き出し）・朝の集まりの答え・焚き火の会の報告・試みの行は、**住人の話し言葉**にする。1回目には「共有：ラッコへ。貝殻が1つある（約110m）」（内部の書き方のまま）、朝の答え「僕は眠る。」（平板）が出た。

### 6-1. 決まり

1. **見出しを付けない**。「共有：」「記録：」「提案：」「了承：」「報告：」「識別：」は、言い方に込める。

   | 見出し | 言い方 |
   |---|---|
   | 共有 | 「〜があったよ」「〜にあるよ」 |
   | 提案 | 「〜しようよ」「〜しない？」 |
   | 了承 | 「わかった、〜する」 |
   | 記録 | 「〜を書きとめた」 |
   | 報告 | 「きょうは〜した」 |

2. **呼びかけは名前から**（「ラッコ、」）。誰に言っているかが、字幕だけで分かる。
3. **数**：住人が自分で知っている数だけ、人が言う形で（「110mくらい先」「22本目」「あと2本」）。かっこ・分数・記号（「/」「（約…）」）は使わない。隠れた値は言わない（これまでどおり）。
4. **長さ**：1回のひとことは2文・30字まで（吹き出しで2行）。
5. **口調は住人ごとに一定**。一人称・語尾を、住人ごとに決める（本体・科学班。`voices.ts` の `mind` に書く）。ラッコの一人称は「僕」（ADR 0004）。
6. **朝の集まりの答え**は、その日の試みから作る。形は「きょうは〜する。〜だから」または「〜してみる。〜はずだから」。夜を過ごしたランタンは、夜に見たこと1つ＋これから眠ること。
7. **焚き火の会の報告**は、きょうの試みの結果から。「〜したら、〜だった。あしたは〜」。
8. **結果のひとこと**：確かめた「やっぱり、〜だった」／違っていた「違った。〜しても、〜だった」。

### 6-2. 例（1回目の記録の台詞を直したもの）

| 1回目 | 直した例 |
|---|---|
| 共有：ラッコへ。貝殻が1つある（約110m） | ラッコ、110mくらい先に、貝殻がひとつあったよ。 |
| 僕は眠る。（ランタン、朝） | ゆうべは、月が遅れて昇った。いまから眠るね。 |
| 僕は海で食べる。（ラッコ、朝） | きょうは岩場でウニを探す。おなかがすいたから。 |
| 浜で 2 回続けて待ってから近くを歩けば、打ち上がった流木が見えて、拾う選択肢が出る（ドット、仮説） | 浜で2回待ってから歩けば、流木が見つかるはず。 |

- 最後の例の「拾う選択肢が出る」は、世界の内部の言い方（選択肢）。住人の言葉では「見つかる」「拾える」。
- 言葉の型は、島の言葉の文（`lumau/frames.ts`）で作る。`islandlang.ts` の古い型（`SAY.share` など、見出しつき）は、`frames.ts` の型に移す（本体）。
- AI の文（試み・ひとりごと）は、頼み方（プロンプト）でこの言い方を求め、検査で見出し・分数・内部の名前（R-016）を見つけたら出さない。表示の側で直さない。
