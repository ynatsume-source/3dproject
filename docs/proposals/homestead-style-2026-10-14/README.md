## 比較の条件

比較用保存は元の薪試作で使用した**人工fixture**を再利用。薪棚設備・薪24kg・近傍の成木1本の伐採記録を含む。同一ファイルを両方に読み込む。利用者の保存ではなく、画像のために本宅や小屋を完成させたものでもない。若木は5本とも未伐採。薪表示8本。

Chromium / SwiftShader、desktop 1280×720 high、phone 390×844 medium、DPR1、同じカメラ・時刻・天気・保存。外部通信を遮断した新規ブラウザーコンテキスト。時刻は昼12:00、夕17:30、夜20:30。

既存の島はこのソフトウェア描画環境で1フレーム数十秒かかる。最初の20warmup設定は撮影前に中止し、両側とも2warmup＋3計測へ統一した。失敗や中止を成功例として扱わない。フレーム時間は読み戻し同期を含む3回の中央値で、実機FPSや安定した性能差の証明ではない。描画負荷はdraw calls／trianglesも併記する。夜の燃焼描画値は両側とも約0.237で、短い待機後の火の立ち上がりを写している。定常状態や長時間配信の夜景評価ではない。

## 状態・動作検証

同じ乱数seedの新規世界で以下が変更前後完全一致：世界配置・100m内の衝突一覧・起動時乱数・60秒後の乱数・生活履歴SHA・保存SHA・fixture SHA・成木伐採直後と片付け後の状態・若木伐採後の保存と乱数。

若木は実際のchopアクションで立木→倒木→切株に移行する検査を追加。同じgeometry参照を維持し、保存trees[0]=1を確認した。**この動作検査だけはchopの前提である流木小屋完成を設定する。スクリーンショットfixtureには反映していない。**

形の単体検査：乱数消費なし、属性有限、葉束と板の閉じた面・外向き巻順、板の外寸、石の頂点位置不変。既存の薪状態テスト5件、fell、nav、本体typecheck/build成功。個別ログと前後fingerprintはevidenceに保存。

## 範囲と残る評価

これは4系統の一段目の比較で、島全体の完成形ではない。広角では未変更の森が大半を占め、家具の差は小さい。近景では新しい葉塊の面の角と光沢、隣り合う塊の継ぎ目が目立つ。全面展開の完成品質とはせず、次の造形・材質調整の判断材料にする。既存shaderと照明を使い、PR14の独立ステージと同じ明るさにはしていない。

実機GPU・長時間配信・大量の生活進行・端末横断でのちらつきは未評価。近景の微小カメラ移動は既存診断を使うが、画素の明度変化は輪郭・色・影にも依存し、純粋なaliasingの分離や合否判定にはならない。今回の少数フレームで品質や性能を断定しない。全面導入はこの実島比較の評価後に段階的に行う。main統合・公開は未実施。

## 再現用の入口

```sh
node --import tsx tools/lab/homestead-geometry.test.ts
node --test tools/lab/firewood-state.test.mjs
node --import tsx --import ./scripts/node-assets.mjs tools/lab/homestead-fixture.ts OUTPUT_DIR
```

撮影はmainと試作をそれぞれ`vite build --minify false`で作り、127.0.0.1:5322／5323でpreviewする。`PLAYWRIGHT_MODULE`と`CHROME`を環境に合わせて設定し、`FIXTURE`に同じ人工保存を指定して`tools/lab/homestead-capture.mjs`を実行する。`CASE`でケース、`OUT`で出力先を指定可能。近景の微小移動診断だけ`FLICKER=1`を付ける。通常のminify済みbuildはアプリループの停止フックに使えないため撮影用に使わない。
