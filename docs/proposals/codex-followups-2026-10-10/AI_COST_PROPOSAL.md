# AI費用管理をサーバーへ移す案（未実装・オーナー判断用）

2026-10-10。ADR 0002 §6 の「判断・会話・内省・創作・科学を合わせて月15,000円」を変えず、既存の共有世界案の AI gateway と予算台帳を具体化する。

## 現状

`src/robots/mind.ts` はブラウザから Anthropic へ直接通信し、キーを `seaglass.aikey` に保存する。通常の会話等は1日120回まで、住民の判断と記事は `seaglass.aipool` の用途別回数を使うため120回の枠とは別。`agent/config.ts` のモデル・上限・単価は運用設定であり、円建ての月額強制はない。端末・タブをまたぐ一元管理もない。

島だよりは Actions の secret を使い、6〜20時の暮らしと記事生成を Node で実行する。`runs/<日付>.json` の `usd` は `mindLog` と仮定単価からの推定で、請求明細ではない。API の事前確認と通常の会話はこの集計に含まれず、思考ログは最大200件。応答が届かない場合の実課金も分からない。この記録を月額上限の正本にはできない。

## 提案する形

国内 VPS の単一 writer と SQLite に **AI gateway と予算台帳を一つ**置く。ブラウザと島だより worker は同じ gateway を利用し、プロバイダーのキーを持たない。科学側に別の課金台帳を作らない。gateway が許すモデル・入出力の上限・用途・呼出元を検査し、世界の判断や記事内容の検査は既存の担当に残す。

1. 呼ぶ前に、`requestId` と `sceneId` を使って月の残額を transaction で予約する。入力・出力・キャッシュ作成を含む最大費用を、単価と余裕を持つ円換算設定で見積もる。会話・内省は場面全体を予約し、予約内で自然に終える。月末をまたぐ予約は開始月で保持する。
2. 送信前・送信済み・確定・送達不明を記録する。API の usage と結果で予約を精算し、確実に未送信の分だけ戻す。送達不明の予約は戻さず、自動で再送しない。同じ ID の再要求は保存した状態を返し、二重送信を防ぐ。
3. 全用途の確定費用と残る予約の合計が運用上限を超える新規予約を拒否する。上限は15,000円より低く置き、円換算・料金改定・外税等の余裕を確保する。世界は習慣と定型文で続く。
4. 月境界は Asia/Tokyo、台帳時刻は UTC。モデル・用途・住民・入出力/キャッシュ量・遅延・結果・予約額/精算額を記録し、月次に請求明細と照合する。世界 snapshot を戻しても予算台帳を巻き戻さない。台帳の復旧が確認できるまで送信を止める。

## オーナーが決めることと導入条件

運用上限の額、円換算の余裕、場面ごとの配分、対象モデルと最新の料金、gateway 利用者の認証を決める。プロバイダー側の支出上限も併用する。既存の個人ブラウザのキー方式を残すなら、オーナー負担の共有世界とは明示的に分ける。

導入時は同時予約・日/月境界・重複 ID・送達不明・再起動・世界復元を検証し、島だよりの事前確認/会話/執筆も同じ台帳を通ることを確かめる。料金や換算の根拠が確定するまでは、円建て上限の保証を出さない。今回は提案書のみで実装は行わない。
