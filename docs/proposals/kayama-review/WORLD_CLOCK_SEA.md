# 海の仕組みに、時計・季節・天気を外から渡す（ADR 0007 への海側の回答）

**未採択の提案資料。** 本体からの依頼（2026-10-05）への海チームの回答。
依頼の中身：海と生き物の仕組みが、時計・季節・天気を外から受け取れるようにする。
- 自然の世界は、現実の値を渡す。
- ドットたちの世界は、島の時計と、再生した天気を渡す。

## 1. いまの作り（洗い出しの結果）

**結論**：海と生き物（`src/eco`・`src/ocean`・`src/render`・監督・ガイド）は、日付をほとんど直接読んでいない。時間は次の3つの経路で入ってくる。

1. `skyState(ms, site)`（`time/clock.ts:147`）
   - 一つの `ms` から、太陽・月の位置、潮、時刻、昼夜、月齢、暦の月・日（`month`/`mday`）をまとめて出す純粋関数。
2. `applySky(loc)`（`main.ts:1004`）
   - `skyState(clock.ms)` と `liveWeather()` を、海の状態（光・雲・雨・うねり `uSwell`・さざ波 `uWave`・潮流 `uCurrent`）に変える。
   - 生き物へは `Ecosystem.setSky(s, current)` で渡す。
3. `Ecosystem.setSky`（`eco/ecosystem.ts:102`）
   - 生き物に暦（`env.month`/`mday`）が届く唯一の経路。

**直接読んでいるのは、時計そのもの・天気・画面の周りだけ。**

| 種類 | 場所 | 何を読む | 外から渡せるか |

### 一つの ms の問題（ドットたちの世界で効く）
`skyState` は、時刻と暦を同じ一つの `ms` から出している。ドットたちの世界は「明暗は現実・暦は13倍」なので、一つの `ms` では表せない。
- 太陽の通り道（日の長さ・高さ）は、暦の季節で変わる。
- 潮と月は、時刻の側で決まる。

## 2. 提案：「世界の時計」を一つの入口にする

```ts
// src/time/world.ts（新規・小さい）
export interface WorldTime {
  dayMs(): number;          // 明暗・潮・月・星：時刻の ms（どちらの世界も現実の時刻）
  calMs(): number;          // 暦・季節：自然の世界は dayMs と同じ。ドットたちの世界は島の暦の ms
  weather(): Weather;       // 自然：実況（いまの liveWeather）。ドット：再生した天気
  label(): { date: string; season: string };   // 画面の日付（島暦の表記もここ）
}
```

- **`skyState(dayMs, site, calMs = dayMs)`**：暦（`month`/`mday`）と、太陽の赤緯（季節で変わる太陽の高さ）を `calMs` から出す。自然の世界は今と全く同じ結果になる。
  - 太陽の高さを島の季節に合わせるかどうかは、本体の判断。合わせないなら、`calMs` は暦だけに使う。
- **`applySky`**：`clock.ms` → `world.dayMs()`、`liveWeather()` → `world.weather()`、`planets` と流星群 → `world.calMs()` / `dayMs()`。
- **`Ecosystem.setSky`**：変更なし（暦は `skyState` から届く）。`?month=` は自然の世界のテスト用に限る。暦の日が変わったら `startDay()` を引き直す。
- **水温**：`world.weather().sst ?? seaTemp(world.calMs())`。あわせて、時差を見ていない点を直す。
- **画面**：時計・日付・季節・記録のキーを `world` から取る。
- **時計の本体**：`clock`（早回し・季節の切り替え・共有リンク）は、観賞用の操作として自然の世界の `WorldTime` の中に置く。ドットたちの世界には別の `WorldTime` を作り、ADR 0001 に従って観賞用の早回しは履歴に触れない。
- **天気の形**：再生した天気は今の `Weather` と同じ形で渡してもらえば、海はそのまま使える（`wave`・`sst` が入っていれば、うねりと水温もそのまま）。

海側の作業は小さい：`world.ts` を作り、`applySky` と画面の時計まわりの呼び出し（十数か所）を替えるだけ。生き物のコードは触らない。

## 3. 自然の世界の嘉弥真島が、住人を外すと変わる所（気づいた点）

- **始まる場所**：住人のいる海では、潜り始めの場所を選ばずに浜の前から始めていた（`ocean/start.ts:11`）。住人を外すと、ほかの海と同じく、魚の多い場所から始まる。問題はない。
- **見どころが薄い**：嘉弥真島の海は、浅いラグーンで種類が少ない（ギンガメアジもベイトボールもない）。これまでは住人が主役だったので、自然の世界の嘉弥真島は巡航が単調になりやすい。
  - 海草の藻場がまだ描かれていない（カメマルの藻場 `beds` は本体の値だけで、海には出ていない）。実際の嘉弥真島の周りにも藻場があるので、自然の世界でも描くと、アオウミガメが食べに来る場面ができる。
  - 季節の生き物（夏のアジサシ、5〜6月のサンゴの一斉産卵、ツマグロの子ども）を、現実の暦で入れる余地がある。
- **説明文**：いまの嘉弥真島の説明は、別の星の前提（「地球と同じ形をした、人の住まない別の星」「ドット、カメマル…が暮らす無人島」）に書き換わっている（3c90bcd）。自然の世界の嘉弥真島は現実の島なので、元の書き方に戻す必要がある。ドットたちの世界の場所を別に作るときに、分けてほしい。
- **水域の区分**：`T.water`（住人が水に入れる所）は、住人がいるときだけ付けている（build.ts:440）。海の水域の区分（`oc.water`）そのものは住人と関係なく作っているので、影響はない。
- **人工物**：自然の世界では現実どおりでよい、とのこと。いま嘉弥真島の海に人工物を出す仕組みはない。足すかどうかは別に考える。現実の嘉弥真島は観光船が寄る島なので、係留ブイなどはありうる。

## 4. 進め方
1. この資料で入口の形を合意する。
2. 海側で `world.ts` と呼び出しの付け替えを行う。自然の世界の見え方と結果が変わらないことを確かめる（`skyState` の旧新比較、既存の各チェック）。
3. 本体が、ドットたちの世界の `WorldTime`（島の時計・再生した天気）を作って渡す。
