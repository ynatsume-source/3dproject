# 海底の物を「土台・固形物・サンゴ・小物」の層で考え直す

**未採択の提案資料。** オーナーの指摘（2026-10-05）を受けてまとめた。
- 平たいサンゴが突き抜けたり、食い込んだりしている。
- 丸いオブジェクトが安っぽく、生き物がすり抜ける。
- 岩やサンゴが浮いている。
- 「土台 → 固形物 → サンゴ → サンゴ同士の決まり」の順に考え直したい。

## 1. いまの作り（問題の根っこ）

| | いまの作り | 問題 |
|---|---|---|
| 土台 | 地形の関数 `loc.f`、洞窟の岩 `cave.topAt` | — |
| 岩 | 土台の上に、それぞれ独立に置く。登録は2つある：障害物の地図 `obst.stamp`（生き物用）と岩の一覧 `rockGrid`（サンゴよけ用） | 登録が2つに分かれていて、形の持ち方も違う |
| サンゴ | 土台の上に、それぞれ独立に置く。岩とは「避ける（ずらす・縮める・消す）」だけ | 岩の上に**着生できない**。サンゴ同士の重なりを**全く見ていない**。障害物として**登録していない**（茂み以外） |
| 小物 | 砂の上の瓦礫・貝・ナマコ | 何とも重なりを見ていない |
| 生き物 | 障害物の地図で地形と岩をよける | サンゴは地図に入っていないので**すり抜ける** |

高さは、2026-10-04 まで中心の一点で決めていた（浮きの原因）。3d8f3e8 で応急的に「体の下全体で据える」ように直した（`scripts/float-check.ts`）。

## 2. 実際のサンゴ礁では（調べたこと）

- **硬い面に着く**：サンゴの幼生は、岩や死んだサンゴの硬い面を選んで着生する。砂の上には育たない（転がっている塊は別）。岩の上にサンゴが載っているのが普通の姿で、いまの「岩を避ける」は逆。
- **テーブルは上から覆う**：テーブル状のミドリイシは周りより高く広がり、下の群体を日陰にする（「覆いかぶさり」）。その下は、ほかの場所の約1/4しかサンゴが育たない（Baird & Hughes 2000、リザード島）。覆いかぶさる戦いではミドリイシ属がほぼ勝ち、直接触れ合う戦いでは負ける、という報告がある（下の出典2）。
  - → テーブルの板は、低い群体の**上に隙間をあけて**張り出してよい。板の下は群体がまばら。板は他の群体を**貫通しない**。
- **触れ合う所には隙間ができる**：群体どうしが触れると、刺胞の長い触手や消化糸で攻撃し合い、境目の組織が死ぬ。触手の届く距離は、種によって数 cm〜20 cm ほど。境目には、白く死んだ帯や細い隙間が見えるのが普通。ヤギ類は根元が 5 cm より近いと枝がぶつかり合う。
  - → 種の違う群体は、根元・体を重ねない。間に数 cm〜十数 cm の隙間をあける。
- **同じ種は絡み合う**：枝状のミドリイシは、同じ種どうしで絡み合った大きな茂みになる。
  - → 茂みの中だけは、重なりを許す（いまの「茂み」の扱いのまま）。
- **向き**：塊状・被覆状の群体は、着いた面に沿って育つ。枝状は光の方へ伸びるので、傾きは小さい。テーブルは水平に広がる（3d8f3e8 で一部反映済み）。

出典：[Baird & Hughes 2000（テーブル状サンゴの下の群集、JCU）](https://researchonline.jcu.edu.au/12914/)、[出典2：サンゴ群体の成長と競争（JCU）](https://researchonline.jcu.edu.au/54194/)、[ヤギ類の最近接距離（BCO-DMO）](https://www.bco-dmo.org/dataset/662791/description)、[サンゴの攻撃（触手・消化糸）の届く距離（Reef Builders）](https://reefbuilders.com/2024/01/06/how-to-deal-with-coral-aggression)

## 3. 提案：層と、一つの登録

| 層 | 中身 | 決まり |
|---|---|---|
| 0 土台 | 地形・洞窟 | 高さ・傾き・底質（砂／岩盤／礁）を返す |
| 1 固形物 | 岩・死んだサンゴの塊・瓦礫 | 土台に体の下全体で据える。形を登録する |
| 2 サンゴ | 生きた群体 | 土台の礁・岩盤、**または固形物の上**（硬い面）に着く。形ごとの条件（傾き・深さ・明るさ）に従う。登録する |
| 3 小物 | 貝殻・瓦礫片・ナマコ・ヒトデ | 0〜2 の表面に載せる。どれにも食い込ませない |
| 4 動くもの | 生き物・ドローン・カメラ | 同じ登録を障害物として使う（すり抜けない） |

**一つの登録（仮に `src/ocean/substrate.ts`）**
- 各物の**体**を持つ：
  - 根元の円
  - 高さごとの広がり（回転体）
  - 硬いか、すり抜けてよいか（ヤギの扇や海草は「しなる」扱い）
  - 上面の高さ
- 次のものが**同じ答え**を使う。住人の `solids.ts`、海の `water.ts` と同じ考え方。
  - 置くとき（重なりの判定、着く面の高さ）
  - 生き物の衝突（いまの障害物の地図 `obst` の代わり）
  - カメラ（めり込まない）

**サンゴ同士の決まり（案。数字はチェックで確かめて決める）**
1. 種の違う群体は、根元も体も重ねない。隙間は大きい方の半径の 5% 以上（最低 5 cm）。
2. 同じ茂みの中は重なってよい。
3. テーブルの板は、ほかの群体の**上**に張り出してよい。板の下面と、下の群体の上端の間は 15 cm 以上あける。貫通は不可。
4. テーブルの板の下は込み具合を下げる（ほかの場所の約1/4）。
5. 丸い群体は、着いた面に沿って傾ける（最大45°）。枝は20°まで。テーブルは水平。
6. 込み具合の上限：1 m² あたりの群体の覆う割合（被度）を、海ごとの目安（例：礁原 30〜60%）に収める。いまの数（海ごとの密度）は、なるべく保つ。

## 4. 進め方（基盤と見た目を分ける）
1. **基盤の組み替え**（見た目はなるべく今のまま）
   - 層と一つの登録に置き換える。
   - サンゴの置き方を、決まり1〜6に従わせる。
   - 生き物とカメラの衝突を、登録に付け替える。
   
   確かめること：
   - `coral-overlap-check` の「入り込んでいる」を 30〜43% → 2% 未満にする。
   - `float-check` を通す。
   - `coral-rock-check`・`coral-depth-check` を通す。
   - 新しい「すり抜けチェック」を通す（魚・カメ・サメがサンゴの体に入る割合）。
   - 群体の数と覆う割合の変化を報告する。
2. **見た目**
   - 平たいテーブルの形（板の厚み・縁・裏側、柄）を作り直す。
   - 丸い群体と丸い岩の形と質感（ノウサンゴの溝、ハマサンゴの凹凸、岩の割れ目）を作り直す。
   - 前後を画像で並べる。
3. 小物と、生き物の避け方（前方のセンサー、マンタトレインの件）を、同じ登録の上で作る。

## 5. 進み具合
- **第1段の一つめ（2026-10-05）**：サンゴ同士の決まり 1〜3（重ねない・茂みの中は重なってよい・テーブルの板は上に張り出してよい）を、体の登録（`src/ocean/substrate.ts`）で入れた。
  - 入り込みは 18〜43% → 0〜0.1%。
  - 候補を約1.5倍に増やし、群体の数の減りを 17〜35% に抑えた（宮古 11,604 → 9,608、嘉弥真 12,494 → 8,172、GBR 33,403 → 21,868）。テーブルは減りが大きい（宮古 602 → 247）。
  - 海を作る時間は約 +13〜28%。
- **第1段の二つめ（2026-10-05）**：硬い体のサンゴ（丸・板・シャコガイ・ソフトコーラル）を、生き物とドローンが避ける高さの地図に入れた。枝サンゴとヤギは、小魚が中で暮らす網目なので入れない。生き物がサンゴの硬い体に入っている割合は、宮古 1.68% → 0.01%、GBR 0.99% → 0.03%（`scripts/passthrough-check.ts`）。ドローンがサンゴの頭で押し上げられることが少し増えた（motion-check の pops、宮古 3 → 10回）。
- **残り**：岩の上への着生、決まり 4〜6、岩と小物の登録の一本化。
