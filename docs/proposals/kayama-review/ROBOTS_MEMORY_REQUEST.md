# 住人側（src/robots/）のメモリ：世界に影響せず軽くできる所の調査と依頼文（2026-10-07）

海側の担当（このセッション）は `src/robots/` を変更しない。そのため、読んで測るだけで調べ、住人側の担当へ渡す依頼文を作った。

## 調べたこと

### 測定

- `tools/lab/memory.cjs`（`SEA=kayama CRUISE=20`）：嘉弥真で 20 分巡航した。1 分ごとに GC してから、JS ヒープとシーンの数を測った。
  - ヒープ：42.5 → 46.3 MB。
  - 3D の形の数：2604 → 2767。主に、島の海で近づいた区画のサンゴを育てる仕組み（`oc.grow`。海側の処理で、離れたら捨てる。上限あり）による。
  - 住人側のリークは、20 分では目に見えるほど溜まらなかった。
- `tools/lab/alloc.cjs`（圧縮しないビルド、`SEA=kayama`、巡航と住人目線の両方）：毎コマ作っては捨てるゴミの量を測った。
  - 上位 30 はすべて海側（魚の群れ・プランクトン・地形・鳥・生き物）だった。住人のコードは入っていない。

### 触らない方がよいもの（世界に関わる）

- **`agent.seen` / `heardFrom` の中身を間引くこと**：住人が見た・聞いた物の記憶そのもので、ADR 0004 の知識にあたる。なくなった物の記録を消すと、住人の判断（取りに行って「なかった」と学ぶ流れ）が変わる。メモリ上の増え方は 1 時間に数十件・数 KB 程度。保存は `slice(-80)` で上限があり、保存データは膨らまない。変える理由がない。
- **`src/robots/` の `Math.hypot`**（`residents.ts` に 64 か所など）：海側では、作っては捨てるゴミの最大の出どころだった。住人側は測ると上位に入っておらず、急ぐ理由がない。また置き換えると結果が最後の桁で変わりうる。判定や経路の境目で住人の行動がずれる可能性があるため、世界に影響しないとは言い切れない。
