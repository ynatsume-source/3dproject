# 説明表示・対象への向かい方・タップ：いまの仕様と課題の洗い出し

**未採択の提案資料。** オーナーの指摘（2026-10-05）を受けた洗い出し。すぐには直さず、仕様と課題をまとめた。

指摘された内容：
- 説明が出ているのに、画面にその生き物がいない（「◯◯の群れ」「シュモクザメ」）。
- 書かれた行動をしていない（「ヒブダイ 藻をかじっている」）。
- 向かった対象が真ん中に来ず、ずれた所を撮り続ける。撮り方が不安定。
- タップしたのに「図鑑から」と出る。
- 画面にいる小さな群れをタップしても、奥の磯へ向かう。
- 案：説明の対象に淡い丸をつける。

## 1. いまの仕組み

### 上部の説明（`#caption`）
- 書いているのは `updateCaption`（main.ts:272-322）。
- 対象は、撮影監督がいま撮っている被写体（`lastShot`）。撮っていないとき（巡航中）は、2秒ごとに前方 14 m 以内・前方約41°の範囲から一つ選ぶ。
- 出す条件は「撮影がある」「観察の段階か、頼まれた撮影」だけ。
  - **画面に映っているか（画角・岩に隠れていないか・霞んで見えないか）は調べていない。**
  - 頼まれた撮影（図鑑・タップなど）では、**まだ向かっている途中から**説明が出る。
- 状態の文（`.s`）は被写体の `status()`。1秒ごとに更新する。
- 見出しの小さな文字（`.k`、main.ts:312）は、頼まれた撮影なら**どこから頼まれても**「図鑑から ・ 到着」。

### 状態の文（`status()`）の作り方
- **正確なもの**：カメ、マンタ、タコ、ウツボ・ウミヘビ、狩り（狩りの段階）、ギンガメアジ、ベイトボール、クジラ、跳躍。
- **不正確なもの**：
  - **礁の魚と回遊魚**（fish.ts:618-626）は、**種ごとにまとめて**計算している。
    - 海全体の群れの活動度を平均し、時刻で「休んでいる」「動き出す」を決める。
    - それ以外は**食性で決まった文**を出す。藻を食べる種は「藻をかじっている」、魚を食べる種は「巡回中」。
    - 映っている個体が実際に何をしているかは見ていない。驚いて逃げていても「藻をかじっている」のまま。
    - どこかの群れが狩りをしていれば、全部が「狩り中」になる。
  - **小魚の群れ**（shoal.ts:249-255）も種ごと。どこかの群れが怖がると、全部が「逃げて…」になる。
  - **図鑑から向かったカメとマンタ**（main.ts:1273-1274, 1372-1379）：
    - カメの状態は「**その時いちばん近いカメ**」のもの。向かっているカメとは限らない。
    - マンタは常に1枚目のマンタ。

### 向かい方
入口は5つあり、どれも `focusOn` → `director.focus`（頼まれた撮影）に入る。

| 入口 | 被写体の作り方 |
|---|---|
| 図鑑の「見に行く」（`goTo`） | 種ごとに違う。魚は**群れのいる場所の点**（`g.c`）、小魚の群れは**先頭の点**（`L.c`）。カメは「いちばん近いカメ」、マンタは1枚目、ウツボや場所は**固定の点** |
| 画面のタップ（`tapAt`） | 被写体を拾えなければ、岩や海底の**固定の点**（「このあたりの礁」） |
| 左下の案内（`#toast`「35m先に ◯◯ › 見に行く」） | その被写体。海の記録から来たものは、記録した時点で**止めた点**（捕食の跡など） |
| 新しく見つけた生き物の丸 | 最後に見えた点 |
| 撮影監督が自分で選ぶ（巡航） | 画角・遮蔽を見ずに、優先度・前方の向き・距離で選ぶ |

**撮り方で、被写体を真ん中に置かないもの**（director.ts）：
- 狩り：狩る魚と獲物の間の 30% の点を、望遠で見る（307）。
- 大きい生き物の撮り方（横・前・後ろ）：体の前後にずらした点を見る（463, 472, 488）。
- 待ち伏せ（wait・pass）：カメラを止めて、通り過ぎるのを待つ（386-388, 453, 497）。
- 先回り（follow）：進む先を見る（380）。
- 向かう途中で経路が 14 m 以上残っている間は、被写体ではなく**経路の先**を見る（main.ts:494, 509）。
- 位置がまだない被写体（来る前のクジラ）は、**東の固定点**を見る（283）。
- 「固定の点」の被写体の中には、大きさ 1.4 以上のため**大きい生き物用の撮り方**に入るものがある。止まった点の前後を、意味のない向きで撮る（記録の点、新しく見つけた点、場所）。
- 「到着」の判定は、近づいたときか、**時間切れ**（25〜90秒）。着いていなくても「観察中」になる。
- 群れは**先頭の点**から約 3.4 m で撮る。魚はカメラを 4 m ほど避けるので、真ん中が空っぽになる。

### タップの拾い方（`pickAt`, main.ts:2087-2109）
- 拾えるのは「被写体」だけで、個々の魚は拾えない。
- **小さい礁の魚（スズメダイ・ハナダイなど）は、そもそも被写体ではない**（fish.ts:638：大きい種で、しかも活動中のものだけ）。そのため、タップは奥の礁（「このあたりの礁」）に落ちる。
- 群れは**先頭の点が画面内にあるとき**だけ拾える。拾える半径は大きさ 3.5 の決め打ちで、群れの実際の広がりも画角も見ていない。
- 「奥の礁より 2 m 以上遠い被写体は隠れている」として捨てる。群れの先頭の点が礁の向こうにあると、手前に見えている魚ごと拾えない。

### 丸と案内
- `#evMark`（記録・案内の丸）：毎フレーム画面に投影する。画面の外では端の矢印になる。大きさは固定。**別の物をタップしても消えず**、最長9秒残る。
- `#newMark`（新しく見つけた丸）：被写体の見かけの大きさに合わせた半径。画面外では消える（矢印はない）。
- 左下の案内（`#toast`）：前方約72°・3〜35 m の候補から選ぶ。**画面に映っているかは見ていない。**

## 2. 課題のまとめ（原因が確かなもの）

| 症状 | 原因 |
|---|---|
| 説明が出ているのに画面にいない | 説明を出す条件に「映っているか」がない／向かっている途中から出る／時間切れで「到着」になる／巡航の候補の範囲が縦画面の画角より広く、岩の遮蔽も見ない／止まった点を被写体にしている |
| 書いた行動をしていない | 礁の魚と群れの状態が「種ごと・時刻と食性」で決まっている／カメとマンタは別の個体の状態 |
| 真ん中に来ない・ずれた所を撮り続ける | 撮り方の多くがずらした点を見る／待ち伏せ／経路の先を見る／固定の点を大きい生き物用の撮り方で撮る／群れの先頭の点は空っぽ |
| タップしたのに「図鑑から」 | 頼まれた撮影は、どこから頼まれても「図鑑から ・ 到着」と表示する。どこから来たかを記録していない |
| 小さな群れをタップすると奥の磯へ | 小さい礁の魚は被写体ではない／群れは先頭の点でしか拾えない／遮蔽の判定が先頭の点 |

## 3. 提案：「見えているものだけを言う」決まり

**決まり1：説明と丸は、画面に見えている間だけ出す。**
- 被写体の体（群れなら魚たちの範囲）の一部が次の条件をすべて満たすとき、「見えている」とする。
  - 画面の内側にある。
  - 岩やサンゴに隠れていない（海底の登録で確かめる）。
  - 霞の手前にある。
  - 画面上で一定の大きさ以上ある。
- 見えている間は、**被写体のまわりに淡い丸**を出す（オーナー案）。丸の大きさは被写体の見かけの大きさに合わせる。今の `#newMark` と `#evMark` を合わせた作り。
- 向かっている途中は、見出しを「◯◯へ向かっています」だけにし、状態の文は出さない。被写体が画面の外なら、丸は画面の端の矢印になる。
- 見えなくなったら、説明は数秒で薄く消す。

**決まり2：状態の文は、その個体（その群れ）の実際の状態から作る。**
- 礁の魚と群れも、カメと同じく**映っている群れ自身**の状態から作る。
  - 例：「藻をかじっている」は、実際に噛む動きをしているときだけ。逃げているときは「逃げている」。
  - 種ごとのまとめと、食性の決め打ちの文はやめる。
- 図鑑から向かうときも、**選んだ個体**に付いていく（カメなら選んだその1頭）。

**決まり3：どこから来たかを、そのまま言う。**
- 向かう理由を記録して、見出しに出す：「図鑑から」「タップした◯◯」「案内から」「見つけた◯◯」。

**決まり4：撮り方は、被写体を画面の中に収め続ける。**
- 撮り方ごとの「見る点」を、被写体の体が画面の安全域（中央の約60%）に入るように補正する。狩りの望遠、大きい生き物の横・前・後ろ、先回りが対象。
- 待ち伏せは、被写体が画面に入っているときだけ使う。
- 経路の先を見るのは、被写体がまだ見えないときだけにする。
- 固定の点（場所・タップした礁）は、その場所をゆっくり見回す撮り方にする。大きい生き物用の撮り方には入れない。
- 群れは、先頭の点ではなく**魚たちの重心**を撮る。

**決まり5：タップは、画面に見えている生き物を拾う。**
- 群れは、個々の魚の画面上の位置で拾う（間引いて投影する）。先頭の点や大きさの決め打ちは使わない。
- 小さい礁の魚の群れも、「小さな群れ」として被写体にする。近くで、ゆっくり撮る。
- 遮蔽は、タップした点の画面上の奥行きと、拾った魚の奥行きを比べて判定する。

## 4. 確かめ方（数字で）
新しい LAB（`tools/lab/caption.cjs`）で、既定の巡航と図鑑・タップからの向かい方を数分ずつ撮り、次を測る。

| 測るもの | 目標 |
|---|---|
| 説明が出ている時間のうち、被写体が見えていない割合 | 2% 未満 |
| 状態の文が、その個体の実際の状態と一致しない割合（狩り・休息・逃避・採餌） | 0 |
| 観察中に、被写体が画面の安全域の外にある割合 | 5% 未満（今の構図チェックより厳しく） |
| 画面の群れや小魚の位置をタップして、その群れに向かう割合 | 95% 以上 |
| 見出しの「どこから」が、実際の入口と一致する割合 | 100% |

  - 輪のずれ：宮古・嘉弥真・GBR とも 0.0%。
- **タップした物を見ながら向かう（2026-10-06、オーナー指摘）**：タップ・案内・初めて見つけた丸から向かう途中は、経路はそのままで、カメラは対象の体を向き続ける（追従も速く）。図鑑の「見に行く」は、見えてから対象を見る（これまでどおり）。
  - `tools/lab/look.cjs`：15〜45 m 先の見えている魚（3回に1回は礁・海底）をタップし、向かう間に、その魚（小魚なら群れの重心）が画面の中央30%以内にある割合を測る。変更前 76% → 変更後 96〜100%（宮古・GBR）。
- **巡航中に指で向けた視点を保つ（2026-10-06、オーナー指摘）**：指で向けた方向を、ドローンの向きからのずれではなく海の中の向きとして持つ。触れている間と、離してから4.5秒（コマの時間で数える）は、巡航が曲がってもその向きを見続け、その後ゆっくり正面へ戻る。何かを頼むと、視点のずれは戻る（頼んだ物が真ん中に来る）。
  - `look.cjs`：60°横へ向けたあと4.5秒、巡航が最大130°曲がる中で、向きのずれ 0°。その8秒後に正面へ戻る（0.1°以内）。
- 測定道具の秒の表示を直した。1コマは世界の時間で最大 1/20 秒で、0.1 秒ずつ進めていた道具は秒を2倍に数えていた（割合の数字は変わらない）。
- **輪は、説明と対象を取り違えうる時だけ、少しの間（2026-10-06、オーナー指摘）**
  - 定義「見ている人が、説明と対象を、まわりの生き物と取り違えずにつなげられる」：次のどれかなら輪を出さない。
    - **A 主役**：対象が画面の短辺の 1/4 以上の大きさで、中心から 30% 以内にいる。ただし、別の種類で対象の 3/4 以上の大きさに写っているものがあれば、主役でも輪を出す（サメの横に同じくらいのサメ、など）。
    - **B 紛らわしいものがない**：画面に、別の種類の生き物で、対象の半分以上の大きさに写っているものがない。同じ種類の魚は数えない（同じ説明が当てはまる）。
    - **C 画面いっぱい**：対象が画面いっぱいに写っている（接写、群れの中）。
    - 大きさは画面上の見かけ（体長 ÷ 距離）で比べる。群れは、その種の1匹の体長で比べる。
  - **出し方**：要るときだけ3秒出して、1秒で薄く消す。次の時は、もう一度3秒出す：紛らわしいものが新しく画面に入ってきた時／対象が一度画面から外れてまた入った時。向かう途中で対象が画面外にある時の端の矢印は、道案内なので出し続ける。
  - **確認**（`caption.cjs`）：説明ごとに、最初の2秒に紛らわしいものがあったか（道具が魚1匹ずつ・ほかの動物を見て別に判定）と、輪が出たかを数える。
    - 紛らわしいのに輪が出なかった：宮古・GBR・嘉弥真とも 0。
    - 輪が出ている時間：説明が出ている時間の 9〜16%。
    - 紛らわしくないのに輪が出た：4〜8件。最初の2秒より後に紛らわしいものが入ってきて出したもの。
    - 測定の途中で、道具側の誤りを3つ直した：ほかの魚の長さを図鑑の大きさで数えていた／カメやマンタを数えていなかった／対象自身が画面外の時も数えていた。
- **オーナー指摘の5件（2026-10-06 夕）**
  1. **NEW SIGHTING の丸が何もない所に出る（ギンガメアジ）**：回遊する群れの「見つけた位置」が、群れが追いかけている先導点（群れより先の開けた水中）だった。前方にいる、いちばん近い魚そのものの位置にした（`shoal.ts` `nearestPos`）。
  2. **魚群の陰のイタチザメに説明と輪が出る**：見えているかの判定は地形（岩・サンゴ）の陰しか見ていなかった。別の種類の魚が視線を横切っていれば、そこは見えないとした。
     - 視線の近くにいる魚（礁の魚・回遊魚・ベイトボール・ギンガメアジの群れ・めったにない光景の魚の川）を1回集める。各種、均等に間引いて最大1500匹。
     - 体の5点への視線のうち、1本でも通れば「見えている」とする。視線は、魚の体長の1/3以内を魚が横切ると塞がれる（魚を横から見たときの体の高さ）。
     - 同じ種類の魚は数えない（群れそのものが対象のとき）。
     - 同じ判定を、めったにない光景の「見えた」にも使う（群れの陰のシュモクザメは、まだ見えていない）。
     - `caption.cjs` の「見えていない」判定にも、別に実装した同じ定義を足した：全部の魚を数え、間引かない。宮古の巡航240秒＋図鑑5種＋タップ3回で、説明が出ているのに見えていない時間は 0.3%（目標 2% 未満）。
  3. **SEA LOG から向かった先の説明が文の切れ端（「スジアラがハタタテダイの群れの下を」）**：
     - 行き先は、その出来事の場所の近くにいる本物の被写体にした。文に名前が出てくる生き物（12 m 以内）を優先し、それ以外は 4 m 以内。説明はその生き物のもの（名前・いまの様子・図鑑）になる。
     - 見つからないときは、場所を「誰の出来事か」（文頭の「〜が／〜は」）で名づけ、SEA LOG の一文をいまの様子として出す。
  4. **ナンヨウマンタが画面中央に大きく映っているのに、説明が 10〜15 秒遅れる**：監督が自分で選んだ被写体は、着いて撮り始める（observe）まで説明を出していなかった。
     - 向かう途中でも、対象が見えていて画面の短辺の1/5以上に写れば、その時点で説明を出す（同じショットの間は出したまま）。
     - 頼んだもの（図鑑・タップ）の「向かっています」の見出しは、これまでどおり。
     - 測定（宮古・モルディブの巡航8分、監督が選んだショットごとに、撮り始めと説明が出た時刻）：ナンヨウマンタ 撮り始め 7.0 s／説明 1.9 s、4.8 s／0.6 s。ジンベエザメ 18.8 s／0.8 s。イタチザメ 7.0 s／0.6 s。ツマグロ 7.8 s／0.6 s。説明が出ないのは、3分以内に同じ種類を説明したときだけ（これまでどおり）。
  5. **テンポが悪くなった**：
     - 測定（ヘッドレス、描画なし）：監督のショットの長さ・最初のショットまでの時間・視点の回転は、変更前と同じだった（宮古・モルディブ8分：平均ショット 26–27 s → 24–26 s、最初のショット 9.6 s）。1コマの処理（描画以外）も変わらない（10.5 → 10.6 ms）。
     - 違ったのは描画：新しい説明欄の「すりガラス」（`backdrop-filter: blur`）は、動いている海を毎コマぼかし直す。SwiftShader・スマホ縦・DPR 2 で、説明が出ている間の1コマが 1976 ms → 2374 ms（約2割増）になった。
     - このアプリは1コマを世界の時間で最大 1/20 秒として進める。だから実機で 20 fps を切ると、海そのものが遅くなる（巡航も、ショットの長さも、振り向きも）。説明が出ている時間が長くなったぶん、ここが効いていたと考えられる。
     - 直し方：説明欄のぼかしをやめ、地の色を少し濃くした（見た目はほぼ同じガラスの板）。輪の「呼吸」アニメーションは、出ていない間は止める。
     - ぼかしを外したあと：説明あり 1754 ms、なし 1687〜1769 ms で、差はなくなった。
     - 実機の fps は測れていない。直したあとも重さを感じるなら、実機で `?diag` を見たい。
