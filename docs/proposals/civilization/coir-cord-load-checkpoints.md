# 縄の荷重：消えた材料の記録を整理する（host-5）

## 範囲と版

荷重部品の基準は main `fcfbf8e3ad1e8ae55d33ce98e096fce777280103`。
PRは受入済みの記録整理を含む `c09181349cfa1271c8b9b45e737c228d1e7ad317` の上に重ねる。
荷重・日照・擦れの記録の寿命だけを変える。整数強度モデル、縄のquality、
収支、荷重結果のID・seq・worldVersion、住人への言葉は変えない。

- processVersion: `host-5`
- 内部の一時結果: `civ-world.coir-cord-load/5`
- Ledger.coirCordLoads と coirCordLoadFormat: `civ-world.coir-cord-load-ledger/5`
- 強度方針: 既存の `INTEGER_HALF_LIFE_POLICY_ID`
- 生きた縄ごとの再送: 直近64件（従来どおり）

/4 の「消えた親IDの要約を永久に残す」という範囲を変更する。
撚り合わせに使われた糸や、切れた親を作った総数に比例して保存を伸ばさない。

## 保持するもの

`cords[lotId]` は、最新状態・二つの時計・期限下限・直近64指示のreceiptを持つ。
切れた親は最新LotViewを持たず、子のIDとreceiptだけを持つ。
`commands` は保持中のcommandIdの索引で、窓内の再送は元と同じ結果を返す。
過去の結果を返しても材料を復活させない。内容違いは拒否する。

`retention` は整数の世代、双方向リストの先頭・末尾・次の掃除位置と、
各行の前後ID・最後に触れた世代を持つ。ヘッダーと各ノードに破損検知用の
チェックサムを持つ。全体のチェックサムを毎回計算し直す形にはしない。

新しい指示が一度成功したときだけ世代を1進め、対象と新しい子片をその世代にする。
同じ指示の再送、拒否、時計が進むだけの時間、保存復帰は世代を進めない。

## 消す条件と掃除

次をすべて満たす行を消す。

1. その材料の最後の成功から、新しい荷重指示が全体で64件以上成功した。
2. 現在の `L.lots` に同じIDがない。
3. 設備の `assembled.from`・`assembled.parts` にも同じIDがない。

組み立て中の縄は、`disassembleParts(..., {keepLotIds:true})` で同じIDに戻る
現物なので保護する。予約中の材料も在庫に存在するため消さない。
切れた親が子のチェックポイントを永久に所有する形にはしない。
子が消えても、窓内の親のreceiptから過去の切断結果は読める。

通常の新しい成功では、保存した掃除位置から最大8ノードだけ調べる。
存在する材料のチェックポイント本文は読まず、無関係な全記録の列挙・複製もしない。
期限時点では存在し、その後に撚り合わせで消えた糸も巡回して再び調べるので、
一度だけ期限リングから見る方式の取りこぼしはない。
掃除は検査済みの小さなパッチを用意してから反映し、拒否では何も消さない。

`compactCordLoadLedger` / `validateCordLoadLedger` は明示的な保存復帰境界で、
全体を検査し、その時点で期限を過ぎた不在行を巡回の待ちなしで取り除く。
この全体検査・旧形式の初回移行だけは記録数に比例する。
通常処理で全体検査を繰り返さない仕組みは従来どおり。

残る行数は、現存または組立中の材料、直近64世代の行、上限付き掃除の巡回待ちで決まる。
材料が増え続ける世界全体の容量は一定にしない。
何も処理しない間に保存を自動で書き換えることもしない。

## 再送の期限

生きた縄は従来の縄ごと直近64件を保持する。
窓から落とした要求の二つの時計を `floor` に残し、古い指示を二重に適用しない。
同時刻の新しい指示と期限外の再送を区別できない境界では、安全側で拒否する。
片方の時計だけが進んだ新しい指示は受け付ける。

消えた縄の全行が掃除された後は、過去の結果の返却を保証しない。
存在しない材料への古い指示は拒否し、物・傷み・seqを変えない。
本体は材料IDを再利用しない。消した材料を同じIDで意図的に在庫へ捏造して戻す行為の
永久検知は、削除した要約へ依存させない。

## /3・/4 の移行

/4 は旧ヘッダー、全行、receipt、チェックサム、子の対応を元の形のまま検査する。
/3 は旧版の全履歴と荷重runを、凍結した /3 の検査器で照合する。
先に /5 の名前だけ付ける移行はしない。

検査後、既存の行・時計・floor・receiptを保って /5 の索引を作る。
移行時の世代は0、各行の最後の世代も0とし、新たな成功64件の猶予を与える。
旧データに残っていない全体順序を推測して早く捨てない。
荷重run以外のrunや予約、在庫・強さ・IDは変えない。
最初のapplyで移行する場合は、その要求の成功または窓内再送と一緒に反映する。
不正な要求で移行だけが残ることはない。

/5 の復帰では、ノードとcheckpointの集合が一致すること、前後のつながり、循環がないこと、
掃除位置、世代範囲、ヘッダーとノードのチェックサムを検査する。
版名だけ変えた /4、欠けた索引、壊れたつながりは拒否する。

## 検査

既存の閾値・収支・ID・観察・/3移行・縄ごと64件の再送と期限を維持する。
縄6本の一年分2190件、保存512KiB未満、無関係な記録の走査を禁じるProxy検査も維持する。

追加する検査は、実際に糸を作って撚り合わせる1,000回、切れた親と子、
64件経過後に消費した糸、組立中の保護と同じIDでの返却、/4保存の移行、
窓内の切断再送・JSON復帰、拒否と再送で掃除の世代が増えないこと。
1,000回で作った縄はすべて物理在庫に残し、`coirCordLoads` の容量だけを比較する。
この検査は世界全体の保存容量が一定であるとは主張しない。
