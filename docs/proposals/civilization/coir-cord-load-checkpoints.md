# 縄の荷重：上限つきチェックポイント（host-4）

## 範囲

基準 main 4b01ab67975e146c5e112210539cb1a51879ca62。
荷重・日照・擦れの台帳記録だけを変更する。整数強度モデル、縄のquality形式、
process-runner、住人の行動・記憶・表示・帆の接続は変更しない。
科学のキメ値と強さの判定は従来どおり。

- processVersion: host-4
- 内部の一時結果: civ-world.coir-cord-load/4
- Ledger.coirCordLoads: civ-world.coir-cord-load-ledger/4
- Ledger.coirCordLoadFormat: 同じ /4（記録欄の欠落を検知するマーカー）
- 強度方針: 既存の INTEGER_HALF_LIFE_POLICY_ID を明示して保存

## 保存するものと上限

cords[lotId] に最新の状態を一つだけ持つ。

- live: 最新のLotView、世界/島時計のカーソル、再送窓の下限、直近64指示のreceipt
- retired: 最新LotViewはnull、切れた二片のID、時計と直近64指示のreceiptだけ
- receipt: 元の要求、返したrunId・lotIds・観察文、小さなチェックサム
- commands: 窓に残るcommandIdから物理lotIdへの索引（縄ごとに最大64件相当）

返した子片も独立した物理IDとしてチェックポイントを持ち、親の時計から始まる。
廃止IDは復活を防ぐため要約を残す。時間がたつだけでは要約は増えない。
上限は「同じ物理IDへの出来事数」に対するもの。縄を新しく作る・切断して物理IDが増える場合まで
全世界の記録量を一定にはしない。要約を任意に捨てて古いIDの復活を許すことはしない。

完了した荷重runはL.runsへ追加しない。要求ごとのcommittedも増やさない。
返すrunIdとseqの進み方は旧版どおりで、切れなかった場合の一時lotIdは外に出さない。
runIdは取引の決定的な識別子であり、永続runへの参照ではない。

## 再送の保証と期限

同じ縄の直近64件は、内容が一致すれば、JSON保存・復帰後も元と同じ結果を返す。
後で縄が切れた・移動した・他工程で消費された場合も、過去の結果を返すだけで物は戻さない。
窓内の同じcommandIdを違う内容や別の縄で使えばconflicting-replay。

64件より前の指示の完全な結果は保存しない。消えた指示を再適用しないため、退去した最後の指示の
世界/島時刻をfloorに残す。索引にない要求が **両方の時計でfloor以下** ならexpired-commandで拒否する。
片方だけ止まっていることは許す。通常の時計の後退・重複曝露は従来の規則で拒否する。

同じ時刻の「日照→荷重→擦れ」は別commandIdで受け付ける。
ただし、64件の窓が同じ時刻の途中で退去した場合、その時刻の未記録指示と古い再送は区別できないため、
新しい指示も安全側で拒否する。本体は極端な同時刻の大量指示をまとめるか、次の確定時刻で送る。
期限外の指示は成功扱いにせず、二重に傷めず、本体が状態を確認する。
commandIdは本体が一意に発行する。窓外の別縄へのID再利用まで恒久的に追跡する仕様ではない。

## 1件の処理

通常処理はヘッダー、対象の縄、最大64件のreceiptだけを検査する。
commands索引は直接参照し、無関係な縄・L.runs・L.lotsの列挙をしない。
台帳全体のstructuredCloneも行わない。対象一つを持つ小さな私有Ledgerで既存runnerの
startRun/commitを実行し、すべての検査に通った後で対象ロットと記録だけを置き換える。
収支・seq・worldVersion・新しいIDは旧版と同じになる。拒否は保存データを変更しない。

明示的なvalidateCordLoadLedger/compactCordLoadLedgerはロード境界の全体検査。
applyCordLoadもJSONから来た新しい記録オブジェクトには一度だけ全体検査を行う。
検査済みの同じオブジェクトはWeakSetで記憶し、履歴を毎回たどらない。
本体はロード時にvalidateCordLoadLedgerを呼べる。PR35のように直接JSONを戻す既存呼び出しも、
最初の荷重呼び出しで同じ検査と移行を受ける。

台帳は本体が所有する正本であり、操作はこのAPIを通す。保存後に記録を直接書き換える場合は
明示的な全体検査が必要。対象の記録は通常処理でもチェックサム・形・現存ロットとの一致を確かめる。
FNV-1aのチェックサムは事故による破損検知用であり、署名・認証・悪意ある改ざんの防止ではない。
全履歴から最新状態を再計算する代わりに、検証済みチェックポイントを保存の正本とする。

## /3の移行

host-3、run /3、ledger /3だけを読む。旧 /1・/2は引き続きunsupported-load-schema。
版名だけ/4へ変更したrecords形式や、旧物理binding・壊れたrunは拒否する。

1. /3の全履歴、対応する完了run、入力・出力の連鎖を元の整数モデルで一度だけ照合する。
2. 配列の元の順で、最新状態・時計・直近64receipt・廃止ID要約へまとめる。
3. 照合済み荷重runだけを取り除く。他工程のrunと予約は触らない。
4. ロット、ID、傷み、強さ、seq、worldVersion、既存のcommittedは変えない。
5. /4と形式マーカーを一緒にインストールする。以後は/3へ書き戻さない。

明示的な移行はその場で保存を更新する。最初のapplyで移行する場合は、
要求の検査・計算が成功したとき（または窓内の再送）にだけまとめて反映する。
無効な要求で失敗したときは/3のまま変更しない。
移行後も直近64件の再送は元の結果と一致。窓外は結果を復元せずexpired-commandで拒否し、
二重処理はしない。無制限の過去の結果を返す保証を、64件へ明示的に変更する。

/3の試験用実装はscripts/fixtures/coir-cord-load-v3.tsに基準mainから凍結して置く。
移行検査器の版は現行版の定数に追従させず、host-3/run-3に固定する。

## 本体との境界

applyCordLoadと住人用wrapperの引数・返却値は維持する。観察には数値や強度・記録を出さない。
PR35は作業中にmain 16e1a3841df8d1c4afd677c808f403e91ec48e50へ入ったため、
マージコミットで取り込んだ。実行時呼び出しは返却lotIdsと観察だけを使うため、そのまま動く。
同PRのテストのrecords直接参照は、cordsの直近receiptを読む検査用の写しに変更した。
本体の実行コードは変更せず、両方のfast検査を残す。帆の接続は行わない。

## 検証

scripts/cord-load-compaction-check.tsをfastに追加する。

- 凍結/3実装との逐次比較：ID・強さ・質量・seq・worldVersion・観察、切断と子片
- /3の80件→64件移行、古い再送の拒否、移行直後の切断ID、他工程run/予約の維持
- JSON復帰・再送・内容違い・同時刻の別指示・廃止IDの復活拒否
- 形・内部フィールド・版名だけの変更の拒否
- Proxyで無関係な縄へのアクセス、runs/lotsの列挙・全体複製を禁止する構造的検査
- 縄6本×365日=2190件。UTF-16保存量512KiB未満、窓充足後の増分20KB以内、完了runゼロ
- 初期/終盤の1件平均msを報告（CIの揺れを許す緩い検査）。計算量は上の構造的検査でも保証

タイミング値は実行環境に依存する。全体のJSON化やlocalStorageへの書込みそのものは本体の担当で、
ここで各イベントにつき測るのは荷重APIの処理。保存のロード全体検査と/3初回移行は件数に比例するが、
通常のイベントごとには繰り返さない。
