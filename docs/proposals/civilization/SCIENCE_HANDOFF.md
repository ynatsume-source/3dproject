状態：本体側（main）が採択した分担と、接続仕様の初版（2026-10-02）。判断は [ADR 0002](../../adr/0002-shared-world-and-science-core.md)、型は [`src/world/science-contract.ts`](../../../src/world/science-contract.ts)。
科学工程の設計案は `codex/creative-world-design`（c510246）の `docs/proposals/creative-world/` にある。82工程のカタログは概念案で、原典照合と数量・熱・時間・性能の校正は済んでいない。実行できる完成レシピではない。

## 1. 目指す世界と、守る原則

誰もが同じ島・同じ住民・同じ歴史を眺める共有世界。住民の性格や関心から創作が生まれ、使われ、直され、伝わることで島の歴史と文化が育つ。
科学文明の長期目標は、原料から器・レンガ・金属・電線・発電設備・照明まで作り、**自作の定置灯が初めて灯ること**。既製電材の回収で代替しない。既存ロボットの灯りや抽象的な電池値を、新しい電力の無償の供給源にしない。

- 作品は部品・接続・働き・作者・来歴として保存し、描画から分離する。
- AI は提案し、世界が材料・場所・支え・衝突・到達・時間を検査して確定する。
- 作品の働きが暮らし（移動・作業・保管・休息）に実際に効く。
- 材料は有限で、使用・劣化・修理・再利用を記録する。
- 利用や不便は、本人が知覚・会話で知ってから記憶へ返す。
- 施工・改修・工程の履歴を残し、あとから見返せる。
- 島の自然・静けさ・余白・描画性能を守る。
- AI は目的・計画・振り返りなどの節目で呼ぶ。全用途で月 15,000 円（科学側も別予算にしない）。

## 4. 接続仕様（初版 0.1.0）

詳細な型は `src/world/science-contract.ts`。要点だけ書く。

**呼び出しの形**：本体側が、ある工程の実行（`ProcessRun`）について、世界時刻の一区間 `[from, to)` ごとに `ScienceStep(request) → result` を呼ぶ。

| 本体側が渡すもの（request） | 科学側が返すもの（result） |
|---|---|
| `world`（worldId / worldEpoch / worldVersion）、工程の ID と版、カタログの版 | `state`：次の科学状態（温度・反応進行・蓄電量など。形式は科学側が定義） |
| `interval`：世界時刻の区間（ミリ秒・UTC・半開区間） | `simulated`：実際に計算した区間（工程が終われば短くなる） |
| `state`：前回の科学状態（初回は null）。本体側は中身を解釈せず保存・復元する | `consumed`：予約済みロットからの消費量 |
| `environment`：その区間の環境と出典（live / simulation / stale / unknown） | `produced` / `released`：生成物と、空気・水・地面への放出（質量の収支を閉じる） |
| `lots`：この工程に予約された材料ロット（これ以外は消費できない） | `energy`：供給元ごとの使用・損失・蓄積（熱・機械・電気を区別） |
| `equipment`：設備として使う作品・部品とその状態 | `equipmentWear`：設備の劣化 |
| `energy`：区間中に供給できるエネルギーの上限 | `observations`：住民が感覚や手持ちの計器で知覚できること（隠れた真値は入れない） |
| `actions`：区間中に住民がした操作（くべる、ふいごを踏む、止める…） | `status`：running / completed / failed / stopped / needs-input |
| `stop`：中断の理由（操作・世界の一時停止・設備喪失・停止） | `evidence`：評価器の版と根拠の出典 ID |
| `seed`：唯一の乱数源（本体側が引いて保存） | `diagnostics`：検証用。住民には見せない |

**守る規則**
1. **一度だけ確定**：本体側は `requestId` ごとに結果を一度だけ、材料・エネルギー台帳・工程状態・イベントと同じ transaction で確定する。再送には同じ結果を返す。
2. **純粋・決定的**：科学コアは時計（`Date.now`）、`Math.random`、ネットワーク、保存を使わない。同じ request には同じ result。
3. **区間の加法性**：`[a,b)` と `[b,c)` を続けて計算した結果と `[a,c)` を一度に計算した結果が、許容差の範囲で一致する。中断・再開・再送・区間の刻み方で結果が変わらない。
4. **収支が閉じる**：質量は `消費 = 生成 + 放出`（カタログに書いた許容差の範囲）。エネルギーは供給元ごとに `使用 ≤ 上限`、`使用 = 蓄積の変化 + 損失 + 仕事`。熱・電気は材料ロットではなくエネルギー台帳に記録する。
5. **単位とID**：台帳の量はその次元の最小単位の整数（mg・mm・mL・count・J など）。次元を混ぜない。エネルギーは実際に計算した区間で積分した J（1 Wh = 3600 J）。温度と電力は状態であって在庫にしない（科学状態と観測に入れる）。カタログの工程・材料・能力は、カタログのIDをそのまま使う（`p20_lime_calcination`、`quicklime` など）。世界に実在するものは種類の接頭辞つき（`lot:`、`eq:`、`run:`、`src:`、`env:`、`res:`）。
6. **版**：契約（semver）、工程（`processVersion`）、カタログ（`catalogVersion`）、評価器（`evaluatorVersion`）、状態スキーマ（`state.schema`）。知らない版には推測せず `failed` を返す。古い状態スキーマの移行関数は科学側が用意する。
7. **中断**：本体側の停止・再起動は運用上の一時停止で、工程の失敗として扱わない。停止中の熱履歴を後から作らない。再開時は保存した状態から続ける。
8. **見えること**：住民の記憶や会話に入るのは `observations` だけ。真の温度や反応率は、本人が計器を持ち、それを読んだときにだけ観測として返す。
9. **実行できる工程**：根拠と条件を確認した工程だけを実行可能にする。カタログの `concept-only` は実行しない。研究済みのフラグで、存在しない窯や発電機を使わない（設備は、いま実在し、検査に通り、空いている作品からだけ）。
10. **既存の電池**：既存ロボットの電池値（0〜1、Wh の容量なし）は `legacy / sealed_bootstrap` として扱い、エネルギーの供給元に換算しない。
11. **研究の取り置き**：試料・燃料・通常の歩留まりの損失は工程の前に予約する。その範囲内の失敗は普通の試行の失敗で、事故（向かい風）ではない。範囲を超えた損失や近くの設備の損傷だけが事故の扱いになる。

## 5. 二重計上を防ぐ線引き（統合時の確認項目）

- **材料**：科学側の結果は「予約済みロットからの消費案」。在庫を減らすのは本体側の確定だけ。科学側で在庫を持たない。
- **熱・電力**：燃料の燃焼は「材料の消費」と「熱エネルギーの供給」の両方に現れる。燃料ロットの消費は一度、熱の供給元（`src:`）への計上も一度にし、同じ燃焼を別の工程へ二重に配らない。電力は発電の工程が `storedJ` や供給元として記録し、使う側はその供給元から `usedJ` を引く。
- **再送・停止・復旧**：`requestId` による重複排除、区間の加法性の試験、復旧後に同じ区間を再計算しても台帳が増えないことを確認する。
- **既存の暮らしとの関係**：既存の採集・小屋・桟橋・石積み・会話・睡眠・ランタンの手帖を消さない。工程は住民の行動（実行器）の一つとして、睡眠や会話と時間を取り合う。

## 6. 最初に揃えたいこと（順番）

0. **前提**：科学側のコアと試験は、本体の完成を待たずに今から進められる。島の中で実際に工程を動かすのは、本体側の G2（共有世界の正本・材料台帳・予算台帳）の後。設計案の S0 も G2 を前提にしている。
1. **科学側**：工程カタログの原典照合を先に行い（設計案では外部資料がまだ一件も取得できていない）、少数の工程（例：乾燥・素焼きの試験片）で量・熱・時間と評価器を校正する。
2. **科学側**：`ScienceStep` の最小実装と、規則 2〜6 の試験（決定性・区間の加法性・収支・版）。本体に依存せず動く。
3. **本体側**：G0（時計・保存・環境・乱数・地形の adapter を `residents.ts` から抜き出す）と、材料ロット・予約・確定イベントの最小の正本。
4. **一緒に**：試験片の研究一周（材料を予約 → 工程を数区間進める → 住民が観測して記録 → 改良）を、閉じた試験世界でつなぐ。共有本番の履歴には混ぜない。

本体側の最初の創作（ドットの小さな共同作業場：材料→施工→ランタンの実利用→フィードバック→改修）は、科学側の完成を待たずに進める。
