# PR21：縄の段取りと台帳接続（第2段階）

## 受入対象と範囲

第1段階 PR22 8ec98037008d7ed4bacce54a34306085955669e8 の科学班受入を受けた、2026-10-16 の第2段階。既存 Ledger の予約・run・commit を使い、PR21 の乾燥、振るう、撚る、縒り合わせる、傷み・荷重をつなぐ隔離した実装。別の世界ホスト・時計・在庫は作らない。

科学班が段取りと表示データを設計し、Codex が実装し、科学班がレビューする。本体は行動の選択と実作業の確定、記憶・AI・3D・カメラを担当する。main統合、自動工程登録、住人運用、表示の見た目は行わない。

起点の科学モデルは aeabb0df57a2ae1a4e43d541340e1baa2b55b14a。PR21-C1 の run・ロット・目的を混ぜる乱数キー修正を含む。数値は引き続き明示的な owner-assumption/coir-cord/2026-10-15/v1 のキメ値であり、校正済みとはしない。PR20 の科学モデルと配分表、process-runner、接続仕様、src/robots は変更しない。

PR22-C1a（担当交代）・C1b（部分精算して片付ける）と灯芯は後続。C1a/b は住人運用前の残件のまま。縄の交代・途中取り出しも未実装で、stop は中断、予約と端数は残る。PR21-C2（浮動小数の傷み計算）は今回は変更せず、サーバー移行時の残件。C3 の湿った束の振るいはモデル上可能、本体は原則乾かしてからを選ぶ。

## 本体が渡すもの

src/world/coir-cord-work.ts：

- applyCordIntent：start / stop / resume と担当者、実時刻、材料ロット、場所、選んだ工程、在席。start は別引数にキメ値ID・作業場、乾燥なら roofed:true、撚るなら要求長さを明記する。
- recordCordSpan：手仕事は executor が確定した連続区間。活動、担当者、対象、在席、到着、両端の位置を検査する。途中で動きや活動が変われば本体が分ける。位置の両端だけから途中を推測しない。
- 乾燥は confirmed-roofed-wait。住人の在席は不要で、屋根の下にあった事実だけを渡す。roofed:false は進まない。予定時刻・経過時間だけを屋根や乾燥の事実にしない。
- すべての意図・executor区間は本体の世界時計。乾燥の区間だけ、既存 toClock('island', ...) で島時計へ変換して科学モデルへ渡す。本体が別の倍率を作らない。
- cordWorkRevision：本体用の排他更新番号。新しい書込みには一致が必要。同じID・内容の再送は更新番号が古くても変更なし。IDが同じで内容が違えば拒否する。

これは信頼された本体内 API。住人の文章、クライアントの任意の時刻、AIの予定を、材料の組成や確認済み作業へ変換してよい認証境界ではない。本体はワールド時刻順に意図を確定する。

## 作業と待ち時間

乾燥は島時計、その他は世界時計。両方とも累積した確認済み時間の30秒単位を科学へ渡す。30秒未満の端数は保存する。休憩・移動・不在・別の活動は手間へ加えない。中断から再開しても端数を失わない。

必要時間は既存キメ値と同じ整数計算で求め、最後の30秒単位を切り上げる。科学の生成量は既存モデルが終点で頭打ちにする。物理・配分を外挿しない。既に乾いている/髄を落とす必要がない時間0の工程は、明示した開始で一度だけ精算し、住人が働いたことにはしない。

作業場と材料は完了まで予約する。手作業で活動中の担当者は別の科学手作業へ同時に入れない。stopで担当者を解放し、材料・場所は保つ。乾燥中の担当者は自由で、別の作業場で手作業できる。

science-work-occupancy.ts の小さな共通確認で、PR22の殻と縄の作業の間でも二重使用を拒否する。PR22の段取りにはその確認の呼出だけを足した。殻の科学、区間処理、保存形式は変えない。その他の住人行動との競合は本体が実際のexecutor区間を正しく配分する。

## 保存・復帰・精算

cordArrangement は既存 Ledger JSON 内の更新番号・意図/区間の再送記録。run.state は civ-world.coir-work/1。runの中に入力の写し、意図の履歴、確認済み区間と科学状態を保存する。読取り時に科学を再構成し、入力・予約・状態・run・時計が一致するか検査する。restoreCordWork は同じ台帳に殻の段取りがあれば既存 restoreHuskArrangement も呼ぶ。手作業は復帰で最後の確認位置までの許可を閉じる。新しい再開意図と実働が必要で、オフラインを作業に数えない。

乾燥の待ち時間は住人の出勤ではないので復帰で中断しない。ただしロード自体は計算を進めず、保存後も屋根が継続したという本体の確認区間が必要。屋根が不明なら確認を渡さない。自己判断で天候や屋根を補完しない。

完了時だけ既存 commit で元ロットを全量消費し、繊維束、髄、撚り糸、縄、余った糸へ置き換える。乾燥で出た水は released の water_vapor → air に記帳する。髄と水は消さない。繊維を使い切って髄だけ残る微量の端も coir_pith として返す。途中の projection は作業途中の隠れた累積であり、在庫へ加算しない。長さの指定は本体用であり、住人へ未測定の長さを勝手に渡さない。

## 材料と隠れた性質

src/world/coir-cord-lots.ts は整数mgの成分と総重量を照合する。PR22が実際に返す coir_fiber_bundle の繊維・付着髄・成分別水を読める。新しい返却形式は成分合計を正本とし、既知のqualityキーだけを認める。未定義の性質を黙って落とさない。

撚り糸/縄は材料の quality に length_mm、base_strength_gf、sun_ms、shade_ms、abrasions、継承した見た目などを持つ。これは世界の隠れた真実であり、住人の知識・日記・UI・一般ログへ展開しない。縒るときは実際に残った3本の現在の強さを科学が読み、余りにも元の傷みを残す。来歴は入力の最小値を返却物へ継承する。

## 傷みと荷重

src/world/coir-cord-load.ts は本体が確定した日なた/日陰、擦れ、荷重イベントを既存PR21の傷みモデルへ渡す。強さの判定を二重実装しない。1イベントを既存台帳の短いrunとして一度だけ精算し、返ったロットIDを本体へ返す。以後は返ったロットを使う。

coirCordLoads は既存 Ledger 内の恒久再送記録と来歴の時計。ロード/切れた後も、同じイベントの再送で傷みや分割を重ねない。別IDで同じ曝露区間を重ねることや、返却後の時計を遡るイベントも拒否する。切れた片へカーソルと隠れた傷みを継承する。荷重が強さと同じなら切れず、超えた場合だけ科学の規則で切れる。微量すぎて2片に分けられない条件は既存モデル同様拒否する。

## 住人への出口とC2

readCordWorksite は段階、working/waiting/paused/completed/available、予約と担当者解放の真偽、理由、次の手順、目視の言葉だけ。重量、進捗、時間、強さ、乱数、配分表、IDを含めない。乾燥の屋根・経過時間の確認だけでは手ざわりを観察したことにならないため、乾燥の材料観察文は返さない。実際の触診をつなぐのは別の確認口が必要。

手仕事の working は最新の実働確認時刻でだけ表示し、後は現在の実働が未確認になる。readCordWorkerObservations は実際に作業を確認できた担当者だけに手ざわりの言葉を返す。読むだけでは新しい作業・日記・記憶は作らない。

内部拒否は一定のメッセージと本体用 code。cordFailureObservations は別の公開用出口で、例「繊維が湿っていて、撚れない」。具体的な感覚を返すには、開始を頼んだだけの在席とは別に、host-confirmed-on-site-attempt を本体が確定する。省略すれば「作業場で材料を確かめたい」の一般的な言葉だけ。エラーやprojectionをそのまま公開してはいけない。傷みの住人向けwrapperも数値・ロットIDを返さない。
