PR20 の科学受入 commit は 66232acafeec38d72830be9268d6d20e79dbe2a2。本変更は科学の中核・配分表を変更せず、既存 PR22 の台帳境界に段取りを加える。PR21 への展開と C1 の乱数キー修正は次段階。

PR18 8b995cf3a8d7dde80d56b7797c5fdbccd3246c24 の設計文書だけを参考にした。コードは引き継がない。待ち時間と実働の分離、中断後の継続、一度だけの予約精算、予定と科学的準備の区別を採用する。本工程には浸水・乾燥の待機モデルを追加しない。

## API と信頼境界

実装は src/world/manual-husk-workflow.ts。既存 Ledger に optional manualHuskArrangement を保存し、別の在庫・時計・保存システムは作らない。

- applyHuskIntent：本体が既に選んだ start / stop / resume、actor・工程・材料・場所・在席を受ける。開始時は別引数の権威ある組成・来歴と版付きキメ値 ID が必須。自然言語や在席だけでは作業にならない。
- recordHuskWorkflowSpan：本体 executor が確定した連続手仕事・休憩・移動などを受ける。開始・再開から中断までの窓を越える手仕事は、呼出側が分ける。端の位置だけから途中の動作を推定しない。
- huskArrangementRevision：本体専用の排他更新番号。新しい操作には一致が必要。同じ ID・同じ内容の再送は古い番号でも変更なし。内容の違う同じ ID は拒否する。
- restoreHuskArrangement：実際のロードで一度呼ぶ。保存された区間の端で在席の許可を閉じ、予約・端数作業は残す。復帰時刻より前へ新しい意図を遡らせられない。再開の意図と新しい実作業の確認が必要。
- readHuskWorksite：表示用の語・状態のみ。現在時刻は本体から渡す。読み出しは作業・在席・在庫・知識を変更しない。
- readHuskResidentObservations：実作業が確認された担当者だけに見た目と手ざわりの文を返す。自動の日記・記憶への書込みはしない。
- readHuskMaterialLabel：材料 ID を許可リストの呼び名にするだけ。quality の展開は禁止。

これは信頼された本体内 API であり、認証 API ではない。住人や外部入力が actorId・時刻・実作業区間を偽装できる接続は認めない。本体はワールド時刻順に意図を配送し、移動・休憩・中断で区間を切る。

## 段取りと精算

殻1個・1run。開始で殻を予約し、同じ作業場の並行利用と同じ住人の二重手作業を拒否する。開始時に不在でも予約は可能だが、手仕事は確定されない。

実働の累積だけを30秒単位で科学へ渡す。30秒未満の端数も保存し、中断後の手仕事と合算する。stop は取消・部分精算でなく「手を離す」。担当者は他の行動に移れ、殻は予約されたまま残る。第1段階の再開者は元の担当者に限る。交代は未設計。

中断より前の確定済み事実は遅れて配送できるが、区間全体が当時の許可窓内である必要がある。それによって現在の在席は復活しない。完了後の再送は再精算しない。完了時だけ、既存 commit 境界を通じて入力を消費し、繊維束・残った殻・作業で出た水に置き換え、予約を解く。中断やロードは消費しない。

手仕事をした瞬間の表示は、最新の確認区間の confirmedAt と表示時刻が同じときだけ working。それより後は現在の実働が未確認の waiting。これはアニメーション継続の推定ではない。operatorFree はこの段取りで別の科学手作業を受けられるかのデータであり、3D の移動をロックしない。stop または完了で解放する。

## 表示と隠れた値

公開 view は題名、段階、working / waiting / paused / completed / available、予約と担当者解放の真偽、止まった理由、次の手順、目視の文。重量、時刻、所要時間、進捗率、ID、配分表、seed、quality、強さを含めない。手ざわりは担当者への別出口。作業前に読んでも新しい観察は作らない。

観察文は保存された自由文から返さず、既存境界が再検査した実作業・実際の物から生成する。段階が終わったことから、乾燥済み・芯に使用可・次工程の準備完了とは言わない。数値を量るには既存の秤量が必要。

材料の隠れた性質は Ledger.lots の quality に残す。台帳・world 専用の projection・意図・executor 事実を、住人の知識、日記、UI、通常ログへそのまま渡さない。本工程の既知成分以外の性質を他の材料へどう継承するかは工程別の契約が必要であり、本段階で縄の強さを生成しない。

## 保存と失敗

段取り schema は civ-world.manual-husk-arrangement/1。意図、許可の履歴、再送の receipt、更新番号を既存 Ledger JSON に含める。科学の状態 schema は変更しない。段取りが欠けた旧 PR22 run を黙って活動中に移行しない。旧実験保存は明示的に拒否し、レビュー後に別途移行を判断する。

ワールド・run・材料・予約・履歴の不整合、未来の事実、古い更新番号、競合を変更前に拒否する。変更はコピー内で行い、全体検査後に反映する。エラーの文は一定で、材料や隠れた値を埋め込まない。保存形式は任意の協調改ざんを防ぐ署名ではない。

全履歴の照合と Ledger コピーを行う試作境界なので、3D の毎フレームから呼ばない。確定済みの連続区間で呼ぶ。production の履歴圧縮・移行・権限は本体接続時の別判断。
