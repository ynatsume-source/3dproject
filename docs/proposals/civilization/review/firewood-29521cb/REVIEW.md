## A1：既知として受け付けた低温でEMCが負になり、木を水蒸気として失う

対象：`src/science/step/firewood.ts:30–36,91–104,138–157`。
`envUsable` が受け付ける−60 °CでHailwood–Horrobin式を外挿すると、RH95%のEMCは **−0.49469584 kg/kg(dry)**。
`allFinite` は負の水を止めず、蒸発量にも実在する水の上限がない。

再現：4,000,000 mgの薪、`water_ppm:0`、太さは既定60 mm、屋根あり、−60 °C・RH95%・風2 m/sで1時間後にoperator停止。

| 出力 | 値 |
|---|---:|
| 初めの水 | 0 mg |
| 蒸気 | 47 mg |
| 環境からの熱 | 114 J |
| 返却薪の質量 | 3,999,953 mg |
| water_ppm | −11.750138… |

検査器違反は0でも、返却薪は `fuelComp` が拒否する。単なる端数誤差ではなく、水のない薪から物質を蒸気にしている。
島の通常気候で起きるという主張ではないが、現状の工程が「既知」として受け付ける入力で物質の意味を壊すためAとした。
気圧計で合意したように「この島には来ない温度」を暗黙の保証にしない。

対応案：**この式・乾燥モデルの適用温度域を明示し、その外は未計算・来歴不完全、または理由つき拒否とする**。
EMCが有限かつ非負で、水も0以上、累計蒸発が初期水＋取り込んだ雨以下になることを不変条件として検査する。
EMCを単に0へ切り上げても、極低温の乾燥を物理的に保証したことにはならない。凍結・氷との平衡も今回のモデルにはない。

回帰は水0の入力と、返却物を次のrunへ渡す形を含める。通常の質量合計チェックだけでは不十分。
診断：`result.json → findings.cold / emcDomain`。

## A2：風速だけ欠測すると、無風を補って計算し、来歴を完全とする

対象：`src/science/step/firewood.ts:91,95–97,116,153`、呼び出す `common.ts:155–159`。
屋根なしの雨量欠測は止めるが、乾燥速度に必要な `windMs` の欠測は止めない。
`wind10m` の `windMs ?? 0` により、測れていない風を無風へ置き換える。

再現：4 kg、水45%、60 mm、屋根あり、28 °C・RH75%のrecordから**風速のフィールドだけを外す**。
40日後に止めると、風0 m/sを明記した対照と完全に同じ結果になり、`history_complete:1` と観察を返す。

| 風速の入力 | 蒸発 | 返却薪の水（湿量基準） | 39日目の観察 |
|---|---:|---:|---|
| 欠測 | 1,008,599 mg | 26.46% | ひびが出て少し軽い |
| 明示的な0 m/s | 1,008,599 mg | 26.46% | 同上 |
| 明示的な20 m/s（比較用） | 1,426,952 mg | 14.50% | 乾いて軽い・乾いた音 |

20 m/sが40日続く現地天気を想定した比較ではなく、欠けた値で結果が変わることを示す対照。
実測の再生に欠測があっても、計算・観察が確定したことになるのが問題。

対応案：この工程のknown判定で風速の存在も要求し、未計算・来歴不完全・以後の観察抑止へ回す。
0 m/sが明示されている場合は今までどおり計算する。風速計の高さ省略時10 mという明示済みの規則とは別問題。
共通関数を変えて他工程へ広げる必要はなく、まずp15の必要条件として扱える。
診断：`result.json → findings.missingWind`。

## C1：RH99%で打ち切る処理はWood Handbookの式にはない（非保留）

対象：`firewood.ts:35` の `Math.min(h,0.99)`。
原典の式4–5ではhは0〜1。係数と式の組み立ては一致するが、この上限は追加の仮定。
28 °C・RH100%では、原式が乾量基準 **28.4869%**、実装は **27.3220%**。
特別な理由で残すなら、原式そのものと区別して手順書に記す。理由がなければ削除を検討する。
これだけでは統合を止めない。なお、式がh=1で有限だからといって、液体水・飽和空気・凍結まで正確にモデル化できるという意味ではない。

## 依頼された3点への回答

### 式と約4か月の乾燥

**係数の転記は正しい。乾燥速度の校正はまだできない。**
[Wood Handbook 2021 第4章](https://research.fs.usda.gov/download/treesearch/62243.pdf) の式4–5を本文で照合。
Table 4–2の361点との差は最大0.0572百分率ポイント（表示は0.1刻み、温度も丸めて表示）。
分母W、K・K1・K2、最後の百分率→比への `/100` は正しい。C1と低温外挿は別に扱う。

28 °C・RH75%でEMCは14.0945% **乾量基準**＝12.3534% **湿量基準**。
4 kg・初期水45%・τ30日の120日後は湿量基準13.2960%（乾量基準15.3349%）。
独立な一次遅れの閉形式と蒸発1,462,632 mgが一致した。「EMC約14%」と「4か月で水約13%」は同じ基準の数字ではない。

温暖な環境の小割り薪についての試験設定として採用できるが、実測で裏付けた標準日数とは呼べない。
[Maryland大学の実測報告](https://extension.umd.edu/sites/extension.umd.edu/files/publications/MeasuringWoodMoisture_FS-1074.pdf) は樹種差と内部の乾きの遅れを示すが、計器の%をこのモデルの湿量基準へ直接換算する根拠が不足する。
[Fortierほか2021](https://www.mdpi.com/1999-4907/12/2/122) の出版社抄録等では、40 cmの割った薪が1年後に屋根あり17.3%、なし20.7%（湿量基準）。島の気象や60 mmの太さには対応していない。
これらからτ30日を実測値として採択したり、一律6か月へ変更したりはしない。

太さ²は内部拡散が律速する近似として理解できるが、長さ・木口・樹皮・樹種・自由水と結合水・山の通風を省いたまま、全寸法へ普遍化しない。
日射で木温を上げ、同じ水蒸気分圧から局所RHを求める式の方向は妥当。ただし+15 Kと速度の倍増率は未校正。
`sunExposure`を固定して長期間与える試算は、昼夜の日射・蒸発冷却を解いていない。
湿った空気からの吸湿を省いているので、現状は「平衡へ両方向に戻るモデル」ではなく、一方向の乾燥モデル。長期では乾燥側へ偏りうる。

### 雨をdrawnで取り込むこと

**0.2.xの使い方として妥当。** 周囲から来た液体の雨を `rain_water`、経路を `from:'air'` として記録してよい。
水蒸気を取り込むこととは区別される。1 mm×1 m²＝1 kg、mgと秒への換算も正しい。
供給された雨のうち実際に吸った分だけを計上し、吸わなかった雨をロットから再放出して二重計上しない。
中間状態へ貯め、終了時に一度だけ `薪＋drawn雨＝返却薪＋released蒸気` で精算する形も契約と一致する。
未終了の時点で雨や蒸気を再度精算する必要はない。

3割の捕捉・乾量基準0.6の上限は仮定で、0.6は湿量基準37.5%。上面積は実際の山に合わせて本体が指定する。
潜熱の整数Jは、累計の整数蒸気mgから求めた値の差分になっている。
雨の顕熱・濡れ熱・吸着熱・器体の熱容量を含めた全熱モデルではない。潜熱分だけの近似という説明を維持し、総必要熱の校正値にしない。

### 丸めないwater_ppm

**今の `fuelComp` の `Math.round(M×water_ppm/1e6)` と組にする限り適切。**
整数mgに精算した水から比を作り、整数ppmへ切り捨て直さない。
通常温度で返却薪を吸水→乾燥へ144回つなぎ、木・灰のmg不変、水の読み戻し、整数質量収支を確認した。
1,000,000 mgを超える量や灰の多い薪も含む。A1の負の水は、この比の保存方法では防げないので別途修正する。
本体がqualityを保存するときにも、ppmを整数へ変換しないこと。
