## C2：荷重時の現在強度を統一する

`src/world/coir-cord-load.ts` は `createIntegerCordDamageModel` を使う。帆のvoyageが選ぶのと同じ `owner-assumption/integer-half-life/2026-10-15/v1`、同じdamage /2、同じbinding、同じ累積傷みから荷重の結果を求める。荷重が強度を**超えたときだけ**切れ、同値なら切れない。

材料には初期強度と日なた・日陰・擦れの累積がある。現在強度のキャッシュは保存していないため、材料のcodecや既存ロットの質量・水・長さの形式は変えない。切れないときは同じID、切れたときだけ二つの新ID、子片の成分・傷みの引継ぎ、観察の範囲も維持する。

旧互換API `currentCordStrength/createCordDamageModel` は、受入済みの隔離試作とその互換検査のため残す。受入済み製造のplyは、元の糸から**新しい縄の初期強さを一度決める**従来の製造仮定のまま。これは製造済みの同じ縄の荷重時に別の現在強度の式を選ぶ経路ではない。今回、製造の数値は黙って変えない。帆と世界の荷重の現在強度は、どちらも整数モデルになる。

## 保存と拒否

- 工程 `prototype_coir_cord_load` は `host-3`。
- run状態は `civ-world.coir-cord-load/3`。
- Ledgerの荷重履歴は `civ-world.coir-cord-load-ledger/3`。
- 内部のdamage状態は `prototype-coir-cord-damage/2`。bindingに整数policy IDを含める。
- 旧ledger /1・/2は `unsupported-load-schema` として拒否。旧run /1・/2やhost-1/2、外側だけ/3にした旧damage、damageのschema文字だけ新しくした旧bindingも、変更前に拒否する。
- 旧保存を破棄したり、過去のイベントを新しい式で勝手に再実行したりしない。移行は実装していない。本体が拒否を受けた場合は、この履歴を新しい荷重処理へ渡さず保存しておく。別途承認した移行なしに履歴を消して再開しない。

荷重の各runは1イベントを一度精算して完了するため、未完了runの予約を解放して済む移行ではない。既存の履歴・ロットをそのまま保つ明示拒否を選んだ。
