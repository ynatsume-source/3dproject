# 葉の干し直し：残った余分な水に比例する待ち時間

この変更は main `174fc320024a3ff97ad8b4df2d364ca16844126a` の科学班通し検査で見つかった、ほぼ乾いた葉を取り込んで再び干すたびに島時計の丸２日を要する問題への対応です。住人の判断や動作は変更しません。

## 明示する仮定

新しい乾燥だけが、版付きの仮定
`owner-assumption/sail-leaf-drying/2026-10-21/v1`
を選びます。科学の factory の第４引数と、世界側の開始 facts の `dryingPolicyId` に渡します。世界側ではこの明示指定がない新規 dry を拒否し、本体の既存の干す入口はこの値を渡します。帆走の `v2-island` / `v2-world` の ID、時計、速さ、力、強さは変えません。

入力の乾物を D mg、水を W mg、島時計の２日を T = 172,800,000 ms とすると、新しい待ち時間は次です。

```text
ceil(max(0, 5 × W − D) × T / (9 × D)) ms
```

計算は掛け算の前から BigInt を使います。これは余分な水 W − D/5 を、生葉の余分な水 1.8D と比べた比率です。水が D/5 以下なら待ち時間は０、正の待ち時間は切り上げて最低１ ms にします。非常に濡れた入力も同じ比率なので、２日を上限にはしません。安全な整数の範囲を超える待ち時間は拒否します。

水が減る計算と終点は以前のままです。開始時の水から `floor(D/5)` まで、確定した時間に対して直線に減り、各時点で整数 mg に切り捨てます。もともと終点以下の水は増やしません。D が５で割り切れない場合も、待ち時間の基準には丸める前の D/5 を使うので、水が 2D の生葉はちょうど２日です。終点の整数化による差は１ mg 未満です。

例：乾物 1,000,000 mg、水 201,009 mg の入力の所要時間は島時計 96,864 ms です。世界側が従来どおり島時計の30秒単位で待機を確定すると、120,000 ms を確定した時点で完了します。途中まで干して取り込んだ葉を次に干すときは、その時点の水から再計算します。再投入による最大１ mg 程度の整数化は、待機区間を同じ run 内で分けることと区別します。

## 保存との境界

- 新しい dry は工程 `host-3`、状態 `civ-world.sail-work/3` です。状態と開始 facts の両方に上の仮定 ID を持たせます。
- dry 以外の工程は引き続き `host-2`、状態 `civ-world.sail-work/2` です。工程版から作る seed も変えません。
- 保存済みの `host-2` の dry は以前の「終点より湿っていれば丸２日」で読み、途中の水分と進捗を保って続行します。`host-1` の移行先も旧来の `host-2` のままです。
- 科学の３引数 factory は従来の意味を維持します。新しい仮定を明示した compact checkpoint だけを `prototype-sail-manufacture/3` にし、仮定 ID を binding に含めます。旧 compact checkpoint は `/2` のままです。
- 旧保存の版名だけを `/3` に変えても、仮定 ID と厳密なキー・checksum が一致しないので受け付けません。逆方向の付け替えも拒否します。
- 台帳の保存形式、精算、材料の予約、観察の言葉、30秒未満の端数の扱いは変えません。

## 検査

既存の fast 検査に次を追加します。

- 生葉・ほぼ乾いた葉・既に乾いた葉・奇数 mg・最低１ ms・非常に濡れた葉の BigInt 参照式との一致、単調な乾燥、水と乾物の整数収支。
- 200入力の区間分割・JSON checkpoint 復帰・同じ確認の再送。
- ほぼ乾いた葉の取り込みと再乾燥、および単一・複数の葉ロットの収支。
- main の世界側コードを frozen fixture にして作った本物の旧 `host-2` 保存が、旧２日ルールでそのまま完了すること。
- 旧新状態の版名だけの付け替えの拒否、明示した仮定のない新規 dry の拒否。
- dry 以外の４工程の開始・進行が frozen main と台帳全体で一致すること。
