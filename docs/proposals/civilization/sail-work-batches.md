# 帆材料の複数束処理（sail-work host-2）

既存の dry と weave の意図が、同じ場所にある同種の複数ロットを明示的な lotIds で受け付ける。
dry は pandanus_leaves、weave は pandanus_strips に限り、harvest・split・mast は従来どおり1ロット。
全ロットを一度に予約し、質量と水を BigInt で合算した1つの混合束として既存の科学モデルに渡す。
仮想束は台帳へ追加しない。決着では実在する全入力を一度だけ消費し、製品と余り1束を返す。
余りの水・乾物の配分は既存のモデルの整数の差分で閉じる。
乾燥の目標は floor(合計乾物 / 5) で、束ごとの切り捨てを足すものではない。

IDは並べてから予約し、複数束の仮想IDには並べた全IDを含める。
入力順を変えても同じrun・seedでは強さを含めて結果が同じになる。
1ロットのときは元のsourceをそのまま使い、既存の配分・丸め・乱数を変えない。
来歴は1つでも不完全なら全出力も不完全。数値と強さは住人への観察へ出さない。

作業版は host-2、状態 civ-world.sail-work/2。段取りの記録形式は /1 のまま。
旧 host-1 / civ-world.sail-work/1 は元の形とチェックサムを確かめてから sources:[source] に移行する。
実働・30秒未満の端数・予約・担当履歴を保ち、保存を閉じていた時間を手作業に足さない。
版名だけの付け替えと壊れたチェックサムは拒否する。

本体の既存の干す／編む意図は、目的の作業場・干し場にある束を優先する。
編む選択肢の既存の量の検査は束ごとでなく同じ場所の合計へ適用し、足りない群は提示しない。
編む場合は十分な同一場所の群、干す場合は最初の同一場所の群を一緒に運ぶ。
別の場所・予約済みの束は含めず、科学側の開始が拒否されたら移動を戻す。
選択肢・判断・記憶・3D・カメラは変更しない。

検査は sail-work-check に追加。端数のある複数束の収支、途中の片付け、
入力順、2番目の予約ロットの改変拒否、9束の葉を既存の干す意図で扱うことを確認する。
不足時の選択肢を止める main 141f14ad の検査も、単独・合計・別の場所の3群で維持する。
旧状態は main 4cf2af68 の sail-work の凍結コピーで実際に作って JSON 保存し、移行後を比較する。
