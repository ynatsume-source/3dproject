# PR20の本体境界：殻1個の確定手作業

2026-10-15。PR20科学受入済み `66232acafeec38d72830be9268d6d20e79dbe2a2` からの接続案。科学班の境目レビュー待ち。mainへの統合、住人での運用、UI・行動・記憶への配線は今回行わない。

## 今回つなぐもの

`src/world/manual-husk-work.ts` は本体の既存 `Ledger`、`startRun`、`commit` を使い、PR20の純粋計算を在庫・予約・JSON保存へつなぐ明示選択の部品である。別の世界時計・在庫・台帳・ScienceStep入口は作らない。PR20の中核と仮定表はバイト単位で変更しない。

通常の工程カタログ・科学入口・住人の `tickLab` には登録しない。自動実行では、task/runIdの一致だけで在席扱いになること、保存時にtaskを持たないこと、日誌と棚の公開viewに未秤量g/kgが出ることが現状の課題だからである。本部品はheadlessで境目を具体化する。実住人への認定処理と汎用在庫公開viewは、運用判断後に改めて配線する。

基準mainは `c29829f53a2e19852ced6650ecefdff34473edbc`。PR12/18の別試作、PR21の縄実装を取り込まない。

## 明示入力

`beginManualHuskWork(L, spec)` に必須：

- `commandId`、担当者の `operatorId`、`openedAtWorldMs`。
- 仮定ID `owner-assumption/manual-husk/2026-10-15/v1`。省略・未知の版を拒否する。
- `huskCount: 1` と、PR20の `WetUnseparatedHusk`（正確な乾物mg、水mg、未分離であること、浸漬来歴）。個数と乾物を湿重量から推測しない。
- 作業地点 `worksite` のlocationId・x/z・手の届く距離reachM。距離はホストが実際の配置から明示する値であり、収率の科学係数ではない。

同じlotIdがLedgerの棚にあり、材料が `wet_unseparated_coconut_husk`、場所が作業地点、質量が乾物＋水と一致することを要求する。qualityにも正確な `dry_mg`・`water_mg`・`husk_count:1`・`unseparated:1`・`history_complete:0|1` が必要。一般の `coconut_husk` は受け付けず、自動変換しない。2個まとめたロットや、分離途中の残殻を新品として打つことも拒否する。

beginは元lot全量を既存runに予約する。同じcommandId・同内容の再送は、完了後も同じrunIdを返す。競合内容は拒否する。

## 実作業の認定

`recordManualHuskSpan(L, runId, span, nowWorldMs)` に渡すのは、本体のexecutorが**区間全体**について確定した `executor-activity-span` だけである。AIの計画文、taskの残り時間、アニメーション、経過時計、天気記録は代わりにならない。

以下がすべてそろった区間だけ実作業とする：

- 担当者・run・殻lot・作業地点が一致する。
- 到着済みで、実際の活動が `separate-wet-husk`。
- 区間の両端の位置が作業地点の手の届く範囲にある。
- executorが途中の移動・会話・休み等で区間を切っており、その全体が同じ活動だった。

端点が近いだけで、途中の在席を推定する契約ではない。ブラウザやLLMからこの型を直接送って認定できるAPIは作っていない。将来の実住人接続では、到着後の実作業分岐で認定し、移動・会話・睡眠・停止・行動変更で区間を閉じる。task.tは移動やwearSlowの影響を含むので使わない。

休み・移動・不在・別担当者・別の殻・未到着・風景の再生は作業を増やさない。欠けた時刻も補わない。完了していない未来の区間、別世界/run、時間の逆行・重複は拒否する。

## 30秒単位と時計

30秒は**累積した実作業時間**の単位であり、30秒の世界経過や島時間ではない。たとえば20秒働く→13秒休む→10秒働くと、30秒分だけ確定する。科学側へは20秒と10秒の実区間を別々に渡す。休みを含む43秒の連続作業へ置き換えない。

30秒未満の実作業片はpendingとしてRun.stateに保持する。休み・保存・再開をまたいでも失わない。単にJSONを復元しただけでは、新しい在席も作業も生まれない。オフラインの空白は作業0で、再びexecutorが認定するまで進まない。

PR20の計算には物理積分の格子がない。この特殊runだけ、既存startRunの「次の30秒境界」を、明示された実openedAtに合わせる。ほかの工程の格子・開始規則は変えない。開始直後の実作業を捨てず、未来分も先取りしない。

標準殻は240,000 msで8単位。乾物比例で縮尺した科学表の終点が30秒の倍数でなければ、ホストの必要手作業を次の30秒単位へ切り上げる。収率は科学表の終点で止まり、外挿しない。大きなspanが完了時刻を越えても、最後に必要な単位が実際に終わった時刻でrunを終える。

同一の物・作業を異なる頻度で採取しても、配分・確定作業量・端数・物の観察・終端精算は同じになる。生spanの区切り、報告が届いた時刻、監査履歴そのものの同一性は保証しない。科学のconfirmedAtにも実際の認定時刻を残し、遅れて届いた報告の時刻を早めて捏造しない。

## 保存・再送・精算

Run.stateの `civ-world.manual-husk-work/1` に、入力・仮定ID・元lotの全コピー・世界/runのbinding・生span・科学state・pendingを一緒に保存する。復元時は元入力と全spanから計算し直して保存内容と照合する。状態の形や版、計算済みの値を勝手に付け替えて再開しない。

処理前には元lotの予約・量・quality・場所を全字段で照合する。終端後の新しいspanを拒否する。同じspanId・同内容の再送は完了後やJSON復元後にも無変化。ID競合は拒否する。グローバルcommittedの500件制限だけに再送防止を頼らない。

入力検査と計算はstructuredCloneしたLedger上で行い、既存commitの検査が通った結果だけを同じ同期操作で反映する。エラー時は元Ledgerを変更しない。無関係なlot/runは変更しない。

完了前は元lotが予約されたままで、物を区間ごとに増殖・消費しない。完了時だけ元の殻を全量消費し、以下へ一度だけ置換する：

| 出力 | 正確な内部成分 | 注意 |
|---|---|---|
| coir_fiber_bundle | fiber_dry_mg・attached_pith_dry_mg・fiber_water_mg・attached_pith_water_mg・water_mg | 付着髄を消さず、PR21へ渡せるmgを保持 |
| partially_separated_coconut_husk | dry_mg・water_mg、unseparated:0 | 未分離新品の殻として再投入しない |
| husk_drainage_water | water_mg、unclassified_drainage:1 | 真水process_waterへ改名しない |

全出力が元のhistory_completeを引き継ぐ。乾物・水をppmに変えて読み戻す丸めは入れない。標準殻900,000 mgは、繊維束201,600＋残殻518,400＋排水180,000 mgで閉じる。

休みやshutdownをstop:operatorへ自動変換しない。本部品は明示的な休止操作を必要とせず、次の認定区間を待つ。既存のgeneric advance/abortを本runの作業確定として呼んではならない。版が変わって中止する場合の予約解放は本体の別判断であり、保存からの通常再開とは分ける。

## 観察の公開範囲

`projectManualHuskWork` とRun.stateは世界専用。配分、残存量、作業総量、仮定、質量を住人へ渡さない。`observeManualHuskWork` とrecordの返答は、見た目・手ざわりの観察だけを返す：

- ほぐれた繊維が束になっている。
- 残った殻に筋がついている。
- 繊維と殻がしっとりしている。

数値のvalue、未秤量のg/kg、ETA、配分表は含めない。重さは別の秤量と対象lotに紐づく記録で知る。入力lotの秤量を新しい生成物へ自動継承しない。

既存の棚のkg一覧・開始/終了日誌へ本出力を流す配線は今回作らない。実運用の前には、これらの経路にも専用公開viewを接続するレビューが必要である。
