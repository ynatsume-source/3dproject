## W3b [P2] 工程自身が返した薪が水分・灰分の上限を超え、次の工程で拒否される

対象: `src/science/step/wood-fire.ts:198–204`（返却）と `56–64`（読み取り）。

部分ごとに整数mgへ切り上げると、残りの成分比が変わります。
返却時の比率を小数のまま残す変更は成分を正確に表しますが、
生成側は水分80%・乾量基準の灰分20%の上限を保証せず、読み取り側はその上限を厳密に検査します。
そのため、許可された薪から、同じ工程が読めない `firewood` が作られます。

### 再現1: 上限内の1 kgの薪を1 msで停止

前回と同じ試験用薪窯・試験片・計画で、薪を次に変更します。

```text
amount: 1000000 mg
water_ppm: 800000
ash_dry_ppm: 10000
interval: [0, 1) ms
stop: operator
```

結果は `stopped`、14 J。返却薪は次のとおりです。

```text
amount: 999994 mg
water_ppm: 800000.8000048001
ash_dry_ppm: 9995.09995099951
```

質量とqualityをそのままJSON往復して次の新規runへ渡すと、
`firewood ... needs quality.water_ppm (0–800000, of the whole lot)` で `failed` になります。
これは浮動小数の誤差だけではありません。水799,996 mg、灰1,999 mg、可燃分197,999 mgという整数の残量自体が80%を超えています。
前後とも `validateResult` の違反は0なので、本体が結果を確定してもこの不整合を検出できません。

### 再現2: 前回の水分60%からも反復で到達

前回と同じ初期薪 `1000 mg / water_ppm:600000 / ash_dry_ppm:0`、設備の `maxBurnKgPerH:1`。
各runを1 msで停止し、返却ロットの質量・qualityを次へ渡します。区間・操作時刻は `[i,i+1) ms` に合わせます。

| 時点 | 結果 |
|---|---|
| 初期 | 水600 mg、可燃分400 mg |
| 20回後 | 水580 mg、可燃分380 mg、熱21 J・O₂20 mg。W3aの修正を確認 |
| 334回後 | 返却332 mg、水266 mg・可燃分66 mg、`water_ppm:801204.8192771084` |
| 335回目 | 返却薪が水分上限を超えているため、無消費で `failed` |

上限を60%から80%へ動かすだけでは、このケースを解消できません。

### 再現3: 灰分にも同じ問題

薪 `8 mg / water_ppm:0 / ash_dry_ppm:200000` を5 msで停止すると、
返却は `4 mg / water_ppm:0 / ash_dry_ppm:250000` になります。
次のrunは `ash_dry_ppm must be within 0–200000` で拒否されます。
入力のmg換算では灰2 mg・可燃分6 mg、返却は灰1 mg・可燃分3 mgです。

**必要な修正:** 生成する全残余組成を、対応する材料と読み取り規則で再び正確に読めるようにしてください。
例えば燃料を読む範囲と「燃えるか」の判定を分ける、薪として扱えない残余を別の材料として返す、などの方針が考えられます。
比率の上限へのクランプで水・木・灰を入れ替える方法や、残った可燃分の黙った廃棄は避けてください。
回帰には、上限そのもの・水分60%からの長い返却連鎖・灰分・可燃分が尽きる境界を含めることを勧めます。

## 確認できたこと

- **W3a:** `halfWater` は可燃分1 mg・O₂1 mg・8 J。前回の20回連鎖は可燃分20 mg・O₂20 mg・21 J。発熱は精算した可燃分の発熱量以下です。
- **熱の定義:** 標準の1時間で `cumUsedJ = 37100332.44467585`、燃えた可燃分×18 J/mgからの独立計算は `37100332.44467586`。整数報告は37,100,332 J。薪の水分の蒸発を損失側へ移す変更を確認。
- **W4a:** 成形で `constructor / toString / __proto__` を無消費で拒否。`lotComp` と `tileComp` を直接呼ぶ6条件もすべて拒否。通常の成形は維持。
- **W1・W2・W5:** 前回診断を工程版 `0.1.2` で再実行。初回の設備喪失は例外なし、36種類の拒否はcontractとdrawnの形式を維持、来歴4組合せは `1,0,0,0`。
- **追加1296条件:** 薪量12種類×水分6種類×灰分3種類×停止時刻6種類。例外・検査器違反0。読み戻せた1081条件では発熱の可燃分上限超過0、返却を読めない215条件は上記W3b。境界を重点的に選んだ数であり、実運用での発生率ではありません。
- **既存の7組成条件:** O₂込みのmg収支が一致。
- **電気窯:** 切り出し前 `7da1db7` と通常・7.3秒刻み・途中停止・強制冷却・割れ2の5条件で、各区間の全結果JSONのSHA-256が一致。

薪の標準条件（60 kg・橙）では、30秒 / 1時間 / 7時間刻みの熱は492,209,383 J、終了時刻39,570,000 msで一致。
7.3秒刻みは493,260,581 J、39,630,000 ms。焼成品はいずれも33,692 mg。
熱の定義変更で総Jは旧版より増えますが、前回診断の6刻みすべてで温度等のdiagnostics・焼成品・終了時刻は旧版 `65aa96b` と同一でした。
分割誤差は既存の許容範囲内です。
