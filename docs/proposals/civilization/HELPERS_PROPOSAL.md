# 小さな手伝い：小ガメと小ラッコ（提案）

2026-10-03 / オーナーの着想を科学側（Claude）がまとめた案 / **未採択の提案。正式な仕様として扱わない**

住民の実装（`src/robots/`）・共有の島・保存は本体側の担当。この文書は、本体側が設計するときの出発点。

## 1. オーナーの意図

- カメマルとラッコが、ある程度言うことを聞く**小さいカメ・小さいラッコ**を連れている。単純作業を任せ、本人は考えること・作ることに時間を使う。
- 主役はあくまで住民4体（ドット・ランタン・ラッコ・カメマル）。手伝いは脇役で、主役を引き立てる。
- 今回の取り組みは **Season 1**（3〜5年で、ある程度のところまで）。世代交代や、手伝いが育って主役になる構想は今は持たない。
- 年齢の概念は設けない。「子ども」ではなく、**役割として連れている小さな仲間**。
- 島の発展が早まりすぎないよう、バランスを取る。

## 2. 手伝いとは何か（案）

| 項目 | 案 |
|---|---|
| 誰が連れるか | カメマルとラッコ。ロボット（ドット・ランタン）は連れない |
| 数 | 1体あたり上限を置く（例：最初は1〜2、節目で増える）。上限と増え方はオーナーが決める |
| 年齢・成長 | なし。増えも減りもしない（いなくならない。ADR 0002 の「永久喪失なし」と合う） |
| 心 | AI を使わない。決まったルールで動く。言葉は話さず、しぐさと声だけ |
| 記憶・日記 | 持たない。研究ノートも持たない。経験は親方（カメマル・ラッコ）の側に残る |
| 見た目 | 親方を小さくした姿。親方の後をついて歩き、作業のときだけ離れる |

主役が4体であることを崩さないため、手伝いは**住民ではなく、住民の持ち物に近い存在**として扱うのがよいと考える（台帳では「住民に属する仲間」）。

## 3. できること・できないこと

| できる（単純作業） | できない（主役の仕事） |
|---|---|
| 運ぶ（粘土・薪・水・試験片） | 次に何を試すか決める、研究ノートを書く |
| 集める（流木・貝殻・石、決められた場所で） | 火の色を見て焼き方を決める、窯の計画 |
| 練る・こねる、型に詰める | 量る・読む（計器の値を知るのは親方だけ） |
| 棚の試験片を並べる・返す、ふいごを押す | 会話、交渉、他の住民との約束 |

- 作業は**親方が指示したときだけ**。親方が見せる・頼む時間がかかる。
- 作業は**親方の近く**で行う（一定の距離まで）。島中で同時に工房を回すことはできない。
- 親方より遅く、ときどき失敗する（落とす、こね方がむらになる）。失敗は世界の規則で決まり、親方が見て気づく。

## 4. バランスの考え方

1. **物理の時間は縮まない。** 乾燥は数日、焼成と冷却は数時間かかる（科学側の規則）。手伝いが増えても、ここは変わらない。早くなるのは「集める・運ぶ・こねる」の部分だけ。
2. **手伝いの仕事にも上限がある。** 科学側では、手伝いの作業を「手の仕事」の申し出（機械的エネルギー、例 `src:helper:<id>`）として数える。1日に働ける時間と力（W）に上限を置き、休む時間もある。科学側の工程（成形など）は、すでに機械的エネルギーの申し出を受け付けるので、変更は要らない。
3. **指示にも時間がかかる。** 新しい作業を任せるには、親方が見せる時間が要る。最初は親方が遅くなり、慣れた作業ほど任せやすい。
4. **数の上限が最後の調整つまみ。** 上の3つで足りなければ、数で調整する。
