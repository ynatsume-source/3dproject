## 物質状態と収支

全質量は非負の安全整数mg。入力は乾物・水分とも正、合計も安全整数内。成分不明の湿重量から乾物率を推測しない。

| 保有区分 | 乾物 | 水 |
|---|---|---|
| 分離した繊維部分 | `fiber.dryMg` | `fiber.waterMg` |
| 同じ繊維束に付着したpith | `attachedPith.dryMg` | `attachedPith.waterMg` |
| まだ分離していない殻/残留組織 | `residualHusk.dryMg` | `residualHusk.waterMg` |
| 機械的に排出した水 | 0という**試験上の仮定** | `dischargedWaterMg` |

付着pithは独立の利用可能pithロットではなく、未洗浄の繊維束に付着する成分。残留殻を純粋pithとみなさず、繊維を純セルロースともみなさない。水流は未分類であり、飲用/清浄/再利用可能を意味しない。浴全体の水や洗浄水は入力に含めない。

`入力乾物 = 繊維乾物 + 付着pith乾物 + 残留殻乾物`

`入力水 = 繊維保持水 + 付着pith保持水 + 残留殻保持水 + 排出水`

乾燥/蒸発、洗浄、水の追加、溶解、微生物分解、CO2、熱/力学エネルギー、繊維の損傷・長さ・強度、撚り/縄化は計算しない。特に排出水中の溶存/懸濁乾物をゼロと置くことは実物についての結論ではない。質量移送の隔離試験であり、化学反応やエネルギー収支が校正されたモデルではない。

## 手作業量と試験プロファイル

`ManualSeparationTestProfile` はID・`uncalibrated-test-profile`・累積knotsを必須とする。各knotは確定手作業msと、繊維乾物・付着pith乾物・両保持水・排出水の累積mg。初点は全0、時刻は厳密増加、全配分は非減少で、元の乾物/水在庫を超えない。数値を推測するAI/文章parser・選択APIはない。

隣接点a,bの間は各配分qを `q(a) + floor((q(b)-q(a)) × (W-a)/(b-a))` とする。積/除算はBigInt、保存値は安全整数。これは**試験用補間規則**であり、実験で得た速度則ではない。端数は残留殻に残る。累積の確定仕事Wから毎回再計算するため、処理呼出の分割や再開で丸めが増えない。

1mg未満の繊維/付着pithを端数切捨てした時に水だけの束を生成しないよう、その成分と保持水は残留殻に留める。繊維乾物が0なら付着pithも出さない。この整数キャリア規則も試験上の仮定。

最後の点を超えた確定仕事も来歴へ記録するが、配分は最後の点に固定し**外挿しない**。`profile-exhausted` はモデルの評価域を使い切った意味で、殻の分離完了や以降の実収率ゼロを主張しない。更なる物性予測には校正データが必要。

## 科学API・保存・世界側境界

- `createManualHuskSeparation(input, profile, context)`：明示された元入力・試験プロファイル・world/epoch/runを検証し、防御コピーを保持。既存本番契約/catalogには登録しない。
- `start()`：全量を残留殻へ置く新しい工程状態を返す。世界のロットを消費/生成する副作用なし。
- `commit(state, interval)`：世界側が完了を確定した手作業区間だけを受け取り、新しい科学状態を返す。元stateは変更しない。
- `restore(value)`：元と同じ権威ある入力・profile・contextで作り直したモデルにJSON保存を渡す。schema/binding、全区間、累積仕事、全成分を再計算して照合する。
- `project(state)`：科学検査用の値コピー。潜在配分を住人の視覚観測/知識へ自動公開する契約ではない。住人やUIへの公開判断は世界側の責務。

確定区間は`[fromWorldMs,toWorldMs)`、正の長さ、元run/world/epochに一致、`confirmedAtWorldMs >= toWorldMs`、`attendance: present`と操作種別が必要。これは**世界側の証明を受け取る境界**であって、科学側が住人の在席/移動/選択を決める機能ではない。文字列タグは暗号署名ではなく、呼出側は任意のAI入力やブラウザ入力からこのAPIを直結してはならない。

同一confirmationId・同一内容は保存復元後や後続区間後も無変化。内容の異なる再送、別IDでの同区間、重複/逆行区間は拒否する。間の空白時間は仕事に加えない。tick/look/表示再生/未完了/不在/数量指定のコマンドは拒否する。原状態や返却viewの変更が他の状態へ漏れない。

返す保有量は**累積snapshot**であり、毎回在庫へ加算する生成deltaではない。世界側は元ロットの排他予約、runの一意性、トランザクションによる一度だけの在庫置換、工程状態との同時保存を担う。本モデル単独で別runによる同一ロット二重使用や保存全体の巻戻しを防げるとはしない。部分分離後は元stateを復元して続け、残留殻を新しい未分離ロットへ改名して再投入しない。

保存bindingはcanonical JSONの一致検査であり、改竄耐性のある署名ではない。元input/profile/contextを保存内容の自己申告から無検査に再構成しない。追加履歴を切り捨てる上限は置かず、将来の長期圧縮は別仕様。
