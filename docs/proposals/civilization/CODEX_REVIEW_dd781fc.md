## A1：布に何も残っていないのに、小石や砂を観察する

対象：科学側 `src/science/step/slake.ts:176–180`。

乾いた10 kg、`xd_kaolinite_ppm:1000000`、粗いものなし、水15 kg。1日待ってこすと、残留組成 `{}`・残留ロットなしなのに、住人へ「こし布に小石や砂が少し残った」と返る。
`cs=0` が常に「少し」に入るため。単位や専門知識の漏れではないが、実際には見えない物を観察したことになり、材料の学習を誤らせる。

観察は実際の残留物から作り、ゼロならゼロの言葉にする。根だけ・未分散の塊だけの場合も、石や砂と取り違えないことを確認してほしい。
診断 JSON の `findings.A1`。

## A2：回収した上澄みの来歴が消え、次の粘土で完全に戻る

対象：`slake.ts:240`（回収水の `quality:{}`）、`knead.ts:88`（未指定を完全として継承）。

元粘土に `history_complete:0` を付けて標準手順を実行すると、粘土と残留物は0だが、回収水8,425,008 mgには来歴がない。
この水から150,000 mgを分けて、完全な既知粘土1 kgに練り込むと、生成物は `history_complete:1` になる。
同じ結果を「元の水が不完全」「天気が unknown」の2経路でも確認した。

回収水にも `hist` を継承してほしい。新しい水だけで検査せず、「不完全な run → 回収水 → 次の run」の連鎖を回帰に入れる。
診断 `findings.A2.provenancePaths`。

## B1：自分が返した raw_clay を、次の run が読めない

対象：`slake.ts:235–238` の生成と `readRawClay` の丸め（同ファイル54–67行、共通 `tileQuality`）。

通常の10 kgロット、水分20%、乾燥組成カオリナイト45%・石英40%・方解石15%、粗いものなし。水15 kgを加え、1時間の直前にこさずに取り出す。
初回は成功し、`amount:24970963 mg / water_ppm:679628` の `raw_clay` が返る。
これをそのまま次へ渡すと `raw-clay-make-up-exceeds-dry-part` で失敗する。

水の ppm を読み戻すと乾燥分が7,999,997 mgになるが、3種を独立に丸めると合計がそれを超える。
総質量の等式は初回も成立しているので、精算だけを見る検査では分からない。

生成側と読取側の丸めを整合させ、受け付けた材料の返却物が再度読めるようにすること。単に超過を無条件に無視して物を増やす修正にはしない。
`xc` の読戻しも含め、返却を繰り返す検査にしてほしい。診断 `findings.B1`。

## B2：直後にこして水を捨てると、空の桶で NaN になって run が止まる

対象：`slake.ts:148–155`。

標準の粘土と水で、0秒に `sieve`、60秒に `decant`、120秒に `take_out`。
最初はまだ全量が塊なので固形分は布へ行き、桶の固形分は0。その後、水がなくなると `waterMg / tubDryMg()` が `0/0` となり、蒸発量が NaN になる。
答えは `failed / non-finite state: refusing to return it`。1回で送っても30秒で分けても再現する。

「早くこしたので何も取れなかった」という有効な実験として、空の桶／水だけの桶も有限な計算で精算できるようにしてほしい。
科学の意図に反して原料を失わせる操作ではなく、通常操作で到達する空状態である。診断 `findings.B2`。

## B3：湿りすぎて取り出した粘土を、待つ工程へ戻せない

対象：`slake.ts:102`、`knead.ts:20`、`CLAY_PREP_HANDBOOK.md` §3。

標準材料を1日後にこし、30秒後に取り出すと含水比2.507、「どろどろで、すくうと流れ落ちる」`settled_clay` になる。
練っても水分は変わらず、同じ手ざわりの `prepared_clay` になる。
手順書は「待つ工程へ戻す」としているが、既存の入口ではどちらの材料も戻せない：

- `p10x_clay_slake`：`raw_clay` と水だけ受理。
- `p12x_test_tile_dry`：`test_tile_green` だけ受理。

取り出して初めて手ざわりが分かる設計なので、早めの取り出しから通常の調製手順へ戻れないのは実際の進行停止になる。
既存の単一入口で待ち直せる経路を用意するか、run を終えずに確かめて待ち続けられる明確な操作を用意し、手順書と本体への指示をそろえてほしい。
診断 `findings.B3`。新しい世界ホストや第二の入口を求めているものではない。

## 通ったところ・数値誤差

- 科学側の新規検査36件、気圧計43件、既存回帰108件、型検査が成功。
- 通常の9日6時間の手順：入力25,000,000 mg = 粘土7,917,289 + 布2,211,439 + 回収水8,425,008 + 蒸気6,446,264 mg。
  潜熱は15,664,421 Jで、整数蒸気から計算した累計の切り捨てと一致。契約0.1.0/0.2.0も一致。
- 45 g／500 g／10 kg、水分0／20／40%、粗い石英0／10／30%の27条件でも、整数 mg の総量と蒸発の累計 J は閉じた。
  これは総量の検査であり、B1のような保存・再読込での組成の保証は別に必要。
- 開始1000 ms、格子外の操作を含み、30秒／1時間／3時間分割は9.25日・12日とも、状態・生成物・観察が完全一致。
- 37.001秒分割との比較：9.25日は精算 mg/J と観察が一致（状態の浮動小数には差）。12日は含水比0.043まで乾き、生成物最大差10 mg、蒸気−10 mg、熱−24 J（−0.000127%）、観察一致。
  今回の寸法・天気・操作で測った誤差であり、全条件の上限とはしない。含水比0.13以下の非線形域もこの比較に含む。
- カタログの `clock` は浸す工程が `island`、練る工程が `world`。処理内部で時計を換算せず、別 run に分ける方針に整合。
  世界側は時計ごとの区間を送り、在庫精算で工程をつなぐこと。工程名から数値の時刻だけを見て時計の誤りを検知する実装ではない。
- 練る途中の供給断は経過時間・Jを増やさず、再開後は連続作業と同じ物とJ。台の喪失は区間末までの仕事を数え、未完了ならロットを消費しない。
- 診断で呼んだ答えはすべて `validateResult` を通った。従って検査器に通ることだけでは A1/A2/B1を検出できない。

## 本物らしさと取得資料

以下の原典本文を取得・読了した。3件を `data/science/sources.json` に追加した。
保存したのは必要な事実の転記JSONであり、その SHA-256 と範囲を明記した。**出版社のHTML全体のハッシュではない**。
全件 `calibrationEligible:false`。材料分析・時刻ごとの水量・温湿度・反復がそろった実測曲線は取得できていない。

- [Digitalfire / Tony Hansen: Slaking](https://digitalfire.com/glossary/slaking)：乾いた塊が湿った塊よりほぐれやすい、こして沈めるという筋を支持。材質、塊の大きさ、水への露出に依存する。
- [Digitalfire: Slaking. What is that?](https://digitalfire.com/picture/1132)：実作者の棒状粘土の観察は約20分で崩れる例。現在の完全乾燥品の τ=1時間を直接校正する条件はない。
- [Mea Rhee: Tips and Tools: Reclaiming Clay（2018年12月）](https://ceramicartsnetwork.org/ceramics-monthly/ceramics-monthly-article/Tips-and-Tools-Reclaiming-Clay-202916)：石膏で脱水してから練る作業例。桶の自然蒸発とは条件が異なる。細粒を含む水を保持するという記述もあり、「濁った水は純水扱い」という現在の省略は明記を続ける。

9日は「この試験条件から出る値」とするのが適切。28 °C・湿度75%・風3 m/s・水面0.15 m²の式は、水が多い間に **約0.697 kg/日（4.65 mm/日）**を飛ばす。
上澄みを捨てた後に数 kg を飛ばすため日単位になる、という算数は説明できるが、島の粘土で9日と実証したわけではない。
日なたの式は常時+15 Kで、同条件なら28.63 mm/日・蒸発潜熱約805 W/m²。24時間この温度差が続く仮定には昼夜がないので、「現実の日なたなら3日」と一般化しない。
速すぎる場合は最初に、固定の表面温度差、蒸発係数、桶の露出面積を疑う。
ほぐれの速さは乾湿だけでなく塊径・材質・攪拌も原因候補。練る5分/kg・20 Wも実測未校正のままにする。
これらは試験モデルの既知の仮定と適用上の注意であり、新しいA/Bや校正値変更の要求は追加しない。今回、新規C指摘はない。

探索した USAID 配布の `https://pdf.usaid.gov/pdf_docs/PNAAS747.pdf` は本文取得がエラーになった。検索結果だけでは資料登録せず、係数の根拠にもしていない。
