## 3. 接続仕様 0.2.0 の採択

`science-contract-0.2.0.proposed.diff`（最新 main に `git apply --check` 成功）。

- 結果に `drawn`（空気・水・地面から取り込んだもの）が加わる。**0.2.x の答えには必ずある（何もなければ `[]`）、0.1.x の答えには付かない**。型では省略可にした（本書のコミットで提案を修正）。0.1.x の答えを返す既存の工程と、型の上で両立させるため。
- 質量の規則2：Σconsumed + Σdrawn = Σproduced + Σreleased。`validateResult` は対応済み（main に取り込み済み）。
- 熱の規則3：`src:env-heat:`・`src:combustion:` は申し出ではない。燃料ロットは run の終わりに精算する。
- 環境の値は測ったものだけ（湿度 0〜1、風は地上10 m）。
- 区間の境界は run 開始 + 30秒 × n で完全一致。run の開始は世界時計の30秒の印に。
- seed は run ごとに1つ。停止の4種の意味、停電後の欠けた区間は `unknown` で送る。

**採択後の確認（科学側で実施済み）**：この差分を当てた作業ツリーで、型検査・ビルド・本体の統合検査 93件・科学側の回帰 98件・薪の検査 32件がすべて成功した。

## 4. 0.2.0 採択に備えた互換の修正（本書のコミット）

採択で `SCIENCE_CONTRACT_VERSION` が `'0.2.0'` になると、修正前は次が起きた。

- 秤量・成形（`simple.ts`）は、その定数と同じ版しか受け付けていなかった → 採択した瞬間に 0.1.0 の要求を断り、0.2.0 だけを受け付けるように切り替わる。
- 乾燥などは 0.1.x しか受け付けない → 世界は工程ごとに違う版を送り分けなければならない。

修正：**既存の工程はすべて 0.1.x と 0.2.x の両方を受け付ける**。0.2.x の答えには `drawn: []` を付ける。結果の中身は版によらず同じ。薪で焼く工程だけは 0.2.x 専用（`drawn` が要る）。

- 世界は、採択後はすべての工程へ 0.2.0 を送ればよい。0.1.0 を送り続けても既存の工程は今までどおり動く。
- 確認：乾燥・電気窯・石灰の焼成・消化・浸漬・秤量で、0.1.0 と 0.2.0 の答えが `contract` と `drawn` 以外まったく同じ（回帰「0.2.0:」6件）。本体の統合検査 93件は変化なし。

## 5. 旧状態の run 中止と予約の解放

- 科学側は古い版の状態を `unsupported-state-schema` で拒否する。薪の状態は `/2`（0.1.2 で熱の数え方が変わったため、それより前の `/1` は拒否）。
- 本体の扱い（前回の合意どおり）：その run を中止し、予約を解放する。確定済みの過去区間の熱の使用は台帳に残す。
- **工程版だけを付け替えて、古い run を再開しない**（Codex の注意）。

## 6. 本体側で決めること（手順書 §6 の再掲）

1. 薪ロットの元：島の流木・枝を、拾う → 乾かす → 割る、でどう薪ロットにするか。
2. 炉の params：焚き火・試験用の薪窯の値は仮定。住民が作る炉は、材料と形から本体側が決める（後の段階）。
3. 火の番：焼いている間、住民が火のそばにいる必要があるか。離れたら `stop` を送るか。
