# 科学の標準run記録の上限

保存の記録欄は civ-world.science-records/1。旧保存ではこの欄がなく、
compactScienceLedger が移行する。科学の状態・物理・材料の保存形式は変えない。

- 動作中の標準runの observations は直近64件。
- 完了・中止・失敗した標準runは runs から除去する。
- 決着の要約は直近64件。ID、工程版、時計、最後の時刻、入力ID、
  終了理由、直近8件の観察だけ。状態・seed・材料のコピーは持たない。
- 直近500 requestId と放出直近300件の既存窓は保つ。
  終了したrunの再送も、run検索より先に requestId で拒否する。
- prototype_* の段取り部品は、自分の決着用データを組み立ててから
  自分でrunを除去する。共通runnerが先に消して二重精算や来歴喪失を起こさない。

移行は時計を進めず、seq・材料のIDと量・活動中の予約を保つ。
旧終了runに残っている予約だけは、そのrunが所有している場合に解く。
新しい版名だけ付けた古い形、異なる世界、壊れた要約は拒否する。

検査: science-records-check。標準run 1200回の完了による記録の頭打ち、
実際のm02x 1000区間の読みと64件保持、旧保存移行、再送、所有者の
明示的なprototype終了、破損した新形式の拒否を確かめる。
材料を無限に作って残した世界全体の容量には、固定上限を約束しない。

## 段取り部品の整理（2026-10-20）

| 所有者 | 新しい記録の版 | 終了後に残すもの |
| --- | --- | --- |
| 潮だまりの殻 | husk-soak host-3・状態 /3・記録 /3 | 決着64件、指示64件、現在ある湿った殻の起源と直近64区間 |
| 手で殻を打つ | manual-husk-records /1・arrangement /3 | 決着64件、区間再送64件、段取りの再送64件 |
| 繊維と縄の作業 | coir-work host-3・状態 /3・arrangement /3 | 決着64件、段取りの再送64件 |
| 帆の作業・航海 | 既存形式 | 既に決着64件・再送64件。完了runを除去する形を維持 |
| 縄への荷重 | coirCordLoads /4 | 既存の縄ごとのチェックポイントと直近64指示を維持 |

旧保存は各所有者が証拠と予約を検査してから移行する。
本体の復帰順は殻 → 縄 → 帆 → 共通runnerの整理とする。
元のlotId・質量・予約・進行中の物理状態を変えず、時計も進めない。
旧殻の生成元を除去する前に、現在ある湿った殻の起源をprivateな来歴欄へ移す。
予約済みロットのqualityを書き換えず、打つ工程の指紋を維持する。
浸け直しの起源は、旧 /1 の進行中保存を移行してから引き上げた場合にも残す。

再送の保証は直近の保持窓に限る。窓の外の時刻や古い改訂を新しい作業として
繰り返さず拒否する。古い全履歴を永久保存する保証は行わない。

灯りの状態内の消灯理由リストも直近64件に制限する。
消費・熱・炎・最後の観察は変えず、古い長いリストは復帰時に末尾を残す。
気圧計の読みは共通のobservations上限を適用し、住人の気圧履歴は既存の400件を保つ。
干し終わった葉や縄の日なた時刻を覚える本体の欄は、元から消えたlotIdを整理している。

### 検査と上限の意味

husk-soak-records-check は100回の浸ける→1個ずつ打つ、進行中の長い浸漬、
旧 /1・/2 保存、予約中の旧殻、再送を検査する。
manual-husk-records-check は300回の作業と旧保存の移行を検査する。
coir-cord-work-check は200回の作業と移行を含む。

容量の比較では、生成した物理的な在庫を明示的に片付け、記録用メタデータを測る。
材料が増え続ける世界全体や、終わらない手仕事の証明区間・交代の履歴に対して
一定容量を約束しない。活動中の手仕事の証明は保存し、終了時に要約へ置き換える。
浸漬の待機区間は累積値と直近64件なので、進行中でも区間数に比例して伸びない。
