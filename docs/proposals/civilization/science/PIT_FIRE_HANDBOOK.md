# 手順書：器を野焼きで焼く（p13y_pot_pit_fire 0.2.1）

2026-10-07 / ブランチ `codex/civilization-simulation` / **未採択の提案**（Codex の全面レビューと本体の最終レビューの後に統合）

設計案 [POT_FIRING_DESIGN.md](POT_FIRING_DESIGN.md) の2つ目。形づくって乾かした器（[POTTERY_HANDBOOK.md](POTTERY_HANDBOOK.md)）を、地面で薪に囲んで焼く。島の時計、接続仕様 0.2.x のみ（火が O2 を取り込む）。

## 1. 入れるもの・決めること

- ロット：器 1〜3 個（`dry_pot`、乾ききっていない `green_pot` も可：蒸気で割れやすい。0.2.0 から、まとめて焼ける）と `firewood` 1つ。割れて分かれた器が1つでもあれば断る。
- 設備：`open_fire_pit`（場所）。器を囲んで積む火の値は科学側の仮定（`pit*`、料理の焚き火の値は使わない）。
- 天気：気温・湿度・風・雨（どれかが欠けたら火を起こさない／途中なら止める。明示の 0 は有効）。
- 最初の依頼の `interval.from` に `fire_plan` を1回：`preheatMin`（あぶる時間）、`pace`（0 ゆっくり・1 ふつう・2 速く）、`targetGlow`（0 暗い赤〜3 黄）、`holdMin`、`forcedCooling`（0 灰の中で冷ます・1 引き出す）。操作 `look` でその時刻の火と器を見る（物理に触れない）。

## 2. 住人が試して分かること（4 L の鍋、日陰で8日乾かした器、乾いた薪 40 kg、28 °C）

| やり方 | 結果 |
|---|---|
| 1時間あぶる・ゆっくり盛り上げる・桜色で30分・灰の中で冷ます、風 1 m/s | 島の時計で約8時間、薪 約32 kg。焼けた鍋（吸水 約14%）。割れたのは 20個中1個 |
| あぶらない・速く・引き出して冷ます | 20個中15個が割れ、10個はかけらに（冷めるときの石英の転移） |
| 気をつけても風 6 m/s | 20個中6個が割れる（片焼け） |
| 1日しか乾かしていない湿った器を速い火へ | 20個中13個が蒸気で割れる。3時間あぶれば1個 |
| 切ったばかりの薪（水 45%） | 煙ばかりで炎が弱く、約 440 °C まで。器は焼けず、土のまま（「水に入れると崩れる」） |
| 強い雨（8 mm/h） | 約 410 °C までしか上がらない |

住人が覚える工夫：よく乾かす・あぶる・乾いた薪を使う・風のない日を選ぶ・灰の中でゆっくり冷ます。どれも観察から気づける。

## 3. 物理（すべて仮定、`params.ts`）

- 火と器は「薪で焼く」工程（p13w）と焼き物の共通の物理（`kiln-ware.ts`）をそのまま使う：壁の厚さに応じた遅れ、乾き切らない水の蒸気、573 °C の石英の転移、脱水、焼き締まり。
- 野焼きの火：熱容量 30 kJ/K、熱の逃げ 25 W/K、燃えた熱のうち器のまわりに残る割合 0.35、燃やせる速さ 40 kg/h。盛り上げ 300/600/1200 K/h。あぶりは 60 K/h で 150 °C まで上げて保つ。
- 湿った薪：薪の水が湿った重さの 2 割を超えると、1 割ごとに器に届く熱が 25% 減る（下限 1 割）。
- 風：地上 10 m の風が 3 m/s を超えると、その比で片焼けの割れやすさ。
- 雨：器に届く熱 ÷（1 + 雨 mm/h ÷ 2）。
- 手で積んだ器の見えない欠陥：どれだけ気をつけても 8% が割れる（半分は細いひび、半分はかけら）。
- 冷まし方：灰の中なら熱の逃げ 0.3 倍、引き出すと 3 倍。
- 焼けたかどうか：300 °C を超えて熱くなれば割れは起こりうる。粘土の鉱物が水を手放す（脱水）まで焼けて初めて `fired_pot`。足りなければ器のまま（`dry_pot`）。
- 割れは run の seed と器ごとに決まる（区切り方で変わらない）。割れて分かれた器は、焼いた後の質量の `pot_sherds`（`potSherdsQuality` の形）。
- 吸水率：試験片の浸す工程と同じ式（焼き締まりから、冷たい水に浸したとき）。

扱わないもの：砂・貝殻の混ぜ物（貝殻の石灰化を含む）、煙で黒くなること、火の中の場所の差（まとめて焼くことは §7）、器そのものの強さと壁の厚さの関係、薪で焼く工程（p13w）への湿った薪の炎（同じ式を入れるなら版を上げる）。

## 5. 0.1.1 の変更（島の粘土は草や根を含む）

0.1.0 は粘土に有機物（`xd_organic_c_ppm`）があると拒否していた。島の粘土は 1% 含むので、このままでは焼けない。

- 有機物は野焼きの火の中で燃えて抜ける（400 °C あたりから）。燃やす O2 は空気から取り込み（`drawn`）、CO2 として出す。質量は閉じる。
- 燃え残ったまま冷めた器は「割ると、器の芯が黒い（土の中の草や根が燃え残っている）」と言う。
- 生木で火が育たなかった場合、有機物は抜けても、器は素焼きにならない（`dry_pot` に戻る。割れたら `pot_sherds`）。
- 共通の焼き物の物理（`kiln-ware.ts` の `advanceWare`）に、有機物を燃やすかどうかの選択（`burnOrganic`）を足した。指定しなければ今までと同じなので、試験片と電気の試験窯の結果は変わらない（試験片の検査 32・52・18・24・47 件で確認）。
- 状態の形は同じ。0.1.0 の run は版で拒否（本体が取り消して中身を返す）。

## 6. 0.1.2 の変更（Codex PF-A1、0a3de47）

燃えている途中で焚き火の場所を失った（`stop: equipment-lost`）とき、0.1.1 までは最後の区間をまるごと計算していなかった。要求の区切り方しだいで、燃えた薪・器の温度・観察が変わっていた。0.1.2 では、ほかの区間と同じように `interval.to` まで燃えてから終わる。2時間で失った例では、1回の要求でも、2回に分けても、薪 6.29 kg が燃えて器は約 378 °C になる（Codex の診断で、境界で知らせる場合も一致）。火をつける前に失った場合の拒否は今までどおり。状態の形は同じ。0.1.1 の run は版で拒否。

### Codex の確認で分かったこと（非保留の補足）

- 830 °C 前後・数時間という温度と時間は、野焼きの実験記録の範囲と矛盾しない。ただし「4 L の鍋に薪約 32 kg」「割れ 20 個に 1 個」は、特定の材料・積み方に合わせた実測ではない。20 seed の頻度を実世界の確率とは呼ばない。
- 生木での最高温度（計画により約 460〜500 °C）は傾向の再現で、生木の普遍的な上限ではない。
- 有機物の燃える熱は省いている（1% 炭素の例で薪の熱の約 0.1%）。有機物の多い粘土には一般化しない。
- 「割ると芯が黒い」は、今の通常条件ではほぼ起きない（有機物が先に抜ける）。黒芯がふつうに起きるモデルにするときは、無傷の器で自動的に見えるのではなく、割ったときに見える観察にする（PF-C1）。
- 格子の外の時刻で区切った場合の差は、試した範囲で usedJ 最大約 0.11%、終了時刻 30 秒、器の mg は一致（全入力の保証ではない）。

## 7. 0.2.0 の変更：器をまとめて焼く（オーナー決定 2026-10-10、本体の依頼）

本体の通しの暮らしで、野焼き1回が乾いた薪の山（約 31 kg、乾かすのに 30 日）をまるごと使い、器1つに約 40 日かかっていた。熱のほとんどは器を囲む火とまわりの地面（熱容量 30,000 J/K）を温めるのに使われ、器そのもの（4 L の鍋で約 900 J/K）はわずかなので、実物の野焼きと同じく、まとめて焼けるようにした。

**オーナーの決定（すべておすすめどおり）**

| # | 論点 | 決定 |
|---|---|---|
| ① | 一度に焼ける数 | 1〜3 個（火の値はそのまま。4 個以上は断る） |
| ② | 薪 | 同じ火。器はそれぞれ自分の熱を火から取る |
| ③ | 隣の器 | 蒸気ではじけて割れた器のかけらで、焼けた隣の器にひびが入ることがある（`pitNeighborBurstP` 0.2、そのうち `pitNeighborBreakShare` 0.3 は割れる。仮定） |
| ④ | 火の中の場所 | 差を付けない（風の片焼けの危うさは各器に同じだけ） |
| ⑤ | 混ぜる | 乾き具合の違う器を混ぜてよい。器ごとに乾き・蒸気を計算する |

**住人が試して分かること**（乾いた 4 L の鍋、§2 と同じ天気・計画）

- 1 個で 30.8 kg、3 個で 31.3 kg の薪が燃える（約 1.5% 増）。器1つあたりの薪は約 1/3。これは 4 L の乾いた鍋の例で、どの大きさ・水分でも同じとは限らない（Codex）。
- 「焼けた隣」は、終わりまでに 300 °C を超えた器のこと。はじけた瞬間の隣の温度は持たない。20%・30% は仮定で、飛び散る距離や衝撃の実測ではない。
- 1 日しか乾かしていない器を乾いた器と一緒に急いで焼くと、湿った器だけが強く湯気を出し、40 回のうち 16 回はじける。はじけると「火の中で器がはじけて、かけらが飛んだ」と聞こえ、隣の乾いた器にひびが入ることがある。

**本体へ**

- `fire_plan` は火に1つ（器ごとではない）。器は lotId の順に並べて計算するので、要求の中の順は結果を変えない。
- 器が2つ以上のときは、器ごとの観察の `quantity` に器の lotId が付く（`crack:lot:pot-2`、`tap:…`、`pot:…`）。器1つのときは今までどおり `crack` など。
- 灰（`wood_ash`）は、lotId がいちばん小さい器の置き場所へ（火の場所）。器はそれぞれ元の場所へ返る。
- 版：状態は §8 の `/3`。0.1.2・0.2.0 の run と /1・/2 の状態は拒否される（中止して予約を解放）。同じ器を lots に二度入れると断る。
- 器1つの結果は 0.1.2 と同じ（科学側で 0.1.2 と新しい版を 327 要求で比べ、結果と状態の値が完全に一致）。

検査：`scripts/science-pit-fire-check.ts` 45 件（8 節が今回）。

## 8. 0.2.1 の変更：30 秒のセルを要求の端で分けない（Codex BATCH-A1、f372385）

10 L の壺 3 個（壁 8 mm・含水 20%）を同じ seed・天気・計画で焼き、69 分 45 秒で一度だけ要求を区切って保存・再開すると、2 個目が「細いひびの焼けた壺」から約 2.97 kg のかけらに変わっていた。要求の端で 30 秒の区切りが二つに分かれ、器の温まり方の速さ（`dTw / dt`）と蒸気の危うさの最大値が、区切り方しだいで変わっていたため（使った熱の差は約 0.00012%）。

- 火と器は、run の始まりから数えた **30 秒のセルで、まるごと** 計算する。要求がセルの途中で終わったら、そのセルは計算せずに次の要求に残す（状態の `simT` はセルの頭）。セルの途中の `look` は、セルの頭からの写しで見る（何も変えない）。
- セルの天気（気温・雨・風）と薪の燃やし方は、セルの頭で一度だけ決めて保つ。セルの途中から始まる要求の天気は、次のセルから効く。
- run の終わり（`stop: operator`・`equipment-lost`）は、今までどおり `interval.to` まで燃やしてから終わる（PF-A1）。セルの途中から天気が分からなくなったら、残っていたセルをその時刻まで保った天気で燃やしてから火が落ちる。
- 共通の焼き物の物理（`kiln-ware.ts`）は変えていない。試験片・電気の試験窯・薪で焼く工程は同じ。
- 器1つで、30 秒にそろった要求の結果は 0.1.2 と完全に一致する（科学側で 335 要求を比べ、開始 1007 ms の run を含めて結果と状態の値が一致）。
- Codex の証人（69 分 45 秒の一時停止と JSON 保存・再開）は、器・薪・気体・熱・最終状態まで区切らない場合と一致。セルの途中で区切る5通り（開始 1 ms 後、あぶり・盛り上げの途中、1 つのセルに3回）でも、3 個・1 個とも一致する。
- あわせて非保留の C も直した：手順書 §3 の「器をいくつも一緒に焼くことは扱わない」を消した（BATCH-DOC-C1）。同じ lotId の器が二度入った要求は断る（BATCH-HOST-C1）。
- 版：工程 0.2.1、状態 `civ-sci.pot-pit-fire/3`。0.2.0 の run と /2 の状態は拒否（未統合なので本体への影響はない）。
