# 住民4体の動作・暮らしを豊かにする草案 v0.1

作成：2026-10-02（日本時間）／状態：**未採択・実装前**

対象：Utsushiyo / `ynatsume-source/3dproject`。調査したチェックアウトは `81917b75cfc280c2a096df8d123b0c839b977af6`。Claude側の開発が進んでいる場合は、最初に現状との差を確認する。

ユーザーの希望は「姿勢・しぐさ・歩き方」と「暮らしの行動・住民同士のやり取り」を同じくらい豊かにすること。長期的には、眺めていると誰かの暮らしを感じられ、性格や才能の奥行きに驚ける世界を目指す。本草案はそのうち**身体の動きと短い行動の連なり**を扱う。

現在のコード・依存関係・保存データを変更せずに作成した。本文の新しい行動名・時間・角度・API例は提案値であり、実装済みの仕様でも、生物学的な測定値でもない。

### 共有ブランチ作成時の追記

共有用ブランチの基点は `987543fd8f13d64881a0da3781848010e92c64e3`。この版では、初回調査後に `src/robots/path.ts` のA*経路探索と、`residents.ts` の植生回避・経路追従が追加されている。動作の改良はこの新しい移動処理に接続し、旧版の `move()` へ戻したり、同じ経路探索を重複実装したりしない。足場の確認は支持姿勢・注視・必要な一時停止として設計し、行き先の決定と経路は既存処理を利用する。

## 1. 最初に試したいこと

4体について「何を気にしたのか→何をしたのか→どう確かめたのか」が、字幕なしで読み取れる短い場面を作る。

| 住民 | 最初の場面 | 見てわかる個性 |
| --- | --- | --- |
| ドット | 流木を見る→両手で持つ→持ち直す→作業台で削る→目線を下げて直線を確かめる | 几帳面。手を動かす前後に確かめる |
| カメマル | 海草へ顔を寄せる→ついばむ→止まる→息つぎへ上がる→同じ場所に戻る | 急がず、目的のある静けさがある |
| ラッコ | 潜って探す→食べ物を抱えて浮く→向きを変えて割る／食べる→口元と毛を整える | 手先が忙しく、興味の対象がはっきりしている |
| ランタン | 足元へ光を向ける→足を置いて確かめる→一歩進む→停止して遠くを見る | 慎重な探検家。脚と光で考えが伝わる |

続いて、ドットの「仕上がりを見直す」とラッコの「貝を選び、仲間に見せる」を**実際に選ばれる新しい行動**として加える。しぐさの改良と暮らしの改良の両方を、小さい単位で確かめる。

### 2.3 共通して効いている原因

1. `Pose` は `act / walk / night / wet / k / food` が中心（`models.ts:9–11`）。注視点、接触点、相手、実速度、旋回量、発話の区切りが渡らない。
2. 多くの動きは共通時刻 `t` に対する正弦波。行動の開始で位相が始まらず、「準備→実行→結果を見る」が出にくい。移動量は `walk` の振幅に反映されるが、歩行周期自体はおおむね時刻で進む。
3. `Residents.update` でドット以外の `sit` が陸では `idle` に変換される（`residents.ts:995`）。焚き火にも専用の落ち着く姿勢が出にくい。
4. `stepTalk` は初回のドットの手振り以外、おもに `idle / look / float`（`residents.ts:778`）。発話者・聞き手・対象物による身体の違いが弱い。
5. 拾得・建設・設置の世界の変化は `done()` が担う（`residents.ts:585`）。接触を伴う見た目は、その確定タイミングとまだ十分につながっていない。
6. `Robot.hand` は任意。ドットの工具用の手は内部にはあるが、返り値に公開されていない。ランタンには物を扱う手がない。`r.held` の固定表示をそのまま増やすと、物が浮いて見える問題が残る。
7. 160m以上離れるとモデル更新を省略する（`residents.ts:991`）。復帰時の動作再同期も設計対象になる。

**比較確認**：同じ乱数初期値、陸上、`walk=0`、60fpsで3秒進め、60/120/179フレームの全ノードの姿勢・表示・色を比較した。ドットの `idle/look/think`、ランタンの `idle/look/work/carry/sit`、カメマルの `idle/look/pick/work/carry/sit` は、それぞれ同一だった。これはモデル単体の限定条件の結果であり、全状況・全描画が同じという意味ではない。ラッコについて同一性の比較は実施していない。

## 3. 動きの共通ルール

### 3.1 行動の中に小さな区切りを作る

基本形は `気づく → 準備する → 実行する → 結果を見る → 元の活動へ戻る`。

- 単発動作は `enter → execute → settle` の3区間を最低限持つ。
- 長い仕事は作業を2〜5回したら、対象を見る／姿勢を直す／短く休む。停止区間も動作の一部として作る。
- 視線が先、首や胴体が次、足の向きが最後、という順序を基本にする。
- 別の行動へはおおむね0.2〜0.5秒、寝起き・浮き姿勢の切替は0.6〜1.5秒かける。接地や物の受け渡しがある場合は、接触条件を優先する。
- キャラクター固有の癖は、同じ目的を達成する2〜3通りの動きで表す。動作開始時に選び、フレームごとに乱数を引き直さない。

以下の秒数は**画面上で読みやすくするための初期調整値**。現行タスクの長さや身体寸法に収まるように調整し、食事・睡眠・呼吸の生理的な頻度を勝手に変更しない。

### 3.2 全員に必要な動作

| ID | 場面 | 動かし方・条件 | 頻度・終了 |
| --- | --- | --- | --- |
| C01 | 気づいて見る | 実在する対象を選ぶ→0.15〜0.4秒後に目／光→首／胴体。首の限界を超えると足を使って向き直る | 対象が変わった時。対象を最低1.5秒保持し、視線を細かく飛ばさない |
| C02 | 歩き出し・停止 | 重心を支持側に移す→最初の足を出す。到着前に減速→最後の足を着く→揺れを収める | 移動開始・到着時。移動の主導は既存の移動処理 |
| C03 | 曲がる・道を譲る | 先に進行先を見る→内外の歩幅を変える。近距離では停止して片側を空ける | 実際の経路と相手がある時だけ。待ち合わせの永久停止を避ける |
| C04 | 何もしていない間 | 微小な重心移動、まばたき、周囲を一度見る。ロボットは機械的な微調整、動物は身体に合う静かな動き | 大きな小動作は8〜25秒に一度を出発点にする。寝ている間は抑える |
| C05 | 語る・聞く | 話し始めの合図を一度。聞き手は相手を見る→少し遅れて一度反応→落ち着く。道具を持った手は振り回さない | 会話の話者交代から発火。発話中ずっと身振りを反復しない |
| C06 | 驚く・安心する | 視線／光が止まる→首を小さく引くか姿勢を低くする→安全なら観察に戻る | 実際に近くで起きた出来事に限定。連続発火に20〜60秒の間隔 |
| C07 | 休息へ入る・戻る | 足やヒレを収める→胴体を落ち着ける→目／光を弱める。起床は逆順で、周囲を見てから移動 | 既存の睡眠・休息の開始終了で一度 |
| C08 | 中断・再開 | 作業を止める→手元を安全な位置に置く→相手を見る。再開時は対象を見直す→持ち直す | 会話や優先行動に中断された時。物と作業結果を二重に発生させない |

### 3.3 静けさと身体を守る

- 大きな上半身のしぐさは同時に1つ。`操作中の手 > 会話の身振り > 何気ない動き` の順で優先する。足・水中姿勢は常に身体支持を優先。
- カメマルを立ち上がらせたり、甲羅へ頭を完全に引っ込めたりしない。ラッコの人間風の二足歩行は加えない。動物の動きは資料で確認し、擬人化の範囲を明示する。
- 住民の会話・建設参加・装飾は創作の設定。野生動物の一般的な行動の説明とは区別する。甲羅干しの場所・頻度などの地域差も、確認せず新しい事実として書かない。
- まばたきだけでは通常の観賞距離で変化が伝わらない。頭・胴・手足を含む輪郭の変化を先に確認する。
- カメラに映ったことだけで全員が挨拶する設計にしない。住民が気づける距離・方向や、近くの対象から動作が生まれる。

### 4.3 ラッコ：触って確かめ、手入れして暮らす

特徴：目線と前足が同じ対象へ集まる。細かな手作業と、仰向けに浮く静けさの落差を作る。

## 5. 暮らしのバリエーション：8つの行動案

単に既存のポーズに別名を付けるのではなく、**何に反応して、どこへ行き、何を終えるか**を定義する。長期の感情値や新しい生成AIは初期版に不要。既存の空腹・眠気・電池・持ち物・近隣対象・会話を使う。

新しい活動は、今の作業を安全に終えた時／自由時間になった時に選ぶ。生理的な必要、物を持ち帰る途中、建設の確定処理を妨げない。初期の再実行間隔は実経過の目安で、時刻パネルの早回しに比例して短くしない。

| ID・優先 | 活動と発火条件 | 具体的な流れ | 終了・再実行・世界への影響 |
| --- | --- | --- | --- |
| B01 P1 ドット | **仕上がりを見直す**。部材の取り付け直後、電池に余裕があり、完成部材へ安全に近づける | 工具を収める→1〜2歩離れる→高さを変えて見る→隣の部材と見比べる→納得して戻る | 8〜18秒。取り付け2〜4回に1回、実時間3分以上空ける。初期版は観察のみで完成数を増減しない |
| B02 P1 ドット | **仕事の間に海辺で休む**。作業をいくつか終え、手が空いている | 道具を安全な姿勢へ→到達可能な近くの休憩点へ→座る→海を見る→立つ→元の仕事を選び直す | 20〜60秒。実時間5〜12分以上空ける。`look/wander` の無目的な選択の一部を置き換える。道具を世界に置く保存機構は初期版では増やさない |
| B03 P1 カメマル | **目の前の生き物を見送る**。近くに実際の魚・鳥がおり、採食・睡眠・呼吸を妨げない | 進路を止める→顔を向ける→ゆっくり追う→視界外で少し待つ→元の活動へ | 5〜15秒、実時間2〜5分以上空ける。同じ対象は連続選択しない。対象が消えたら静かに終了 |

### 5.1 やり取りを身体で見せる

| 場面 | 話しかける側 | 応じる側 | 終了条件 |
| --- | --- | --- | --- |
| 出会い | 歩みを緩め、相手に視線／光を向ける。ドットは空いた片手、ラッコは頭で小さく合図 | 0.3〜1.2秒遅れて向く。カメマルは遅め、ランタンはまず停止 | 応答がなければ10秒以内に自分の用事へ戻る |
| 物を見せる | 持つ物→相手→持つ物の順に見る。持ち出す位置で一度止める | 相手の顔→実物→相手の顔と見る。種類ごとに小さな反応 | 対象喪失・相手離脱で中止。初期版は受け渡しなし |
| 作業を見守る | 作業者は仕事を続け、一区切りで相手を見る | 工具の届かない位置で止まり、手元と完成箇所を見る | 5〜15秒。双方の元のタスクを維持する |
| 焚き火の沈黙 | 火を見る、姿勢を小さく直す | 話者が現れた時だけ相手を見る。全員同時には反応しない | 次の発話または既存の散会時刻。沈黙を埋める台詞は不要 |
| 別れ | 向きを変える前に一度相手を見る。ドットは小さく手を上げる | 短く見送って、自分の対象へ視線を戻す | 1〜3秒で終わり、再挨拶のループに入らない |

### 5.2 新しい行動を選ぶ規則

- まず既存の優先条件を守る。新しい気まぐれ行動が睡眠・呼吸・空腹への対応や、持ち物の処理を繰り返し中断しない。
- 候補は2〜5秒おき、またはタスク完了時に評価する。毎フレーム経路検索・全生物検索をしない。
- 新行動には有効な対象、到達可能性、終了条件、待機上限、再実行間隔を持たせる。候補がなければ今の活動を続ける。
- 長く働くと少し休みやすい、物を拾った直後は見る／見せる候補が上がる、という**現在の文脈**を重みとして使う。抽選結果だけで物や気分の事実を作らない。
- 初期版の重みと間隔は調整値。既存タスクの頻度と比べて、新行動が独占しないことを短いログで確認する。
- 行動選択用の乱数と、まばたき・身振り用の乱数を分ける。見た目の改良だけで暮らしの抽選結果が変わる結合を増やさない。

## 6. 具体的な演技の時間割

### 6.1 ドットが流木を拾う：現行3.5秒の例

| 経過 | 頭・胴・足 | 手と物 | 世界の事実 |
| --- | --- | --- | --- |
| 0.0〜0.4秒 | 流木の中心と両端を見る。最後の一歩を着く | 手はまだ体側 | 流木は地面にあり、既存の予約対象 |
| 0.4〜1.1秒 | 膝を曲げ、腰を落とす。目は対象を追う | 両手を左右の把持点へ | 拾得未確定 |
| 1.1〜1.6秒 | 支持足を動かさず、胴を少し前へ | 指／手先が把持点へ届いて閉じる | 拾得未確定。接触が届かなければ動作開始位置を調整 |
| 1.6〜2.5秒 | 支持足から起き上がる | 流木を少し上げる | 早めに持ち上げて見せるなら、予約中の物の描画代理だけを動かす |
| 2.5〜3.2秒 | 胴の揺れを収め、進路を一度見る | 流木を体へ寄せる。片手を一度持ち直す | 所有権の変更をアニメーション側で行わない |
| 3.2〜3.5秒 | 運搬の姿勢へ | 運搬用の保持位置へ接続 | `done()` で `items.take()` 成功後に所持を確定。失敗したら空手で復帰 |

初期実装で描画代理の管理が大きすぎる場合は、把持までを演じて、**既存の拾得確定後に持ち上げる短い後続動作**にする。接触前に物が消える、原物と代理が同時に見える、キャンセルで物が失われる状態は避ける。

### 6.2 ラッコが貝を割る：6秒の小まとまり

0.0〜0.8秒：貝と石の位置を合わせる。
0.8〜2.5秒：2〜3回叩く。振り上げは0.25〜0.4秒、打ち下ろしは0.1〜0.15秒。
2.5〜3.3秒：止めて貝を見る。
3.3〜4.2秒：貝を回す。保持する前足は急に反対側へ飛ばない。
4.2〜5.4秒：もう一度当てる、または既存の食事区間に応じて口へ運ぶ。
5.4〜6.0秒：静止して咀嚼する／次の組へ。

「割れている」形状が必要なら食べ物モデルの状態を追加する別作業。音だけで割れたと決めたり、1組の終了ごとに満腹度を更新したりしない。食事の成果は既存の `eat` 完了で確定する。

### 6.3 仲間へ見せる：相手の反応を含む例

ラッコが相手を見て1秒待つ→相手がラッコを見る→ラッコが貝を差し出す0.8秒→相手が貝を見る1〜2秒→各自の小さな反応→ラッコが胸へ戻す0.8秒→既存の会話か収集へ。

全体4〜8秒。返答待ちは上限を持つ。相手が呼吸や移動を優先したら、静かに持ち物を戻して終える。相手の動作の終了通知を永久に待たない。

## 7. 現行構造に収める実装方針

### 7.1 世界の更新と動作の表示を分ける

流れは `decide / step / done → 描画用の状況 → 各モデルのポーズ → 接触に同期した表示・音`。

- `residents.ts`：行き先、実際の位置・向き、所持、建設数、空腹、会話、日記を所有する。
- モデル側：関節、視線、物を持つ表示位置、動きのつなぎ方だけを所有する。アイテム取得や日記の追加を行わない。
- カメラ外・低画質・ヘッドレス・追いつき計算でも、世界の結果は表示の有無に依存しない。
- 既存の `Act` を粗い分類として残し、作業種別や動作区間を補足する。全パターンを `Act` に並べる大規模な置き換えは避ける。

### 7.2 必要な入力を少しずつ追加する

以下は**設計例**。名前をそのまま採用する必要はなく、その段階で必要な情報だけ追加する。

```ts
// 既存 Pose へ追加する候補。世界データへの書き込み権限は持たせない。
interface MotionContext {
  actionKey: number;       // 同じ Act の別タスクも区別。セッション内の連番でよい
  taskKind: string;        // craft / fetch / eat 等、同じ work を演じ分ける
  stage: 'enter' | 'execute' | 'settle';
  elapsed: number;         // この動作の表示上の経過秒。世界の時刻とは分離
  phase: number;           // 単発動作の0..1。移動中の tk.t を流用しない
  variant: number;         // 動作開始時に選んだ差分。途中で引き直さない
  lookLocal?: [number, number, number];
  contactLocal?: [number, number, number];
  speed: number;          // m/s。歩行位相には前フレームからの移動量も使う
  turnRate: number;       // rad/s
  immersion: number;      // 既存の水中・水面状態から導出
  speaking: boolean;
  holding: string;
}
```

`lookLocal/contactLocal` はキャラクターの `root` ローカル座標に統一する。座標の供給側で最新の world matrix を使って変換し、モデル側で毎フレーム行列を作り直さない。例えばラッコは `root.scale=1.2` なので、ワールドの距離をそのまま関節座標へ入れない。

`Robot.hand` 一つで足りない動作では、必要なモデルにだけ名前付きの接触位置（左右の手、口、胸、運搬位置）を用意する。指や顎の追加が必要なら、その生成器内の小さな変更として分離する。カメマルの真顔を保ったまま採食を読ませる方法を先に試し、可動の顎の新設は別途比較する。

### 7.3 時間・繰り返し・中断

- 歩行の位相は実際に移動した距離から進める。停止時に足踏みし続けない。旋回は別の支持足の動きとして扱う。
- 作業の1打・まばたき等は表示用の時間で進め、同じ動作の開始・終了がわかるようにする。30/60fpsで秒数が変わらないことを確認する。
- タスク開始・会話の話者交代を検出して動作を切り替える。毎フレーム `elapsed=0` に戻す実装にしない。
- 打撃・足音などは区間境界を**通過した時に一度**発火する。`phase > 0.5` の全フレームで発火させない。大きな `dt` で境界を飛び越えても扱えるようにする。
- 所持や完成の更新は既存の世界側で一度だけ確定する。表示用イベントの再生漏れを世界側の失敗にしない。
- 中断時は到達前／接触後／確定後を区別する。対象の予約解除・所持の保持は世界側が決め、表示側はその結果へ追従する。
- 会話が終わったら元の対象を再確認する。対象が消えていれば新しい活動を選び、古い座標で手を動かし続けない。

現行の `endTalk()` は `r.task=null` として次の活動を選び直す。「同じ工程の途中へ戻る」機能はまだない。最初は、所持状態に応じて安全に次の作業を選び直す動作を自然につなぐ。工程そのものを保存して再開する改修は、対象の予約・有効性・二重完了を確認する独立した変更にする。

### 7.4 接地・接触・水面

- 足は接地中の支持点を保つ。斜面では胴体を少し傾け、膝を使って高さを吸収する。接地時の足裏のずれ2〜3cm以内を最初の目視調整目標とし、実寸とモデルで見直す。
- 地面の参照は地形だけでなく、既存の桟橋床を含む `G()`（`residents.ts:354`）と整合させる。桟橋上で海底へ足を伸ばさない。
- 到着判定の0.6mだけでは手が届くとは限らない。対象の接触位置と身体寸法から作業用の立ち位置を決め、既存の移動処理でそこへ寄せる。腕を無限に伸ばさない。
- 工具先端と対象、前足と食べ物、口と食べ物をそれぞれ接触させる。体の中心が近いだけでは完了扱いにしない。
- 水面への接近、浅瀬での支持、水面に浮く姿勢を分ける。現行の水面基準に合わせ、動作だけが波や浮力を新しく計算して世界の位置と食い違わないようにする。
- ラッコの仰向け回転は連続する角度／quaternionで補間する。±πの境界をまたぐ際の一回転を防ぐ。
- 全身の物理演算や新しいアニメーションライブラリは初期版に不要。最初は既存関節の目標姿勢と補間、必要箇所の簡単な接地補正で確かめる。

### 7.5 保存・時間・非表示との整合

- ADR 0001 の「住民の世界時間＝現実の時刻」を守る。現在の `clock.ms` と住民の結合は既知の別課題であり、本件で無断で全体修正しない。新しい再実行間隔や行動履歴は観賞の早回しへ結び付けない。
- まずは新しい活動も既存の保存内容から再開できる範囲にする。ポーズ、左右のまばたき、動作の小さな差分は保存しない。初期版の短い再実行抑制はセッション内で持てるが、ロード直後の連続発火は抑える。
- 行動の継続記憶を保存したくなったら、保存互換性を扱う別タスクとして設計する。`seaglass.*` のキー変更や保存消去を動作追加に混ぜない。
- カメラ外では世界側の行動を続け、モデルの表示更新は省略できる。再表示時は現在のタスク・段階へ合わせ、過去の拾得・打撃・効果音をまとめて再生しない。
- 20秒刻みの追いつき処理では身振りを再生しない。描画イベントを呼ばなくても行動の成果が成立する構造を保つ。

### 8.1 最初に比較したい完成場面

1. ドット：流木を拾って加工する様子を30秒。少なくとも接触・持ち上げ・作業中の確認が見える。
2. カメマル：採食から息つぎ、再び採食へ戻る1巡。検証用に既存周期の直前から開始してよい。
3. ラッコ：潜水から浮上して貝を扱う1巡。貝・石・両前足がつながって見える。
4. ランタン：平地→段差の確認→停止して周囲を見る20秒。足と光が同じ状況を表す。
5. 暮らしの追加後：仕上がりを見直す／貝を吟味する行動が実際に選ばれ、既存の仕事・収集へ戻る。
6. やり取り追加後：見せる側・見る側がずれたタイミングで反応する10秒。字幕を隠して意味がわかるか確認する。

### 8.3 実装後の合否基準

- 正面・横・斜め後ろと、通常の見守り距離で確認する。接写だけで成功にしない。
- 通常再生と0.25倍の録画で、開始・接触・終了の飛び、足滑り、物の瞬間移動、関節の反転を確認する。
- 低い／高い画質、30/60fps、160mの表示境界の往復で、動作の意味と世界の結果が変わらない。
- 拾う途中で会話が始まる、対象がなくなる、相手が離れる、足場が不適、岸で陸水をまたぐ、を確認する。新規行動が待機し続けない。
- 作業中にロードする／追いつき計算する／描画しない場合も、拾得・食事・建設の確定は一度。アイテム数、所持、空腹、建設数を比較する。
- 関数テストを書くなら、境界を飛び越える `dt`、二重発火、キャンセル、対象喪失、保存互換性など壊れると困る条件を中心にする。正弦波の式をそのままテストへ写さない。
- 4体同時の動作処理にかかるCPU時間と割り当てを改修前後で比較する。毎フレームのメッシュ生成・ジオメトリ作成・全生物探索を増やさない。
- SwiftShaderでの結果は動き・描画の確認として扱い、実GPU性能やWindows/ANGLEでの互換性は別に記録する。
- 採食・泳法・毛づくろいの細部は、水族館・研究機関等の映像で実装前に照合する。本草案では新たな外部映像による生態監修はしていない。
