## 初回タスクの具体化：ドット

### タスクA：拾う・加工する動きを読めるようにする

対象：READMEの D02〜D04 と、必要な範囲の C01・C02・C08。

**変更の中心**

- `src/robots/models.ts` の `makeDot` と `Pose`。
- `src/robots/residents.ts` のモデル更新へ、対象・動作の経過・作業種別を渡す部分。
- 必要ならデバッグ用の `src/robots/gallery.ts`。通常の画面に技術的な操作を増やさない。

**観察したい場面**

1. 地面の流木を見る。
2. 手が届く位置に止まり、しゃがむ。
3. 手を両端に近づけてから、流木を持ち上げる。
4. 持ち直して運搬する。
5. 作業台で2〜4回削り、止めて面を確かめる。
6. 中断されたら手元を保ち、戻ったら対象を確認して続ける。

**合格条件**

- 既存の流木予約・取得・所持が維持され、同じ流木を二重取得しない。
- 手より先に流木が飛び上がらず、持つ表示と地面の表示が同時に残らない。
- 拾得途中の対象喪失・会話の割り込みから、空手／所持の正しい状態へ戻る。
- 30fpsと60fpsで動作の秒数が大きく変わらない。カメラ外から戻った時に過去の拾得動作や音を再生しない。
- 横から見ても手が対象へ届く。通常の見守り距離でも、拾う→確かめる→持つがわかる。

世界の取得を行う時刻の変更が大きな設計変更になる場合は、既存の `done()` で取得が成立した後に短い持ち上げ動作を接続する案を優先する。アニメーションの終了を待たなければ世界が進まない構造にしない。

### タスクB：新しい暮らしとして仕上がりを見直す

タスクAと別の変更にする。対象は B01 / D08。

- 完成済みの部材があり、仕事を一区切りし、電池に余裕がある時にだけ選ぶ。
- 到達可能な観察位置へ移動し、高さや角度を変えて見る。
- 8〜18秒を初期値として終了し、通常の活動選択へ戻る。
- 初期版は観察だけ。部材数を変更しない。修理したという日記も生成しない。
- 完成のたびに必ず行わず、再実行を抑制する。保存やロードのたびに連続発火しない。

合格は「ポーズを呼べた」だけではなく、**暮らしの中で選ばれ、終わって戻れたこと**。普通に仕事が進むことも確認する。

## 検証時に間違えやすいこと

- ギャラリーの `solo` 番号は `0=dot / 1=kame / 2=rakko / 3=lantern`。`Residents.list` の並びとは同じとは限らないので、島ではIDで指定する。
- `robots.html?act=...` は粗いポーズの確認用。固定 `k` と床面では、実際の拾得や水面遷移を検証できない。
- `npm run sim -- miyako` で住民の検証が済んだとは報告しない。嘉弥真島の住民が対象。
- 時刻パネルを操作して朝夜の位置だけ確認した結果を、保存された暮らしの時間が正しい証拠にしない。
- ラッコの顎と前足は使用モデルにあるが、可動範囲は限られる。カメマルの現在の真顔モデルには独立した顎がない。必要な追加は別の小さな変更へ分ける。
- ランタンの `work` が動かない点を、食事の `work` と一括で修正しない。住民IDとタスク種別が必要。
- 身振り用の乱数やフレーム数が、アイテムやタスクの抽選へ影響しないようにする。
- 現在の会話終了処理はタスクを消して選び直す。最初の「再開」は所持状態に合う作業へ自然に接続する範囲とし、工程途中の厳密な再開は別の変更にする。
- 保存済みデータで確認するときはコピーした検証用のブラウザコンテキストを使い、ユーザーのデータを消去しない。

## 資料ブランチの使い方

`proposal/resident-motion-v1` は、この2ファイルを `docs/proposals/resident-motion-v0.1/` に追加する資料専用ブランチ。既存の `CLAUDE.md` やアプリコードは変更対象に含めない。

Claudeはそのブランチの資料を読み、最新の開発ブランチ上で必要な項目だけ実装できる。資料ブランチをmainへマージすることは実装の前提ではない。Claude側のローカル作業をresetや自動的なブランチ切り替えで失わせない。

別環境で作業中のClaudeは、作業中のブランチを切り替えずに、次の読み取り手順で資料を参照できる。

```sh
git fetch origin refs/heads/proposal/resident-motion-v1
git show FETCH_HEAD:docs/proposals/resident-motion-v0.1/README.md
git show FETCH_HEAD:docs/proposals/resident-motion-v0.1/CLAUDE_HANDOFF.md
```

fetchで取得するのは資料を含むコミットであり、作業ツリーへの適用やブランチの切り替えは不要。資料を参照して、ユーザーが選んだ範囲を現在の開発へ取り込む。mainへのpushで公開が走る既存運用を維持する。
