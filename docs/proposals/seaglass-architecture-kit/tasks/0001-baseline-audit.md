# Task 0001｜現在の構造と基準動作を確認する

状態：提案。初回のClaude Codeへの依頼用。

## 目的

今のSeaglassの良さを守りながら、長期のAI開発用設計を導入できる場所を特定する。

## 最初に読む

このキットのSTART_HERE.md、docs/00-current-state.md、docs/01-architecture.md、既存README、package.json、既存CLAUDE.md等の開発ルール。

## 今回行うこと

1. 現在のブランチ・コミット・未コミット変更を記録する。既存変更を上書きしない。
2. src/main.ts、time、data、eco、ocean、render、director、scriptsを調べ、実際の責任分担を整理する。
3. 保存、乱数、時刻、外部通信、状態の所有者について、あるものと未確認事項を区別する。
4. 環境が許す範囲で既存のtypecheck/build/シミュレーション確認を実行する。依存導入が必要なら環境の指示に従う。
5. 代表的な観察条件を選び、実際に取得できる画像・動画・性能の基準を記録する。取得できない場合は未実施とする。
6. このキットと現実装の対応表を作る。現実装のほうが適切な部分は残す。
7. 次の小さな変更を1つ提案する。期待する効果、変更範囲、検証、戻し方を付ける。

## 出力

- 現状対応表。
- 実行した検証結果と、未実行の確認。
- この設計の採用候補・修正すべき提案・後回しにする項目。
- 最初の実装タスク1件の具体案。

## 今回しないこと

既存ソースの書き換え、全体のフォルダ再編、依存関係の更新、API課金、秘密情報の表示、公開push、保存データの削除。

文書を保存する場合は既存資料を上書きしない新規の調査メモにする。

## 完了条件

次の作業者が、現状・提案・未確認を区別し、既存機能を何で守るか説明できること。
