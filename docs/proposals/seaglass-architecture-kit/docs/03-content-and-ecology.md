# 03｜魚・海域・見た目・行動を増やす設計

## 1. 「魚種」と「個体」と「見た目」を分ける

現在のSpecies定義には見た目や生態のパラメーターが含まれる。[S4] このデータ駆動の仕組みを活かす。

| 区分 | 内容 | 変更例 |
|---|---|---|
| SpeciesDefinition：種類の定義 | 名称、モデル参照、生息条件、行動特性、参考資料 | 種類を追加する |
| EntityState：個体の状態 | ID、場所、速度、空腹、現在の行動 | この魚が餌を食べる |
| RenderBinding：表示との対応 | 個体IDとモデル・描画用インスタンスの対応 | 遠くの魚を簡略表示へ替える |

「尾びれを自然にする」変更は主に表示側。「サメを見て逃げる距離を調整する」変更は行動側。同じファイルで行う必要があっても、変更理由と検証を混ぜない。

## 2. 魚種定義の具体的な項目

初期にすべて必須にせず、使うものから定義する。

| 分類 | 項目の例 |
|---|---|
| 識別 | id、和名、学名、定義の版 |
| 形と色 | モデル生成器ID、材質ID、体格範囲、色パターン |
| 見た目の動き | 尾の振幅、周期、旋回時の姿勢、ヒレの動作 |
| 生息条件 | 使用できる海域、水深、底質、隠れ場所 |
| 基本移動 | 通常速度、加速、旋回、上下移動の制限 |
| 行動 | 活動時間、群れ、採餌、危険回避、休息 |
| 生態系上の関係 | 餌カテゴリ、捕食対象、繁殖・補充方針 |
| 品質 | 観察距離ごとの表示、個体数予算、テストシナリオ |
| 根拠 | 出典、参照日、根拠がある値／推定値／演出値の区別 |

実在魚種について、AIが出したもっともらしいパラメーターを科学的事実として扱わない。速度等に根拠がなければ「演出上の仮値」として登録する。図鑑の説明も別に検証する。

## 3. 種類のたびに行動プログラムを複製しない

初期の共通行動を、例えば次のように用意する。

```text
移動の部品：泳ぐ／飛ぶ／歩く／水面に留まる
判断の部品：群れに合わせる／危険から離れる／餌を探す／休む
環境の条件：昼か夜か／水中か空中か／浅すぎないか／障害物があるか
```

魚種は使う部品と係数を選ぶ。新しい種類に本当に必要な特殊行動だけ追加する。「生物A専用コピー」を量産しない一方、すべての生物を扱える巨大な汎用エンジンを先に作る必要もない。

例えばサメの「危険を知覚する判断」と、小魚の「どの方向へ泳ぐか」を区別する。空腹の判定、経路の計算、尾の振動も別の更新理由として扱う。

## 4. 採餌と捕食は一度だけ確定する

複数の捕食者が同じ対象を狙った場合、食べられた事実は世界の更新担当が1回だけ確定する。描画、音、ログ、撮影監督、住民の記憶はその結果を読む。

例：`PredationResolved` のような確定イベントから、魚数の更新・水しぶき・観察ログを派生させる。各機能が別々に「捕食に成功した」と判断しない。

これはすべてのシステムをイベント配信基盤にするという意味ではない。初期は1プロセス内の型付き結果・有限のイベント配列で十分。

## 5. 生態系はどの程度「本物」にするか

現行READMEは捕食後に外から個体が入る補充方針を説明している。[S1] これは観賞体験を維持する設計で、閉じた自然生態系の厳密な再現とは目的が違う。

当面は「現実らしい振る舞いをする、観察が楽しい生態系」を初期方針とする提案。個体数維持の補助を禁じないが、ルールとして明示する。

自然淘汰・繁殖・資源制約による長期変動を試す場合は、別世界または明示的なモードで行う。大切な住民が突然全滅するような仕様を、表現改善の副作用として入れない。

## 6. 環境の事実と演出を分ける

太陽方向、時間、潮、水温などは環境から取得する。各魚、サンゴ、カメラが別々に「今は昼」と判定しない。

見やすい夜の露出や彩度は表示側の調整であり、生態系が感じる明るさと同一である必要はない。その区別を名前と仕様で示す。

実際の天候データには、取得元、観測／予報の区別、対象時刻、取得時刻、有効期限、取得失敗時の代替値を持たせる。現実データと演出用の値を混ぜた場合は、それを説明できるようにする。

## 7. モデル・テクスチャ・音の台帳

各資産に、assetId、ファイルまたは生成器、版、出典、作者、利用条件の根拠、改変履歴、必要なクレジット、容量、品質別の参照先を付ける。

AI生成物も「生成したから無条件で商用利用可能」とは扱わない。後で商用化を検討する際に、個々の資産を確認できる記録を残す。ここでは利用可能性の法的判断は行わない。

共有資産は参照数や所有者を管理し、不要になった時に解放する。Three.jsのGeometryとTextureにはGPU資産を解放するdisposeが定義されている。[S9][S10] 地域から離れた際の資産解放と、世界から個体を消す処理を混同しない。

同じ形の大量描画ではInstancedMesh等を候補にできるが、形式の変更だけで性能目標が達成されるとは仮定しない。公式には同一geometry/materialの多数描画を想定した仕組みとして説明されている。[S11]

## 8. 魚種を1つ追加する作業の完了条件

種類の定義が登録され、指定海域で出現し、図鑑の内容と参照が整う。昼夜と脅威の有無で意図した行動をする。海底や水面の禁止境界を越えず、低画質でも表示が成立する。

固定した観察条件の短い動画と、変更前後の性能記録を残す。他魚種の共通挙動を変更した場合は、その影響も別に説明する。

ただし、見た目だけの小さな変更に毎回すべての検証を要求する必要はない。変更が触れた境界に応じて確認を選ぶ。
