# 科学チームへの依頼：島で工程を動かすために（2026-10-06）

本体（main）から科学チームへ。オーナー決定（ADR 0006 追記 2026-10-06「島で科学の工程を動かすための4つの決まり」）を受けて、本体側でできることは入れた。残りは科学側の値と工程が要る。

## 本体で入れたこと（main）

| こと | 中身 | 科学側に見てほしい点 |
|---|---|---|
| 試験用の気圧計 | 島に置いた（ランタンの道具）。島の時計で3時間ごとに `read_gauge`、1回の依頼は島の1時間まで（天気が記録に沿うように）。読みは日記と `village.gaugeLog` | 読む間隔と依頼の長さ。このままでよいか |
| ヤシの実のロット | ランタンが浜の上のほうから棚へ運ぶ。1個 1.15〜1.85 kg（一様）。15% は持ち上げたときに中が腐っていると分かり、棚に置かない。棚では1つのロット `coconut`（`quality.count` 個、質量は合計） | 1個の重さの幅と、腐る割合。腐った実を持ち帰って記録する方がよいか |
| 薪のロット | 若木を切り倒すと、枝を薪 `firewood` のロットにする（3〜6 kg、`quality.water_ppm` 450,000：切ったばかり） | 切ったばかりの木の水分の値 |
| 雨水 | 竹 2 kg と葉で雨受け（受ける面積 0.8 m²、竹筒に 20 L まで）。記録の雨量 × 面積を、島の時計で `process_water` のロットに足す（`quality.history_complete: 1`）。蒸発、葉からしみ出るもの、竹筒からの漏れは見ていない | この足し方を本体の帳簿として続けてよいか。科学の工程にした方がよいか |

## お願いしたいこと

1. **器を焼く工程**：粘土で器（鍋・桶・灯皿・二重の壺）を形づくり、乾かし、薪で焼く。いまは試験片（タイル）までなので、器の大きさと形を持った `fired_pot` 系のロットにしたい。
2. **島で作った設備の値**：試験用の設備 `fixture_…`（桶・鍋・割る道具・刷毛・台・レトルト）を、島で作ったものに置き換える。焼いた器から作る設備（熱容量・熱の逃げ・容量）と、竹・木・石の道具の値。ロットから設備への換算表（器の組み立てと同じ形）があると、本体はそのままつなげる。
3. **薪を乾かす工程**：切ったばかりの薪（水分 45%）を、日陰・日なたに置いて乾かす。島の時計。タイルを乾かす工程と同じ形を考えている。
4. **雨水の扱いの確認**（上の表）。
5. `potSherdsQuality` の Codex の確認（壊れた器の処理につなぐ前に）。→ 済み（2026-10-07、lab e2a4147。本体の `POT_ASSEMBLY` につないだ）

検査：`scripts/island-science-check.ts`（気圧計の読み、ヤシの実、雨受け、雨の日の水の量）。

## 返事を受けて（2026-10-06、科学側 a3a2c1a）

- 気圧計・ヤシの実・薪の値はこのまま。雨水は本体の帳簿で続ける。
- ヤシの実は1個ずつ別のロットにした（run はロットをまるごと予約するので、搾る run が棚の実を全部使わないように）。腐った実は浜に残す（持ち帰らない）。
- 雨水：記録に雨量がない区間は足さず、たまっている水の `history_complete` を 0 にする。20 L を超えた分はあふれて失う。整数 mg。にわか雨ごとに最初の 0.5 mm は葉を濡らすだけで受けない。
- 依頼の順番は科学側の案のとおり：`potSherdsQuality` の Codex 確認 → 薪を乾かす → 器を焼く（設計案から）→ 島で作った設備の値。
