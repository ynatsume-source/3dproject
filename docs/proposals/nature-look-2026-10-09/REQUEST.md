# 自然班への依頼：島の植物ともの、丸っこく親しみやすく（2026-10-09）

本体（main）から自然班へ。香山島（Dot の島）の陸のものの見た目を、世界観は保ったまま、少しキャッチーで親しみやすい方向に寄せてほしい。形と色だけの仕事で、置き場所や住人の動きは本体が持つ。

画像はこのフォルダにある（`docs/proposals/nature-look-2026-10-09/`）。

## 1. 何を目指すか

ひとことで言うと「丸っこく、柔らかく、でも八重山の海岸林」。

- 近くで見て、思わず見入る、絵本や箱庭のような手触り。角ばった多面体や、ばらばらの細かい葉の寄せ集めに見えないこと。
- 種類が見分けられること。テリハボクは濃い緑の丸い樹冠、オオハマボウは低く広い黄緑の樹冠、アダンは支柱根と垂れる細長い葉とオレンジの実。図鑑の写実ではなく、特徴をつかんだ「デフォルメ」。
- 色は少し明るく、温かく。葉は上が明るい黄緑、下が深い緑の2色の濃淡。砂はクリーム色、流木は白っぽい灰ベージュ、石は温かい灰色。
- 光は今の空の光（`AIRLIT`）のまま。新しくライトを足さない（シーンにはライトがない）。

やらないこと：
- 写実を捨てたトイ調、原色、輪郭線のトゥーン。うつしよは「地球と同じ形をした、もうひとつの星」で、ロボットが暮らす島。かわいすぎず、実在の島の植生を下敷きにする。
- 置き場所、密度、木の本数、当たり判定の大きさを変えること（本体の担当。§3）。
- 海、魚、水面（別の班が進めている）。

## 3. 変えてはいけない約束（本体とのつなぎ目）

1. **関数の名前と引数、返すもの。** `treeGeo` は高さ1（地面0、樹冠の上が約1）に正規化した `BufferGeometry` を返す。属性は `position`、`normal`、`aTint`（色）、`aSway`（風で揺れる量）、`aLeaf`（葉=1／幹=0）、`aSh`（空の見え方、0.55〜1）、`aMn`（光の向きに使う法線）とインデックス。シェーダー（`buildForest` 内の `treeMat`、`shore.ts` の `plantMat`）がこれを読む。属性を足すなら、シェーダー側も合わせて直す。
2. **足もとの大きさ。** 住人の道探しと当たり判定は、形の数字を前提にしている。
   - 木の幹：半径 0.55 m の円柱として扱う（`forest.trunks`）。幹を太く広げすぎない。
   - 浜の植物の茂みの半径と高さ（大きさ1あたり）：クサトベラ 0.55・0.5、モンパノキ 0.5・0.75、アダン 0.38・1、岩 0.85・0.5（`shore.ts` の `VEG`）。岩の当たりは直径が大きさの約1.1倍、高さ約0.7（`solids.add`）。
   - 流木の当たり：長さ方向（x）に大きさ分、太さ約 0.06×0.45×大きさ。
   - 拾えるものの大きさ：流木 0.8 m、石 約0.26 m、ヤシの実 約0.29 m、貝殻 約0.1 m（手に持つ見た目が変わるので、大きく変えない）。

   形を変えて、この数字と合わなくなるなら、新しい数字を教えてほしい（本体が `VEG`／`solids` を直す）。
3. **乱数。** 形は `mulberry32(seed)` の決まった乱数で作る（同じ seed なら同じ木。近くの版と遠くの版（`lo`）が同じ木になること）。`Math.random()` を新しく呼ばない。three の `Geometry`／`Material` を作ると内部で `Math.random` を使う（uuid）ので、作る数を変えると島の配置の乱数列がずれる。数が変わる場合は §5 の本体チェックを回す。
4. **光。** 新しいライトや `MeshStandardMaterial` を足さない（このシーンにはライトがなく、真っ黒になる）。色の濃淡は頂点の色（`aTint`）と既存のシェーダーで出す。
5. **シェーダーの決まり。** GLSL の `#if` の分岐の中でも、同じ名前の変数は二重に宣言できない（変換後に1つの関数になる）。シェーダーを触ったら `node scripts/shader-check.mjs` を通す（各海を Chromium で開いて、シェーダーのエラーを拾う）。

## 4. 重さの上限

スマホで回す。今より重くしない。
- 木1本の三角形数：高い版は今と同じかそれ以下（目安 6,000 以下）、低い版（`lo`）は 2,000 以下。苗木は 1,700 以下。
- 浜の植物・拾えるものも、今の三角形数の2倍まで。
- 描画の呼び出し回数を増やさない（今はインスタンス描画。種類ごとに1回）。新しい種類を足すなら相談。
- テクスチャは足さない（足すなら小さいもの1枚まで、相談）。
- 丸さは「球を多く分割する」より、「少ない頂点で、法線を外向きに曲げて柔らかく見せる」（今の `aMn` のやり方）を優先。

## 5. 確かめ方

1. 型検査：`npx tsc --noEmit -p .`
2. シェーダー：`node scripts/shader-check.mjs`
3. 本体の住人のチェック（形や数の変更で、配置や乱数が変わっていないか）：
   ```
   for c in nav tideline house wall fell; do npx tsx --import ./scripts/node-assets.mjs scripts/$c-check.ts | tail -1; done
   ```
   すべて PASS であること。落ちたら、理由（乱数列のずれ、当たりの大きさ）を書いてもらえれば本体で見る。
4. 見た目：`npm run dev` で開き、`http://localhost:5173/?debug#planet`（ポートは vite の表示に従う）。左上の住人一覧で「ドット」を押すと、ドットを見守る視点で島に降りる。ドラッグで回り込み、ホイールで寄る。昼の時刻で、少なくとも次の4か所を撮る。
   - ドットの家のまわり（少し上から）
   - 林のへり（目の高さ）
   - 浜の流木と岩（近く）
   - 林の中

   今の画像（`now-*.jpg`）と並べて比べられるように、同じくらいの角度で。

## 6. 進め方と渡し方

- ブランチは main から切る（例：`nature/rounded-look`）。
- 段階を分けると確かめやすい。
  1. 林の木（`treeGeo`）
  2. 浜の植物と岩
  3. 拾えるもの
- できたら、`docs/proposals/nature-look-2026-10-09/` に、前後の画像と、変えたファイル・三角形数・足もとの数字の変更を書いた短いメモ（`HANDOFF.md`）を置いて知らせてほしい。本体がレビューして main に入れる（科学班との最終レビューと同じ流れ）。
- 住人が作るもの（ドットの小屋と家、焚き火、器、薪棚など。`src/robots/residents.ts`、`house.ts`）は、工程と一緒に動いているので今回は対象外。木の方向が決まったら、同じ方向で本体が寄せる。

分からないことや、約束を変えたほうがよさそうなところがあれば、手を動かす前に聞いてほしい。
