# 構想メモ：話題づくりと、外からの干渉（2026-10-01）

まだ実装しない。ユーザーと一緒に詰めていく前提で、出たアイデアと方針を忘れないように残す。

## 1. 島ラボ（住人が発信するWebメディア）

- 同じドメインの下にディレクトリを切って置く（例：`/3dproject/lab/`）。アプリ本体とは別のページ。
- 書き手は島の住人。記事の例：
  - 島の新聞：その日の出来事と見出し
  - 研究・工作の記録：失敗、途中で投げ出したもの、趣味
  - お邪魔キャラへの対策記事（下記3）
- **コンテンツの質が高いほど驚きが大きい**。量より、読んで価値のある一本を優先する。
- 住人の作ったもの（デザイン、小さなWebサービスなど）が現実で使える、という路線もここから出す。

## 2. 住人にカメラを渡す（島のアルバム）

- 住人が自分でレンズを選んで撮る。
- 撮り手ごとに作風がある：
  - プロ顔負けの構図と光で撮る者
  - 素人っぽいが愛らしい写真を撮る者（ぶれ、傾き、近すぎ、ペットばかり、など）
- 撮った写真は島ラボのアルバムに並ぶ。海の「名場面のベストショット」（今日のログの提案）とも合流させる。

## 3. お邪魔キャラ（侵略者・妨害者）

- マイクラのクリーパーのような存在。住人の作ったものを壊したり、邪魔したりする。
- 見どころは、攻防そのものより**住人が知恵をつけていく様子**。対策を考え、試し、失敗し、改良する。
- 対策の記事を島ラボで発表する。
- 癒しのトーンを壊さないよう、強さ・頻度・被害の大きさのバランス調整は必須。

## 4. ボトルメール（外からの干渉の一案）

- 外の世界（ユーザー）から、この世界にどこまで干渉できるか。これは引き続き設計の大事な柱。
- ボトルメールはその構想の一つとして保留しておく。
  - 流れ着くまで時間がかかる
  - 誰が拾うか分からない
  - 返事が来るかも分からない
- 詳細はおいおい一緒に詰める。

## 5. 「いまここに潜ると、こんな景色が見られる」

実在の海の天気・波の高さ・海水温は、すでに Open-Meteo から取り込んで映像に反映している（`src/time/weather.ts`）。時刻、季節、月齢もそうなっている。足りないのは「現実を映している」と伝わる形。

**おすすめ：世界は一つのまま、「現実に合わせる」度合いを切り替える。**

- 平行世界をもう一つ作ると、住人の暮らしやログが二つに割れてしまう。
- 代わりに、表示の切り替えと演出の抑え方で区別する。
- 潜水コンディションのカード「いまの宮古島の海」
  - 中身：水温、波の高さ、風、天気、透明度の目安、月齢と潮、日の出・日の入り
  - 「この季節・この時間に見られやすい生きもの」も載せる（例：冬の宮古ならザトウクジラ）
  - 数字はすべて実データ、または実データからの推定と明記する
- 「現実どおり」モード
  - めったに起きない光景（マンタの大群など）を止める
  - 生きものの多さを、実際の季節と時間帯に合わせる
  - 「いま潜ったら本当にこう見える」に近づける
- ふだんの写し世は、少しだけ物語のある海のまま。
- ダイバー向け：行く前の下見、行けない日の代わり。作業用の窓：「いま本物の海はこう」という静かな同期感。
